## 摘要
将前沿的视觉语言模型转化为机器人策略，通常意味着对其进行微调以输出其在预训练中从未见过的动作表示，这会丢掉许多使该模型值得被选用的推理能力。我们反其道而行之，保持 VLM 不变。它以一段简短的 Python 控制函数来编写策略，无需演示数据，无需微调。然而，一次性地写出代码属于开环控制。现有的闭环方法在错误的层级上做出反应：它们要么重试一个固定的策略，要么选择另一个子任务，但从不重写失败的代码。VLCP 在失败真正发生的控制代码层、在单个回合内实现闭环。每隔 $K$ 步，VLM 从多视角 RGB、本体感知状态和状态增量重新观察场景，然后基于刚刚看到的画面重写控制函数，从而在失败累积之前将其捕获。我们在涵盖 57 项任务的 MuJoCo/RoboVerse 基准上进行了评估。这种免训练策略取得了 $35.1\%$ 的合并成功率，而同一系统在每回合仅查询一次的条件下仅为 $3.5\%$。这一十倍的差距在所有场景族中都保持置信区间不重叠。该增益可追溯到在失败抓取上 $27.3\%$ 的回合内恢复率：开环控制器会让一次失误一直延续到回合结束的失误，在下一次重规划时被重新观察并修复。同时闭环的开销很低。输入令牌的中位缓存命中率达 $84\%$，一个回合仅需约 $10$ 次紧凑查询，而在任意重规划期间写入的控制块会被持久化到跨回合技能库中，供后续提示复用。

## Abstract
Turning a frontier vision-language model into a robot policy usually means fine-tuning it to emit an action representation it never saw in pretraining, which throws away much of the reasoning that made the model worth reaching for. We go the other way and keep the VLM frozen. It writes the policy as a short Python control function, with no demonstrations and no fine-tuning. Writing that code once is open-loop, though. Existing closed-loop methods react at the wrong level: they retry a fixed policy or pick a different subtask, but never rewrite the code that failed. VLCP closes the loop where the failure actually lives, on the control code, within a single episode. Every $K$ steps the VLM re-observes the scene from multi-view RGB, proprioceptive state, and a state delta, then rewrites the control function from what it just saw, so a failure is caught before it compounds.   We evaluate on a 57-task MuJoCo/RoboVerse sweep. This training-free policy reaches $35.1\%$ pooled success, against $3.5\%$ for the identical system queried once per episode. That tenfold gap holds with non-overlapping confidence intervals in every scene family. The gain traces to a $27.3\%$ within-episode recovery rate on failed grasps: a miss an open-loop controller would carry to the end of the episode gets re-observed and fixed at the next replan. And the loop stays cheap. A median $84\%$ of input tokens hit cache, an episode needs only about $10$ compact queries, and control blocks written during any replan persist to a cross-episode skill library reused in later prompts.

# VLCP 论文详细总结

## 1. 论文核心问题与整体含义

### 1.1 研究背景与动机
- **VLA 范式的代价**：当前主流的视觉-语言-动作模型（VLA，如 OpenVLA、π0）通过对预训练 VLM 进行微调，使其输出预训练中从未见过的动作表征（专用 token 或连续动作）。这一适配过程会让模型偏离其预训练分布，可能损失其原本具备的推理能力。
- **VLA-0 的启示**：以纯文本表示动作（而非特殊 token）可缩小分布偏移，得到显著更强的策略——即"对预训练模型的偏离越少，能力保留越多"。
- **代码是更好的动作表示**：前沿 LLM 最擅长的恰恰是代码。令模型直接生成 Python 控制函数作为策略，既不需要新动作语言，也无需微调或示教数据。

### 1.2 核心矛盾
- **代码策略的开环缺陷**：若仅在回合开始前一次性写好控制代码，执行期间发生的任何失误都将无声地延续到回合结束（如抓取空夹）。
- **现有闭环方法的"层级错位"**：
  - 代码生成类（Code-as-Policies、ProgPrompt、ELLMER）：单次查询，无重观察；
  - 监控与重规划类（Code-as-Monitor、DoReMi、Inner Monologue）：在任务/语言层闭环，但只重试同一策略或切换子任务，不修改失败的控制代码；
  - VLA 类：反应式但输出不透明，无中间推理点；
  - Act-Observe-Rewrite：跨试验重写完整控制器，但一个回合仍跑完固定控制器。
- **核心空白**：没有任何方法在**单个回合内**、针对**控制代码本身**实现闭环。

### 1.3 论文目标
提出一种训练免费（training-free）的方法，在控制代码层面实现回合内闭环恢复——失败发生时被观察、被重写，并在同一回合内被纠正。

## 2. 方法论

### 2.1 总体框架
- **冻结 VLM**：直接用作代码生成器，模型权重不更新。
- **策略表示**：Python 函数 `control(obs, J) → actions`，其中 `obs` 为多视角 RGB 与本体感知，`J` 为解析计算的 3×7 末端执行器雅可比矩阵，`actions` 为 PD 控制器所需的逐关节位置目标。
- **两层闭环**：
  - **块内闭环**（快）：编译后的控制函数每步接收新 `obs` 和 `J`，对数值状态反应；
  - **块间闭环**（慢）：每 $K$ 步（默认 $K=50$）调用一次 VLM，基于最新观察**重写整个控制函数**。

### 2.2 关键技术细节

#### 2.2.1 视觉闭环重规划
- **观测输入**：每个块边界处提供：(i) 上一个块起始的多视角 RGB、本块生成的代码及其 $K$ 个动作字典；(ii) 当前同步的多视角 RGB；(iii) 末端执行器位姿、关节位置、物体位姿的 JSON 摘要；(iv) 一个状态增量 $\Delta$。
- **视觉的角色**：特权物体位姿仅用于初始化抵达；失败信号（夹爪提前闭合、角度偏移、滑动、目标被推移等）必须由同步 RGB 图像读出。
- **图像清理**：历史中每轮副本会丢弃图像与引用图像的散文，避免悬挂指针。

#### 2.2.2 重规划节奏
- 默认 $K=50$，回合长度 $T=500$，故每回合约 $10$ 次重规划。
- 块越小，重观察越频繁、捕获失败越早，但 VLM 调用次数越多。

#### 2.2.3 提示结构（三块式，支持缓存复用）
- **块 A（静态前缀，约 8k token）**：机器人与环境文档、技能 API 源码、三个单阶段控制示例；
- **块 B（学习技能库）**：扫描 `control_policies/skills/` 目录，按修改时间倒序注入至多 12 个模块源码；
- **块 C（目标钉）**：任务标识与自然语言目标，放置在系统提示而非对话历史中，避免被截断。

#### 2.2.4 输出格式契约
- 仅允许响应被 `# control`、`# skills/<name>.py` 头注释标记的 Python 代码块，不允许散文。
- `control` 块必须定义 `def control(obs, J) -> list[dict]`，且每个重规划只处理下一个阶段（约 $K$ 步）。

#### 2.2.5 跨回合技能库
- VLM 在任何重规划期间可附带写出命名辅助模块（如 `# skills/move_to_grasp.py`）。
- 模块被原子化写入磁盘共享目录，导入失败则回滚并在下一轮提示中反馈错误。
- 通过进程级锁支持并发实例共享。
- 技能文件在所有后续提示中按修改时间排序被注入，最多 12 项。

#### 2.2.6 历史管理与缓存
- 保留至多 $H=20$ 轮的先前重规划对话对，超过则丢弃最旧。
- 缓存断点位于最近一个助手回合结束处，因此从该处开始的静态前缀在下一调用可命中缓存。

- 75 个回合中 40 个始终未恢复——为闭环 VLCP 仍未覆盖的上限。

### 6.3 泛化能力

### 6.4 系统可行性
- 提示缓存使回合内重规划负担可控：中位 84% 输入 token 命中缓存、单回合约 10 次紧凑查询，每次中位 18.8 s 延迟。

- **受控消融的归因清晰**：$K=T$ vs $K=50$ 唯一变量分离，避开跨基准、跨 API、跨任务集的混杂因素；
- **机制可解释、可量化**：除黑箱成功率外，还从日志直接计算恢复率，并以定性文本（"recenter lower and regrasp the pudding after the last miss"）佐证模型确实在诊断错误；
- **跨回合技能库**：把每次重规划的副产品沉淀为可复用模块，构成"不重训即可积累能力"的自然基底；
- **零训练、零示教**：跳过昂贵的数据收集流程，直接复用预训练模型的代码能力；
- **工程细节成熟**：三块式提示结构、缓存断点、原子化技能写入、进程级锁、图像与散文清理等，使系统在循环中保持稳定。

## 总体评述

VLCP 的核心贡献是把"闭环"这一概念**在正确的层级上重新定位**——不是重试同一策略，也不是切换子任务，而是**在控制代码层面、回合内、用同一冻结模型**完成观察-诊断-重写-再执行的全过程。其受控消融（$K=T$ vs $K=50$）干净地将 10 倍成功率提升归因于回合内重规划本身，并通过恢复率这一机制性指标直接验证了"看图像 → 改代码 → 重新抓起"这一闭环行为确实存在且有效。

论文的局限同样不容忽视：仿真依赖、特权感知、API 成本与单回合评估都是其走向大规模真实世界部署前必须解决的工程与统计问题。但作为一项**概念验证**，它展示了"用预训练模型最擅长的语言（代码）作为动作表示，并仅在失败发生时重写代码"这一思路的强大潜力，也为未来训练免费的机器人策略提供了一条清晰的演进路径。
