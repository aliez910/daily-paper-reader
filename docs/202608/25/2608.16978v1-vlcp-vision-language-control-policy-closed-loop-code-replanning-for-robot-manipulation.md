## 摘要
将前沿的视觉-语言模型转化为机器人策略，通常意味着对其进行微调，使其输出一个在预训练中从未见过的动作表征，这会丢失使该模型值得使用的许多推理能力。我们反其道而行之，保持VLM冻结不变。它将策略编写为一个简短的Python控制函数，无需演示，无需微调。然而，一次性地编写该代码属于开环方式。现有的闭环方法在错误的层级上做出反应：它们重试一个固定的策略或选择不同的子任务，但从不重写失败的代码。VLCP在失败真正发生的层级——控制代码上——在单个回合内闭合环路。每隔K步，VLM根据多视角RGB、本体感知状态以及状态增量重新观察场景，然后依据刚刚观测的内容重写控制函数，从而在故障累积之前将其捕获。我们在包含57个任务的MuJoCo/RoboVerse基准上进行了评估。这种无需训练的策略取得了35.1%的汇总成功率，而每回合仅查询一次的相同系统仅为3.5%。这一十倍的差距在所有场景类别中都保持置信区间互不重叠。该增益源自27.3%的回合内失败抓取恢复率：开环控制器会将一次失误带到回合结束，而该方法在下次重规划时重新观察并修复它。并且该环路代价低廉。输入词元的中位缓存命中率为84%，一个回合仅需约10次紧凑查询，任何重规划期间编写的控制块都会被持久化保存到跨回合的技能库中，供后续提示词复用。

## Abstract
Turning a frontier vision-language model into a robot policy usually means fine-tuning it to emit an action representation it never saw in pretraining, which throws away much of the reasoning that made the model worth reaching for. We go the other way and keep the VLM frozen. It writes the policy as a short Python control function, with no demonstrations and no fine-tuning. Writing that code once is open-loop, though. Existing closed-loop methods react at the wrong level: they retry a fixed policy or pick a different subtask, but never rewrite the code that failed. VLCP closes the loop where the failure actually lives, on the control code, within a single episode. Every $K$ steps the VLM re-observes the scene from multi-view RGB, proprioceptive state, and a state delta, then rewrites the control function from what it just saw, so a failure is caught before it compounds.   We evaluate on a 57-task MuJoCo/RoboVerse sweep. This training-free policy reaches $35.1\%$ pooled success, against $3.5\%$ for the identical system queried once per episode. That tenfold gap holds with non-overlapping confidence intervals in every scene family. The gain traces to a $27.3\%$ within-episode recovery rate on failed grasps: a miss an open-loop controller would carry to the end of the episode gets re-observed and fixed at the next replan. And the loop stays cheap. A median $84\%$ of input tokens hit cache, an episode needs only about $10$ compact queries, and control blocks written during any replan persist to a cross-episode skill library reused in later prompts.

# VLCP 论文总结

## 1. 核心问题与研究动机

- **背景**：当前主流方法（VLA 类，如 OpenVLA、π0、VLA-0）通过微调让视觉-语言模型输出"动作 token"或文本化动作表征，这要求模型学习一种**预训练分布之外**的表征方式，可能损失其原有的推理与代码生成能力。
- **关键缺口**：
  - **Code-as-Policies / ProgPrompt / ELLMER**：让 LLM 写 Python 控制函数，但属于**开环**——一次性生成，运行时错误无法修复。
  - **Code-as-Monitor / DoReMi / Inner Monologue**：监控并反馈，但只在任务/语言层级反应（重试固定策略或切换子任务），**不重写失败的代码本身**。
  - **Act-Observe-Rewrite**：虽然重写控制器，但**在回合之间**重写，回合内仍按旧代码运行到结束。
- **核心问题**：如何在**不微调、不依赖演示数据**的前提下，让 VLM 策略具备**回合内**、**对控制代码本身**的闭环纠错能力？

## 2. 方法论

### 核心思想
- **保持 VLM 完全冻结**，让其编写**短 Python 控制函数** `control(obs, J) → actions` 作为策略。
- **双层闭环**：
  - **块内（within-block）闭环**：编译后的 `control()` 每步接收新鲜的 `obs` 和解析雅可比矩阵 `J`，对数值状态反应。
  - **块间（across-block）闭环**：每 `K=50` 步触发一次 VLM 重规划，根据实时观测**重写控制函数本身**。
- **关键创新**：闭环点位于**控制代码层**，而非任务/子任务层或动作 token 层。

### 算法流程
1. **观察（Observe）**：在每个块边界，采集双视角同步 RGB、本体感知状态（末端位姿、关节角）、目标物体位姿，以及**显式状态增量** Δstate。
2. **生成（Code）**：VLM 根据以上输入重写 Python 控制函数 + 可选的辅助 skill 模块。
3. **执行（Execute）**：该控制函数运行 `K=50` 步，期间仅做数值级 IK 反应，不再询问 VLM。
4. **重规划（Replan）**：到达块边界 → 回到步骤 1。

### 关键技术细节
- **动作表征**：函数返回按关节位置目标的字典列表，由仿真器 PD 控制器消费；速度级 IK 通过预解析的雅可比矩阵 `J` 直接提供。
- **提示词结构（三块缓存设计）**：
  - Block A（静态前缀 ≈ 8k tokens）：机器人/环境文档、API 源码、3 个单阶段控制示例。
  - Block B（学习到的 skill 库）：磁盘上所有已存模块源码按时间排序，取最近 12 个。
  - Block C（goal pin）：任务标识与目标语句，放在 system prompt 中以防历史截断时丢失。
- **严格输出格式契约**：仅允许 `# control` 头（定义 `control(obs, J)`）与零或多个 `# skills/<name>.py` 头。
- **跨回合 skill 库**：任何 `# skills/...` 模块原子写入 `control_policies/skills/`，跨 episode 与并发实例共享（进程级锁），下次重规划时按 mtime 注入。
- **历史与截断**：保留最多 H=20 对历史，超过则丢弃最旧；图像只出现在当前 API 回合，历史中丢弃图像与相关文本。
- **模型**：GPT-5.5 作为重规划 VLM；尝试过 Qwen3-4B 但生成代码与重规划均不可靠。

## 3. 实验设计

- **仿真器 / 平台**：MuJoCo + RoboVerse；机器人 Franka Panda 7-DoF + 平行夹爪。
- **数据集 / 任务集**：
  - **主实验**：57 任务跨三类场景
    - Object Picks：10 个 LIBERO-Object 拾取任务
    - Kitchen Scenes：30 个（LIBERO-90，含铰接物体、拣放、干扰消歧、抽屉放置、堆叠、多步序列）
    - Living-Room Scenes：17 个（LIBERO-90）
  - **指令重框架研究**：6 个 LIBERO-Object 任务（alphabet_soup, bbq_sauce, chocolate_pudding, cream_cheese, ketchup, butter），原指令 "pick up {object} and place it in the basket" → 改写为 "put {object} in the basket"。
- **基准对比（Baselines）**：
  1. **Open-loop VLCP（K=T）**：同一系统，每回合仅查询一次，无回合内重规划——这是关键的"受控消融"，保持仿真器、API、特权位姿、任务集、模型、回合预算完全一致，仅变化"K"这一变量。
  2. **VLA-0**：在完整 LIBERO 上微调的 VLA，作为**演示训练上限参考**（仅用于指令重框架研究）。
  3. **CaP-Agent0（CaP-X，并发工作）**：作为外部训练自由代码代理参考，引用其 LIBERO-PRO 报告数据。
- **评估指标**：Wilson 95% 置信区间的成功率。

## 4. 资源与算力

- **未使用本地 GPU 训练**——核心方法**零训练**，VLM 保持冻结（GPT-5.5 通过 API 调用）。
- **推理侧算力未具体说明**，仅给出：
  - 每回合约 10 次 VLM 调用（共 81 个回合 ≈ 721 次重规划调用）。
  - 单次重规划延迟中位数 18.8 s，均值 25.9 s（以前沿模型服务端生成为主）。
  - VLA-0 在指令重框架研究中作为本地推理参考（原文称"cheap and local"），但未列具体硬件。
- **实验成本限制**：因每次回合需调用闭源 VLM API，主扫描对每个任务仅运行 1 个回合（57 回合），改用 Wilson 区间与按场景族汇总代替多 seed 重复。
- **原文明确指出**：未来要做多 seed 评估并切换到开源强 VLM 以降低成本。

## 5. 实验数量与充分性

- **主扫描**：57 任务 × 1 回合（闭环）+ 57 回合（K=T 开环对照），按 3 个场景族汇总。
- **恢复行为分析**：75 个闭环拾放回合（含主扫描外的额外日志回合）。
- **成本/延迟分析**：81 个闭环回合 ≈ 721 次重规划调用。
- **指令重框架研究**：6 任务 × 2 指令变体 × 2 方法；VLA-0 原指令 50 回合/任务、改写指令 10 回合/任务；VLCP 各 10 回合/任务。
- **公平性 / 充分性评价**：
  - **优点**：K=T 消融做到了极致的"单一变量"控制（同仿真器、同 API、同特权位姿、同模型、同预算）；按场景族做 Wilson 区间分析，且**所有族置信区间均不重叠**，证据扎实。
  - **不足**：
    - 每个任务仅 1 回合，无多 seed，无法量化任务级方差；recovery 与 cost 分析基于更全集而非 57 任务，**统计外推时需注意口径差异**。
    - 与 VLA-0 仅做指令重框架子集对比，未在主扫描正面比较。
    - 公开代码协议（外部代理 CaP-Agent0）跨不同基准（LIBERO-PRO），仅做引用，**不可视为同基准对照**。

## 6. 主要结论与发现

- **回合内重规划是成功的关键因素**：闭环 VLCP（K=50）vs 开环 K=T
  - Object Picks：60.0% vs 10.0%
  - Kitchen Scenes：33.3% vs 3.3%
  - Living-Room Scenes：23.5% vs 0.0%
  - **总体 35.1% vs 3.5%**，约 **10 倍差距**，每族 Wilson 区间均不重叠。
- **机制可量化**：在 75 个闭环拾放回合中，55 个含至少一次失败抓取，其中 15 个（**27.3%**）在后续重规划中重新接近并成功提升物体（中位数 3 次重规划后恢复）；开环版本因构造原因恢复率为 0%。
- **失败模式**：长视野场景（Living-Room）成功率下降，反映即使抓取恢复成功，仍需在同一固定视野内完成后续放置子目标。
- **指令鲁棒性**：VLCP 对指令重框架**不敏感**（总体 40.0% → 40.0%，Δ=0）；VLA-0 在 butter 任务从 96% 跌至 0%，bbq_sauce 从 96% 跌至 50%，总体 97.3% → 75.0%，表明其原性能部分依赖具体措辞。
- **运行成本可控**：
  - 每回合约 10 次紧凑 VLM 查询（输出中位 349 tokens）。
  - 输入 token 缓存命中率中位数 **83.8%**（首批后），静态前缀 ≈ 8k tokens。
  - **代码有效性 100%**（778/778 控制块全部解析编译通过）。

## 7. 方法与实验设计的亮点

- **闭环位置选择极具洞察力**：把"在哪一层闭环"作为核心论点（任务层 / 子任务层 / 动作 token 层 / **控制代码层**），并以一张对比表（Table 1）清楚刻画五维能力坐标。
- **极致的单一变量消融**：K=T 不仅是"少做几步重规划"，而是与 VLCP 共享**完全相同的系统栈**，让 10 倍增益无法归因于环境、模型或 API。
- **机制可观测、可复现**：直接从日志化的 per-block 物体高度与夹爪状态计算恢复率，而非依赖定性叙述。
- **跨回合 skill 库**：把代码即策略的设计延展为持续学习载体——成功的辅助模块直接落盘并自动注入后续提示词，无需筛选策略或人工策展。
- **缓存感知的提示词结构**：将静态文档、动态 skill、目标 pin 三块分置，最大化 KV-cache 复用，把回合内重规划成本压到 ~10 次紧凑调用。
- **严格的输出契约 + 原子写盘 + 失败回滚**：保证生成代码 100% 编译通过、skill 导入失败自动回退并向 VLM 报告错误。

## 8. 不足与局限

- **依赖特权物体位姿**：当前用仿真器读出的目标物体位姿来"种子化"首次接近，刻意把感知问题隔离在闭环问题之外；真实机器人需要替换为学习式检测器，但该替换未在文中验证。
- **仅仿真评估**：未在真实机器人上验证鲁棒性与动力学。
- **高频控制受限**：单次重规划延迟中位 18.8 s，意味着方法适合**慢速操作**而非高频反应式控制。
- **闭源 VLM 与成本**：
  - 评估受限于 API 预算，主扫描每任务仅 1 回合，无法做多 seed 方差估计。
  - 开源小模型（Qwen3-4B）生成不可靠，**可访问性与部署成本受限**。
- **基线选择偏向自己**：
  - 与 CaP-Agent0 仅做跨基准引用，未做同基准对照。
  - 与 VLA-0 的对比限定在指令重框架子集（6 任务），**主扫描缺乏同基准 VLA 对照**。
- **长视野任务天花板**：固定 500 步视野内既要恢复抓取又要完成放置，恢复虽常见但"剩余时间不足"成为主要失败源；论文承认这是当前实例化下的硬约束。
- **VLAs 的失败案例分析偏定性**：VLCP 失败时被归因为"重复同一错误"，但未对失败模式做与 27.3% 恢复率同等粒度的系统化对照。
- **未公开代码或训练脚本**：仅给出 prompt 与生成代码示例（附录 A/B），完整 skill 库与复现脚本可获得性未明确说明。
