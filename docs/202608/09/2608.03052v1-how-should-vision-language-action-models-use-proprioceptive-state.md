## 摘要
近期的视觉-语言-动作（VLA）模型几乎普遍将机器人的本体感受状态作为输入，但接入方式却互不兼容——有的将其序列化进文本提示，有的投影到视觉-语言前缀中，有的则直接送入动作专家模块——并且几乎总是只使用单一的当前帧。三个问题尚未得到解答：（1）当前状态是否、且在哪些任务上确实能改善闭环控制；（2）状态历史有多大帮助，以及其收益究竟源自真实的时间变化还是仅仅增加了条件信息容量；（3）状态应当从何处进入模型——是视觉-语言骨干网络还是动作生成模块。我们通过在流匹配 VLA 上进行受控实验来回答这些问题，全程固定骨干网络、训练数据、动作表示与评估协议。我们在实现细节保持一致的条件下，实现了五种具有代表性的接口——离散状态提示、VLM 前缀、动作前缀、状态专家与特征调制——并在涵盖三个任务族的 45 项原子任务以及 20 项复合任务上进行评估；随后我们将状态历史长度从 1 帧扫到 96 帧，以考察历史状态信息如何影响模型性能。实验对三个问题给出了系统性回答，并提炼出针对具备状态感知能力的 VLA 的可检验设计原则。

## Abstract
Recent Vision-Language-Action (VLA) models almost universally take robot proprioceptive state as input, yet wire it in incompatible ways -- serialized into text prompts, projected into the vision-language prefix, or fed directly to the action expert -- and almost always as a single current frame. Three questions remain open: (1) whether, and on which tasks, current state actually improves closed-loop control; (2) how much state history helps, and whether its benefit reflects genuine temporal variation rather than added conditioning capacity; and (3) where state should enter the model -- the vision-language backbone or the action-generation module. We answer these questions through controlled experiments on a flow-matching VLA, fixing the backbone, training data, action representation, and evaluation protocol throughout. We implement five representative interfaces -- discrete state prompt, VLM prefix, action prefix, state expert, and feature modulation -- under matched implementation details, and evaluate them on 45 atomic tasks spanning three task families plus 20 composite tasks; we then sweep the state-history length from 1 to 96 frames to examine how historical state information affects model performance. The experiments yield systematic answers to all three questions, distilled into testable design principles for state-aware VLAs.

# 论文总结：VLA 模型应如何使用本体感受状态？

## 1. 核心问题与研究动机

- **研究背景**：最近的视觉-语言-动作（VLA）模型几乎都把机器人的本体感受状态（proprioceptive state）作为输入，但接入方式五花八门：
  - **π₀.₅**：将状态量化并序列化成文本 token，拼到 VLM 的语言提示里；
  - **OpenVLA-OFT**：把状态连续投影后注入语言模型的输入序列；
  - **GR00T N1**：把状态直接送到动作专家（action expert）。
  - **几乎所有方法都只用单帧当前状态**，很少考虑历史时间序列。
- **核心矛盾**：视觉和语言在 VLM 中已经过大规模预训练；本体感受状态却没有同等规模的预训练，因此是 VLA 中最缺乏研究、最不被理解的输入。
- **三个待解的关键问题（RQ）**：
  1. **是否以及在哪些任务上**，当前帧状态能真正改善闭环控制？
  2. **状态历史有多大的帮助**，其收益是来自"真实的时间变化"，还是仅仅因为"多出来的条件 token"提供了额外容量？
  3. **状态应注入哪里**——VLM 骨干网络，还是动作生成模块？该选择是否随历史长度变化？
- **整体意义**：已有研究的差异都被混入不同的骨干、预训练、数据与评估协议中，无法横向比较；本文将"主干 + 训练数据 + 动作表示 + 评估协议"全部固定，把状态设计当作**唯一自变量**，从而给出可复用的设计原则。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体思路

- 选用 **π₀.₅**（VLM + 流匹配动作专家）作为测试床。
- 在统一实验框架内实现 **5 种状态接口**，并扫描 **1→96 帧历史长度**。
- 引入 **"slot-matched repeat-current" 对照组**（用当前状态复制填满同样数量的 slot），将"时间信息含量"与"条件 token 数量"两个因素拆开。

### 2.2 状态表示

- 原始状态 $s_q \in \mathbb{R}^{16}$：末端执行器的位置 + 四元数、底座位置 + 四元数、两指夹爪关节。
- 除离散提示接口外，其余接口使用同一个两帧共享的逐帧投影器：$h_i = \phi_2(\text{Swish}(\phi_1(s_i)))$，将 32 维（零填充后）映射到与宿主模块相同的宽度（VLM 前缀 d=2048，其余 d=1024）。
- **离散提示（sp）**：当前帧逐维量化到 256 桶，借用预训练 tokenizer 序列化产生 ~66 个 prompt token。

### 2.3 五种状态接口

| 接口 | 注入位置 | 形态 | 单帧可训练参数 |
|------|----------|------|----------|
| **sp**：State Prompt | VLM 文本侧 | 离散文本 token | 0 |
| **vp**：VLM Prefix | VLM 前缀（双向） | 连续 token (d=2048) | 4.26M |
| **ap**：Action Prefix | 动作专家前部（因果） | 连续 token (d=1024) | 1.08M |
| **se**：State Expert | 独立 Transformer 流 | 连续 token | 199.30M |
| **fm**：Feature Modulation | 动作专家每层交叉注意力 | 每层 γ/β 调制 | 123.84M |

- 特征调制公式：$\text{Mod}(z; S) = (1 + \gamma(z,S)) \odot z + \beta(z,S)$。
- 关键设计：五者**共享同一动作生成目标、数据流水线与训练策略**，仅在"如何表示 + 注入哪里"上有所不同。

### 2.4 两个分析协议

- **Slot-matched temporal control**：用"K 份当前帧重复"对照"K 帧真实时序"，隔离"内容"与"容量"。
- **Fixed-checkpoint probe**：在不训练的前提下，对同一图像/语言/动作目标，比较 true-state 与 state-off 前向差异，量化 VLM 层语言到图像的注意力分布重分配（TV 距离）、图像隐藏表示的相对 ℓ2、动作流沿去噪轨迹的修正方向与幅度。

## 3. 实验设计

### 3.1 基准与环境

- **仿真平台**：基于 RoboCasa 的 **RoboCasa365**。
- **视觉输入**：左外、右外、腕部三个相机视角。
- **动作空间**：末端执行器增量（EEF deltas）。
- **状态坐标**：默认 EEF pose，并重复关键对比于 joint-angle 状态。
- **训练起点**：所有方法从同一预训练 π₀.₅ 检查点开始**全量微调**，共享优化器配置、数据管线、动作表示和学习率。

### 3.2 任务基准（"分层评估协议"）

- **原子任务（Atomic）**：共 45 个，按控制语义（而非按表现）预分为 3 个族 × 15 个：
  - **A 类**：重排 / pick-and-place（大范围末端与底盘定位）；
  - **B 类**：铰链物体交互（持续接触、运动相位建模）；
  - **C 类**：旋钮/开关/家电（小工作空间，高精度）。
  - 每个家族**独立训练类别专家**，每任务 50 次闭环 rollout。
- **复合任务（Composite）**：使用 lifelong_learning_phase2，20 个任务类型，每个 episode 串联 2–3 个原子子目标；联合训练 1 个策略，每任务 25 次闭环 rollout。
- **统一评估指标**：闭环任务成功率（SR）。

### 3.3 对照项

- **无状态基线（NS）**；
- 5 种状态接口（sp, vp, ap, se, fm）；
- 8 个历史长度档位：1、4、8、16、32、48、64、96 帧；
- slot-matched repeat-current 对照；
- 固定检查点探针实验（附录 A）和 PrepareToast 案例研究（附录 B）。

## 6. 主要结论与发现

### 6.1 RQ1（当前帧状态是否有用）

- 当前帧状态总体上**有帮助**：45 原子任务上 NS 宏平均 54.6%，五接口均高于基线，提升区间 +1.1（ap）至 +3.1（sp）。
- **离散提示 sp** 是唯一**置信区间排除零**的接口（Δ+3.1, 95% CI [0.2, 6.1]）。
- **没有统一最优接口**：A 类重排偏好 sp（68.7%, +7.0）；B 类铰链 vp 最优（68.8%, +6.1）；C 类旋钮 se 最优（42.8%, +3.3）且 vp 反而掉到 −1.2。"宏平均会掩盖任务族级的反转"。
- 性能/算力权衡：sp 最高代价（~1114 训练 GFLOPs），se 与 fm 在相近宏平均（57.6%）下边际算力极低。

### 6.2 RQ2（历史帧多深才合适）

- 在原子任务上历史深度呈**非单调**：短历史好，长原始历史会退化（尤其 C 类）。
- **K=8 是实用甜点**，被采用为后续实验默认深度。
- 在 20 复合任务上，K=1→8 给动作前缀带来最大增益（EEF-pose +10.8、joint-angle +4.8），而 VLM 前缀增益不稳定（EEF-pose −0.6）。
- **Slot-matched 关键对照**：ap 上 8 帧重复当前帧（30.8%）远低于 8 帧真实时序（39.0%），证明增益来自**真实时间变化**而非多出来的条件 slot。

### 6.3 RQ3（状态应注入哪里）

- **K=1（单帧）**：VLM 侧更优（原子上 sp/vp 领先 0.1pp；复合上 vp 34.4% vs ap 28.2%，EEF-pose；33.6% vs 31.4%，joint-angle）。
- **K=8（短历史）**：动作侧彻底反超（ap 在三处面板里都是最佳：原子 59.6%、复合 EEF-pose 39.0%、joint-angle 36.2%）。
- **可总结为设计原则**：**单帧状态注 VLM 骨干；多帧短历史路由到动作专家**。
- 探针验证：vp 显著抬高 VLM 末端 6 层的语言→图像注意力 TV 距离与图像表示相对 ℓ2；ap 主要在动作流去噪过程中体现"修正量"（ap₁ → ap₈，最终对齐 0.079→0.270、归一化幅度 0.174→0.382）。

### 6.4 案例研究（PrepareToast）

- ap₁ 与 ap₈ 在前两个放置子目标阶段表现接近（S₁ 90% vs 96%、S₂ 64% vs 68%）；
- **差异从两个物品放完、机器人必须返回关柜时（S₃）爆发**：ap₁ 30%、ap₈ 56%，+26pp 持续到 S₄ 与最终成功，bootstrap 区间 [+10, +42]；

## 7. 论文优点与亮点

- **控制变量思维**：把"状态设计"作为唯一变化量，所有外部因素固定，让"成功率差异"可归因到设计本身。
- **多维度的复合设计空间扫描**：覆盖 5 接口 × 8 历史 × 2 任务基准 × 2 状态坐标，并叠加"原子 + 复合"双层评估，揭示非单调与交叉关系。
- **Slot-matched 时序对照**：精巧地排除"更多 token 即更好"的容量混淆，使"历史有用"的结论真正落在"时间变化"上。
- **机制级证据**：固定检查点探针在 VLM 层和动作流去噪轨迹上同时给出量化证据；任务边界处的 5.2× 敏感度为系统级结论提供行为层面定位。
- **计算成本透明**：附录给出闭式 GFLOPs 推导，明示"sp 性能强但开销最高、se/fm 性价比高"这种工程权衡。
- **可复用与可检验**：评估流程、协议、自助法都明确，是审计未来"具备状态感知能力的 VLA"的工具。
- **任务族预划分**：依据控制语义而非按表现分族，避免 cherry-picking。
