## 摘要
人类在执行长时序操作任务时，能够保留对先前动作所建立状态的知识，同时不断调整正在进行的运动。相比之下，采用动作分块方式的视觉-语言-动作（VLA）策略在每次查询时都会基于当前输入重新进行规划。现有方法通常通过记忆机制保留长期任务证据，或通过动作复用与集成保留短期运动，但都未能完整地完成跨查询的衔接。我们提出 ChainVLA——一种具有 12 亿参数的 VLA 策略，通过一种联合且可修订的执行状态来链式连接连续的查询。具体而言，进度上下文（Progress Context）将循环的工作状态与稀疏的事件记忆相结合，以承载从观测中提取的任务进度；而运动尾部（Motion Tail）则将前一次预测中尚未执行的部分馈入状态构建与动作生成之中。这两个组件共同作用于一个解码器，使其在最新观测下重新生成每个动作视野，从而允许所携带的状态在不固定的情况下引导下一次预测。ChainVLA 在 RMBench 上达到 62.8% 的平均成功率，并在四个 LIBERO 套件上达到 98.8%；而移除 Motion Tail 或 Progress Context 后，RMBench 的成功率分别下降至 11.2% 和 3.0%。这种非对称的消融结果与如下观点一致：运动连续性有助于保留从中可推断任务进度的观测流。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 1. 核心问题与研究动机

长时序操控任务要求智能体同时具备两类能力：(a) 保留过往动作所建立的任务进度记忆；(b) 在执行过程中维持并动态调整当前运动的连续性。然而，现有动作分块（action-chunked）VLA 策略采用严格的"前缀执行 + 重新规划"模式，每次查询都仅基于当前观测、本体状态与指令重新预测一个完整动作视野（horizon），而前一次预测的未执行片段和先前推断出的任务证据并未显式地传递给下一次查询。

这种"跨查询衔接缺失"在两个层级产生歧义：
- **任务层**：当关键证据（如已完成的子任务、初始布局、目标位置）离开当前视野后，相同的观测与指令可能对应完全不同的历史，从而需要不同的下一步决策（RMBench 中 Put Back Block 任务即为典型例子）。
- **运动层**：重新规划会丢弃前一预测的未执行尾部，新预测的指令前缀可能与它所替代的运动不一致，产生边界跳变，进而改变后续观测流，使任务进度推断所依赖的视角序列偏离训练分布。

现有研究两条路线各自只解决一半：记忆增强方法（MemoryVLA、Mem-0 等）保留任务证据但丢弃未执行运动；动作集成/续接方法（Temporal Ensemble、Native Continuation 等）保留运动连续性但无长期任务记忆。本文的核心问题即：**如何在保持每个新预测对最新观测响应的同时，将任务进度与未完成运动在查询间链式衔接？**

## 2. 方法论

### 2.1 核心思想
ChainVLA 提出将跨查询执行状态（execution state）拆为两部分：
- **Progress Context** $g_k$：回顾性，承载观测派生的任务进度；
- **Motion Tail** $u_k$：前瞻性，承载上一预测的未执行后缀。

两者联合构成"联合且可修订"的执行状态 $s_k=(g_k, u_k)$，供解码器在最新观测 $x_k$ 下重新生成整个动作视野，状态作为"可修订先验"而非固定计划。

### 2.2 关键组件

#### Progress Context（任务进度侧）
- **Recurrent Working State** $W_k=(L_k, B_k)$：8 个学习到的 working query 通过 cross-attention 作用于当前多模态 token $X_k$，并以掩码 $m^{live}_{k-1}$ 融合上一查询的 live token；$B_k$ 为有界 FIFO 缓存（3 个槽位、24 个旧 live token）。池化后的 $\bar{W}_k$ 用于事件检索。
- **Sparse Event Memory** $C_k$：仅在事件写入规则触发时变化，每个事件包含 64 个视觉 token、8 个 Stage Info token、8 个时间 token、检索键 $\kappa$ 与写入查询索引 $b_i$；容量 16 条，按阶段切换写入（RMBench 阶段阈值 0.55，无标注数据集每 3 次查询写一次）。检索用年龄感知余弦相似度公式 $\rho_{k,i}=\cos(\mathrm{LN}(q^{e}_k),\mathrm{LN}(\kappa_i+\mathrm{Emb}_{age}(\mathrm{clip}(k-b_i))))$，取出 anchor 加两个非 anchor 记录，经 cross-attention 形成读取 token $Z^e_k$，与 $L_k$ 融合得到 $g_k=\mathrm{Fuse}(L_k, Z^e_k)$。

#### Motion Tail（运动连续性侧）
两条模型侧路径：
- **Tail tokens** $U_k=\phi_U(u_k)$：4 个 token 进入 Working State 构造，影响事件检索；
- **Trajectory-aligned initialization**：对齐归一化的后缀作为解码器初始均值 $\mu_{k+1}=I(u_{k+1})$，加噪后形成条件化初始 $e^{(0)}_{A,k+1}=\mu_{k+1}+\sigma_u \epsilon_{k+1}$，等价于 $e^{(0)}_{A,k+1}\mid u_{k+1}\sim \mathcal{N}(\mu_{k+1},\sigma^2_u I)$。

解码器（DiT backbone）在最新观测下重新生成全部视野位置，不复制或冻结任何位置。解码完成后，控制侧对重叠步做线性混合（execution-side handoff）。

### 2.3 查询转移方程
$$
(A_k, W_k, C_{k+1})=F_\theta(x_k, D_k, W_{k-1}, C_k, u_k),\quad u_{k+1}=\mathrm{Tail}(A_k)
$$
其中 $D_k$ 为已执行动作历史，独立于 Motion Tail；episode 间状态全部清零。

### 2.4 训练
- 训练沿 episode 查询顺序展开，前一查询的尾端被 detached 后供下一查询使用（应用概率 0.5，否则掩码 tail 路径使用标准噪声初始化）；
- 损失包括 conditional-flow 动作目标、阶段监督（标注可用时）、overlap-consistency 正则（权重 0.2，仅在 Motion Tail 启用时）；
- 阶段标签仅监督事件写入，不进入动作解码器。

## 6. 主要结论与发现

1. **主结果**：
   - RMBench 平均成功率 **62.8%**（1.2B 参数），在五项全覆盖方法中超越 Mem-0（52.8%，8B+2B），Put Back Block 单项达 96%，Swap Triangle 74%；
   - LIBERO 四套件平均 **98.8%**，LIBERO-Long 98.2%，每个套件均超 98%。
2. **非对称消融**：仅保留任务进度（w/o Motion Tail）= **11.2%**；仅保留运动连续性（w/o Progress Context）= **3.0%**；二者皆去（w/o Both）= 1.6%。两个单侧组件性能相加远低于 Full（62.8%），说明二者不是独立可叠加改进。
3. **运动-记忆耦合**：去掉 Motion Tail 后，保留的记忆通路仍完整，但成功率大幅下降；这是因为运动边界跳变会改变后续观测流，使 Progress Context 在分布外查询上工作。Full 相对 w/o Motion Tail 在四个边界诊断上分别下降 56.6%、40.4%、57.4%、43.1%。
4. **后解码平滑不能替代**：Linear Continuation 边界值最低但成功率 0–2%；Temporal Ensemble 边界改善但成功率同样为 0%。说明接缝处的运动平滑只能插值两个已生成的计划，无法改变解码过程本身；Motion Tail 的关键在于把未执行片段送入状态构造和生成阶段，而非后处理。
5. **关键洞见**：运动连续性保护了"任务进度推断所依赖的观测流"，二者是"链式连接"而非"并行能力"。

## 7. 优点

- **统一框架**：首次在同一 per-query 状态更新中显式联合任务进度（observation-derived）与运动续接（prediction-derived），且二者对解码器均为可修订先验；
- **优雅的非对称消融实验**：通过单侧移除揭示二者并非独立可加，明确指出运动连续性是任务进度观察输入的"维护者"；
- **丰富的边界诊断**：四个互补的局部指标 + 匹配场景 paired rollout 设计，使运动侧效应可量化、可重现；

- **训练-推出一致性**：训练沿 episode 查询顺序展开，状态转移方程与 rollout 完全一致；
- **写作上**：明确划定了"诊断 ≠ 目标""匹配对比 ≠ 因果"的边界，并坦诚报告边界度量不衡量物理平滑或累积状态偏差。
