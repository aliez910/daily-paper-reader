## 摘要
长时序机器人操控将众多接触丰富的技能串联成一个多阶段任务。视觉-语言-动作（VLA）模型日益精通各项单一技能，但整体链路仍然失败：错误不断累积，超出策略的可修正能力，并且某个子任务会悄然限制下一个子任务。一种颇具前景的方案是冻结VLA，由LLM智能体主导：它以语言进行规划，使用解析式原语在自由空间运动，仅在接触丰富段落调用VLA，并将适配信息写入语言记忆。然而应用于长时序场景时，这种方案会遭遇两次失败。（1）能力来源于测试时的整任务探索，其成本随阶段数呈乘性增长：若某个阶段需要T轮尝试，则K阶段任务需约T^K轮，且失败时无法定位是哪个阶段导致。（2）该方案缺乏对转移的表示：VLA原语仅有退出条件而无进入条件，因此子任务可能以某种形式成功，但其后续任务却无法使用。我们提出了BATON。针对问题（1），BATON将子任务作为探索单元：在代价低廉的短时序范围内对每个子任务进行探索，并将解存储于记忆；长时序轨迹随后由这些解组合而成，而非整体发现。成本变为可加（T*K），且每次失败可归因于单一阶段。针对问题（2），BATON为探索配备了转移感知记忆。在子任务内部，验证智能体管理调用转移：仅当腕部视角确认场景就绪后才调用VLA。在子任务之间，交接转移恢复被前序子任务残余破坏的进入状态；前瞻转移则选择后续任务可继承其结果的那种策略。该方法无需更新任何参数。在长时序基准RoboMemArena上，BATON相对当前最优方法，任务成功率提升11.6%，累计成功率提升14.9%。

## Abstract
Long-horizon robot manipulation chains many contact-rich skills into one multi-stage task. Vision-language-action (VLA) models increasingly master the individual skills, yet the chain still fails: errors compound beyond the policy's ability to correct, and one subtask silently constrains the next. A promising recipe freezes the VLA and puts an LLM agent in charge: it plans in language, moves in free space with analytic primitives, invokes the VLA only for contact-rich segments, and writes adaptation into language memory. Applied to long horizons, it breaks twice. (1) Competence comes from whole-task exploration at test time, whose cost is multiplicative in stages: if one stage needs T episodes, a K-stage task needs about T^K, and a failure does not reveal which stage caused it. (2) It has no representation of transitions: the VLA primitive carries an exit but no entry condition, so a subtask can succeed in a form its successor cannot use. We present BATON. Against (1), BATON makes the subtask the unit of exploration: each is explored in the cheap short-horizon regime and its solution stored in memory; a long-horizon trajectory is then composed from these solutions rather than discovered whole. Cost becomes additive (T*K) and every failure is attributed to a single stage. Against (2), BATON equips exploration with a transition-aware memory. Within a subtask, a verifier agent governs the invocation transition: the VLA is called only after the wrist view confirms the scene is ready. Across subtasks, a handoff transition restores an entry state disturbed by the predecessor's residue, and a lookahead transition selects the strategy whose outcome the successor can inherit. No parameters are updated. On the long-horizon benchmark RoboMemArena, BATON improves task success by 11.6% and cumulative success by 14.9% over the SoTA.

# 论文总结：Don't Drop the BATON

## 一、核心问题与研究动机

### 1.1 问题背景
- **任务定义**：长时序机器人操控任务（如"整理厨房"）由多个接触丰富型短技能串联而成，单个任务可达 1000+ 控制步骤。
- **关键困境**：Vision-Language-Action（VLA）模型与 World-Action Models（WAMs）在单项接触丰富型技能上能力日益精进，但把它们串成长链时仍会失败：
  - 误差逐级累积，超越策略的可纠错能力；
  - 前序子任务会以"成功但残局污染"的方式悄然限制后续子任务的可行性。
- **典型证据**：π0.5 在 RoboMemArena 千步家庭任务中能完成约 50% 的中间阶段，但完整任务成功率仅约 10%。

### 1.2 已有方案及其局限
- **Harness VLA 范式**：冻结一个预训练 VLA，由 LLM 编码智能体在语言层规划、用解析原语在自由空间移动，仅把接触丰富段交给 VLA，并把适配经验写入语言记忆。该方案在短时序任务上工作良好。
- **应用于长时序时的双重失败**：
  - **❶ 探索成本乘性放大**：全程探索要求 K 个子任务同时成功，所需 episode 数近似为 \(T^K\)（每阶段平均 T 次试验，乘性放大），一次失败无法定位哪个阶段出错。
  - **❷ 无转移表征**：VLA 原语仅有"退出条件"而无"进入条件"，子任务可以以一种后继无法继承的形式成功；子任务之间存在两类跨越（handoff 与 lookahead），现有方案未对它们建模。

## 二、方法论

### 2.1 整体思想：把"转移"作为一等公民
- **核心洞察**：长时序操控的失败根源不在技能，而在技能之间的转移——既有子任务内部的"调用转移"，也有子任务之间的"交接转移"与"前瞻转移"。
- **高层架构**：单一 LLM 智能体同时扮演三个角色——
  - **Explorer**：在测试时探索单个子任务；
  - **Verifier**：基于腕部相机判断场景是否就绪；
  - **Scheduler**：根据后续计划选择当前子任务的执行策略。
- **统一公式**：
  - 短时序分解（Eq. 2）：\(T = u_1 \triangleright \sigma_{1,2} \triangleright u_2 \triangleright \dots \triangleright \sigma_{K-1,K} \triangleright u_K\)，其中 \(u_k\) 为子任务，\(\sigma_{k,k+1}\) 为交接边界。
  - 调用转移显式化（Eq. 3）：\(u_k = a_k \triangleright \sigma^{act}_k \triangleright v_k\)，把"agent→VLA"的跨越写为可检查的条件转移。

### 2.2 关键机制一：分层子任务探索（针对 ❶）
- **以子任务为探索单元**：先由 LLM 把长指令拆解成 K 个短子任务，再分别在短时序范围内探索每个子任务，避免长链乘性失败。
- **代价由乘变加**：总探索代价近似 \(T \cdot K\)（加性），不再是 \(T^K\)。
- **失败归因局部化**：失败发生在某个命名子任务或某个命名边界，可被诊断与修复；类似接力队分别训练各棒交接。
- **分层组合**：从相邻单元开始，逐级向外交验——先链成"开抽屉-关抽屉"，再逐步扩大，直到完整任务；写回内存的只在边界失配处。

### 2.3 关键机制二：转移感知记忆（针对 ❷）
记忆 M 由三部分组成，统一按"节点-边"的图结构组织：
1. **技能记忆（节点）**：每个子任务的多份粗轨迹（包含成功与失败），彼此互为"竞争策略"。
2. **转移记忆（边）**：承载三种条件。
   - **调用转移（invocation transition）**：子任务内部，由腕部相机 verifier 判定场景是否就绪；只有条件成立才调用 VLA，否则用解析原语重新 staging。例如"打开微波炉门"前要求两夹爪指针从两侧夹住把手；
   - **交接转移（handoff transition）**：记录后继子任务的入口条件（Entry condition），由 verifier 在边界用解析原语恢复（如开完微波炉后重置腕部姿态为垂直、张开、悬于物体上方）；
   - **前瞻转移（lookahead transition）**：根据剩余计划 \(P_{>k} = \langle u_{k+1}, \dots, u_K \rangle\) 的执行约束，由 Scheduler 在多个竞争策略中选择一个"后继可继承"的形式。例如：与"放入微波炉"配合时只能侧握抓罐子（顶握过高过不去），与"长距离运输+倾倒"配合时则须深顶握到底。
3. **失败记忆**：每次失败都被语言化存储，后续重试绕开重复错误。

### 2.4 训练范式
- **零参数更新**：没有任何梯度训练或微调；所有新知识以语言形式写进记忆，可在任务间迁移。
- **后端可替换**：任何以同样接口（带 prompt 与 stop predicate）暴露的接触丰富型策略都能接入；论文以冻结的 π0-family VLA 作为默认后端。

## 三、实验设计

### 3.1 基准
- **RoboMemArena**：26 个家庭场景任务，平均 1000+ 控制步骤，3–9 个验证阶段，部分可观测厨房；68.9% 的子任务为"记忆依赖型"。
- **四大类别**：Transferring（4）、Occlusion（11）、Counting（7）、Sequence（4）。

### 3.2 度量
- **任务成功率（TSR）**：所有验证阶段均满足的任务占比；
- **累计成功率（CSR）**：完成的阶段占比。

### 3.3 协议
- 探索用参考配置 seed 50；评估用两个保留配置 seed 51、52 并平均。
- 探索预算：Harness VLA 每完整任务最多 20 个 episode。

### 3.4 对比方法
- **基准报告方法**：GPT-5.4（裸 VLM 智能体）、π0.5、HiF-VLA、MemoryVLA、MemER、PrediMem（含/不含 GT 记忆 oracle）、FrameSamp+Modul。
- **自跑基线**：Harness VLA 完整任务探索（同 seed、同预算）。
- **后端**：冻结 π0-family VLA（与 Harness VLA 一致）。

### 3.5 主要结果（Tab. 1 平均列）
- BATON：**TSR 57.7%，CSR 78.8%**；超过此前最强报告系统 FrameSamp+Modul（TSR 46.1%、CSR 63.9%）**+11.6 / +14.9 个百分点**。
- **同时超越 PrediMem + GT Memory Oracle（46.1 / 64.8）**——理论上界本身被打破；
- 类别领先主要在 Occlusion（50.0 vs 39.1）与 Counting（68.8 vs 31.4）；
- 任务→阶段的转换率最高（73%），表明剩余失败较少集中在边界；
- Transferring 类别落后 FrameSamp+Modul，主因是一个任务（任务19）的 BDDL 场景定义在保留种子上有缺陷，导致所有方法均得零分。

## 六、主要结论与发现

1. **长时序操控的瓶颈是"转移"，而非技能本身**——把转移作为一等对象进行语言级约束，即可大幅超出"完美记忆 Oracle"。
2. **以子任务为探索单元的代价是加性的**，并使失败具备可定位性；这借鉴了接力队"逐棒训练"的思路。
3. **三种转移各司其职**：调用转移保证 VLA 不被错误时机激活；交接转移修复残留状态；前瞻转移保证当前策略产生的结果可被后续继承。
4. **全程零参数更新**，所有经验以语言写回，可读、可审、可在任务间复用。
5. **跨越泛化性**：转移条件按"边"而非"任务"索引，"在带窄边的容器中释放"等约束可在篮子、抽屉等之间迁移。

## 七、优点

- **问题定位精准**：把"长链失败"重新表述为"转移失败"，把乘性失效转为加性学习。
- **机制解耦清晰**：三角色（Explorer / Verifier / Scheduler）+ 三转移（invocation / handoff / lookahead）的对应关系明确。
- **实用性强**：无需任何参数更新与训练，部署到新机器人后端只需保留接口。
- **可解释性**：所有"经验"以自然语言写回，便于审计与跨任务复用。
- **性能超过理论上界**：在 RoboMemArena 上击败带 GT 记忆的 oracle，对组合性问题的诠释具有说服力。
- **类别结果具有诊断意义**：Occlusion 与 Counting 上的大幅领先正好对应"记忆依赖型"子任务占比最高的类。

## 八、不足与局限

- **缺乏显式消融**：未单独剥离"分层探索"与"转移感知记忆"两者贡献，难以量化各自的作用大小。
- **基准单一**：仅在 RoboMemArena（26 任务）上评估，部分类别（如 Sequence 仅 4 任务）样本偏少，且存在已知 BDDL 缺陷任务，可能影响 Transferring 结论。
- **算力与推理开销不透明**：未报告智能体调用 VLA 的频率、LLM token 消耗、wall-clock 时长等，对实际部署成本参考有限。
- **后端假设较强**：依赖子任务内部存在可被腕部相机观察的"准备就绪"线索，对于遮挡严重或视角受限的场景，verifier 自身的可靠性同样脆弱。
- **跨任务迁移未定量评估**：虽然文中声称"转移按边索引"具有泛化性，但未在跨任务集合（如把在篮子里释放的策略迁移到抽屉）上给出量化指标。
- **对手策略覆盖可能不全**：竞争策略（rival strategies）只有在某个下游约束"判否"既有策略后才新增，存在系统性遗漏的可能。
- **与 oracle 对比的解读**：BATON 在平均上超 GT-mem oracle，但单类（Sequence、Transferring 之一）仍落后，未给出系统化归因。
