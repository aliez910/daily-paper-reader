## 摘要
机器人在每个决策步接收异构观测，而序列模型在如何随时间组织这些输入方面有所不同。我们提出了 WorldToken，一种时序优先的策略实例化方法，将每个策略时间步内的多视角图像、本体感知和任务条件融合为一个世界令牌。一个因果时序 Transformer 对生成的世界令牌序列进行建模，扩散动作头生成动作片段。在 23 个 RoboCasa 任务上，除了一个冻结的预训练 CLIP 文本编码器外，一个 85.3M 参数的策略从零开始训练，每个任务使用 2,900 条生成演示数据，实现了 59.45% 的平均闭环成功率。在五种数据集规模、五种模型规模和两个训练随机种子上的完整因子扫描显示，增加目标域数据带来持续收益，而超过中等模型规模后收益递减。在相同检查点历史截断条件下，将可见历史缩短至一或两个策略时间步会降低全部 50 个 RoboCasa 策略的闭环成功率。在 RMBench 方块排序任务中，将可见历史从 146 秒缩短至 8 秒使评估器成功率从 95% 降至 28%，而一项探索性扩展执行使参考交换序列持续超过 850 秒。这些结果确立了完整 WorldToken 实例化的实证可行性，并刻画了其在所测试方案下的数据扩展和时序上下文行为。它们并未确立其相对于其他序列组织方式的优越性，也未分离出完整实现中哪些组件驱动了所观察到的性能。

## Abstract
Robot policies receive heterogeneous observations at each decision step, yet sequence models differ in how they organize these inputs over time. We introduce WorldToken, a time-first policy instantiation that fuses multiview images, proprioception, and task conditioning within each policy timestep into one world token. A causal temporal Transformer models the resulting world-token sequence, and a diffusion action head generates action chunks. On 23 RoboCasa tasks, an 85.3M-parameter policy trained from scratch apart from a frozen pretrained CLIP text encoder achieves 59.45% mean closed-loop success using 2,900 generated demonstrations per task. A complete factorial sweep over five dataset sizes, five model sizes, and two training seeds shows consistent gains from additional target-domain data and diminishing returns beyond moderate model size. Under same-checkpoint history truncation, reducing visible history to one or two policy timesteps lowers closed-loop success for all 50 RoboCasa policies. On RMBench Blocks Ranking, reducing visible history from 146 to 8 seconds lowers evaluator success from 95% to 28%, while an exploratory extended rollout sustains the reference swap sequence for over 850 seconds. These results establish the empirical feasibility of the complete WorldToken instantiation and characterize its data-scaling and temporal-context behavior under the tested recipes. They do not establish superiority over alternative sequence organizations or isolate which components of the complete implementation drive the observed performance.

# WorldToken：面向机器人模仿学习的时序优先序列建模 — 论文总结

## 1. 核心问题与研究动机

- **基本问题**：当把机器人策略写成序列模型时，"序列中的每个 token 应当代表什么"这一问题尚无统一答案。不同方案将每个策略时间步展开为多个模态专属 token，或通过循环模块、显式记忆、检索机制处理历史。
- **物理直觉**：与文本序列以 token 为天然单元类似，物理世界也存在天然的组织轴——**物理时间**。每个策略时间步本身就是一个"观察—决策—重规划"的闭环事件。
- **研究动机**：将"策略时间步"作为顶层序列单元（即"时序优先"），在步内完成多模态融合，使序列长度等于决策次数，与模态或感知 token 数量解耦，从而为后续时序建模与动作生成提供干净、可干预的接口。

## 2. 方法论

### 2.1 核心思想
将策略分解为三段：**(1) 步内多模态编码器** $\mathcal{E}_\theta$ → 单个世界 token；**(2) 因果时序 Transformer** $\mathcal{T}_\phi$ → 历史表征 $h_t$；**(3) 扩散动作解码器** $\mathcal{D}_\psi$ → $H$ 步动作块。公式：
$$z_t = \mathcal{E}_\theta(o_t),\quad h_t = \mathcal{T}_\phi(z_{\leq t}),\quad A_t \sim \mathcal{D}_\psi(\cdot|h_t)$$

### 2.2 关键技术细节
- **步内编码器**：
  - 每个相机有 5 阶段 CNN stem（5×5 卷积 + maxpool + GN + SiLU），128×128 图像 → 4×4×768 特征。
  - 本体感知与任务文本投影后与多视角 patch token 拼接为步内序列。
  - 引入 **4 个可学习 readout token** $Q=(q_1,\dots,q_R)$：观测 token 的 query 不能关注 readout key，但 readout 可关注所有观测 key，从而聚合而不污染观测表征。
  - 输出 $z_t = W_z \cdot \text{RMSNorm}([r_1^t;\dots;r_R^t])$，即步内仅有 **1 个 token 进入时序主干**。
- **时序主干**：
  - 基于 Qwen2 解码器架构，**从零训练**（仅 CLIP 文本编码器冻结预训练）。
  - 使用一维 RoPE 沿世界 token 序列编码策略时间。
  - 因果自注意力保证 $h_t$ 只依赖 $z_{\leq t}$；最大可见历史长度 $C$，滑动时仅重索引，相对几何不变。
- **扩散动作头**：
  - DiT 噪声预测，$\hat{\epsilon} = \epsilon_\psi(A_t^{(k)}, k, h_t)$，由 $h_t$ 与扩散步 $k$ 通过 **adaLN-Zero** 调制每块。
  - 每个查询生成 $H=10$ 个动作，仅执行前 $H_\text{exec}=4$ 个，再重规划（receding horizon）。
  - 推理采用 20 步随机 DDPM 采样。
- **重要设计取舍**：
  - 不将执行过的动作显式插入序列；动作的影响通过下一帧图像与本体感知回流到上下文。
  - 仅监督动作生成，不监督未来世界预测。

## 3. 实验设计

### 3.1 数据集与场景
- **RoboCasa**：23 个日常家务操作任务（已剔除 OpenDoubleDoor，仅有 1,500 演示）。每任务保留 100 条 holdout 演示（共 2,300），与训练集互不相交。
- **RMBench Blocks Ranking**：方块排序长程任务，按固定 3 步周期 `swap(M,R)→swap(L,R)→swap(L,M)` 交换 1–5 次到达目标。

### 3.2 训练配置 sweep
- **数据集大小 $D$** ∈ {50, 100, 300, 1000, 2900} 演示/任务。
- **模型规模** ∈ {44.3M, 85.3M, 218.8M, 648.9M, 1.49B}。
- **训练种子**：2 个 → **5×5×2 = 50 个策略**。
- **上下文长度 $C_\text{train}=10$**（RoboCasa 主实验）。
- 评估采用官方 seen/unseen 场景协议，**每策略 3 次完整评估**，每次每任务 50 episode → 共 **172,500 条闭环 episode**。

### 3.3 对比方法
- **本地 BC-Transformer 基线**（官方代码复现），相同 23 任务与 1,150 episode 评估注册表，但优化器/步数/动作执行节奏未对齐。
- **公开 RoboCasa 系统**：X-WAM、Xiaomi-Robotics-1、GR00T N1.5/N1.6、Cosmos Policy P2/P2.5、π0/π0.5/π0-FAST、Video Policy、HAMLET、DreamZero、FLARE 等（24 任务，多为亿级预训练 VLA），仅作量级参照，协议不匹配。

### 3.4 消融/干预
- **同检查点历史截断**：所有 50 个 RoboCasa 策略，$C_\text{test}\in\{1,2,5,10\}$。
- **短上下文重训**：218.8M / D=300，$C_\text{train}=C_\text{test}\in\{1,2,5,10\}$。
- **Blocks Ranking 同检查点截断**：$C\in\{608,288,128,64,32\}$（约 7.68–145.92 秒可见历史），100 个初始条件。
- **探索性扩展 rollout**：9 条轨迹继续到首次成功后不重置，测试周期性规则能否超出训练演示长度。

  - 8 × NVIDIA H100-80GB

## 5. 实验数量与充分性

### 5.1 实验规模
- **50 个 RoboCasa 策略**（5×5×2 sweep）+ **8 个上下文长度对照组**（4×2 种子）。
- **Blocks Ranking**：5 个可见上下文长度 × 100 episode + 9 条扩展 rollout。
- **单锚点架构诊断**（D=300，C=10）：时序放置、当前观测旁路、token 粒度（K∈{1,2,4,50}）、视觉宽度、动作头 LR、动作分布（高斯/GMM）等。
- 总评估 episode 数 172,500（RoboCasa 主实验），并报告方差与 Spearman ρ = −0.980。

### 5.2 客观性与局限
- 优势：
  - 每个 sweep cell 报告 3 次重复的标准差，跨种子给出 25 对比较。
  - RMSE 与 SR 分开讨论，明确两者非简单替代关系。
  - 公开"recovery status"标签（recovered-exact / repair-log / archived-only），透明披露哪些数字可独立复算、哪些只能从前损手稿读取。
- 局限：
  - 仅一组 WorldToken 实现族，未与显式记忆（M em-0、MemoryVLA）、状态空间（Chronos）、patch-level tokenization 等其他序列组织做"公平对照"。
  - 单锚点架构诊断多仅 1 个种子（如 token 粒度、视觉宽度、动作分布），不足以做组件归因。
  - 扩展上下文证据集中于 Blocks Ranking 一个长程案例。
  - 14.24% SR 相对范围覆盖了相邻高配 cell 之间的多数小差异。

## 6. 主要结论与发现

- **有效多任务控制**：85.3M 参数 WorldToken 在 23 个 RoboCasa 任务、2,900 演示/任务下达到 **59.45% 平均闭环成功率**（2 种子均值），最佳单次 60.1%；218.8M 同规模达到 **60.26%**，最佳单次 **62.0%**；进入 24 任务、十亿级预训练 VLA 报告的 50–79% 区间，且只在 D=300 上就比 BC-Transformer 复现高 12–16 pp。
- **数据扩展一致有效**：相邻数据量 40 对比较全部提升 SR、降低 RMSE；D 从 50 → 2900 使 SR 提升 32.7–39.3 pp，RMSE 下降 47.0–56.8%；RMSE 数据尺度符合 $a_P D^{-\alpha_P}$ 描述性幂律，$\alpha_P\in[0.151,0.211]$，$R^2\in[0.990,0.999]$。
- **模型规模收益递减**：44.3M → 218.8M 持续改进；超过 218.8M 后无稳定优势；高数据下 648.9M 与 218.8M RMSE 几近重合；闭环比上 85.3M 以上容量无清晰排序。
- **时序上下文被显著使用**：所有 50 个 RoboCasa 策略在 $C_\text{test}=1$ 或 2 时均掉点（最小 3.5 pp），但仅 $C_\text{test}=5$ 已接近 $C_\text{test}=10$（47/50 在 2 pp 内）；重训的短上下文策略恢复大部分掉点，表明部分历史依赖是**训练上下文适应**而非不可约任务需求。
- **RMSE ≠ SR**：在 D=300 锚点 $C=5\to10$ 时 RMSE 改善但 SR 下降；时序放置诊断中 WorldToken RMSE 低 6.4–8.7%，但 DP-like 变体 SR 高 1.4–3.0 pp。
- **Blocks Ranking 长程**：$C=608\to32$ 使评估成功率从 95% 降到 28%；困难集中在多交换顺序任务而非单步操作；扩展 rollout 中一条轨迹完成 31 次正确顺序交换（持续到 856.44 秒），最后正确交换距上下文开始滑动（145.92 秒）后仍能继续 710+ 秒，说明学到了**周期性规则**而非仅复现有限前缀。

## 7. 优点

- **接口清晰**：在策略时间步这一稳定语义单元上解耦"步内感知压缩 / 跨步时序计算 / 动作生成"，使各阶段可独立干预与归因；附录 E 中多个单锚点诊断正利用这一性质。
- **完整析因实验**：5×5×2 sweep + 上下文长度实验 + 单锚点组件消融，配合 3 次重复评估，方差透明。
- **历史利用的精细拆解**：同检查点截断 + 短上下文重训"双干预"，明确区分"学到用历史"与"任务需要历史"。
- **可重复性披露**：详细的 hyperparameter provenance（Appendix B）、recipe frozen before sweep、recovery status 标注（Appendix G）提升研究可信度。
- **公开材料**：表格与附录公开 23 任务下 218.8M D=2900 seed1 repeat02 的逐任务成功率（62.0%），便于与外部系统对照。
- **与语言建模类比自然**：将策略步类比会话前缀，使时序压缩与主动感知可联合设计。

## 8. 不足与局限

- **组织比较缺位**：仅展示一个完整 WorldToken 实现族，未与其他序列组织（patch-level tokenization、显式记忆 bank、状态空间模型、循环状态压缩）做协议匹配对比；作者明确承认"未确立优于其他组织"。
- **单锚点诊断过浅**：时序放置、当前观测旁路、token 粒度等多数组件诊断仅 1 种子、1 数据量，且 sweep 范围对架构归因而言仍太小。
- **证据集中在仿真**：仅 RoboCasa（23 任务）+ RMBench Blocks Ranking（1 任务），无真机验证，不测量真实机器人不确定性、扰动与延迟。
- **动作生成以外未验证**：未将显式执行动作插入序列、未加入预测式世界模型目标、未评估系统级延迟/内存/能耗。
- **扩展上下文证据单一**：仅 Blocks Ranking 一个长程任务；stress test 是探索性、未与其他记忆方案对照。
- **数据泄露与完整性风险**：原始实验服务器被入侵导致主存档删除；一个 seed-1/D=2900/1.49B 终态 RMSE cell 为 archived-only；任务级 SR 方向审计存在 157/10/63 vs 158/10/62 两种 archived-only 记录无法裁决；一个 evaluator 一回合 episode 存在 reset 解释冲突，文中已声明"不作数值结论"。
- **可重复性提醒**：SR 三次重复相对范围中位数 3.40%、最大 14.24%，相邻高配 cell 之间多数差异落在该范围内，意味着 SR 不适合做细粒度模型选择，应以 RMSE + 多粒度 SR 综合判断。
- **基准任务覆盖偏少**：RoboCasa 23 任务（而非官方 24）且为厨房子集，无法覆盖户外、移动、长视野等场景。
