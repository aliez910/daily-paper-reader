## 摘要
长时程机器人操控将众多富含接触的技能串联成单一多阶段任务。视觉-语言-动作（VLA）模型日益精通各项独立技能，但整条链路仍会失败：误差不断累积，超出策略可修正的能力，且一个子任务会在无形中限制下一个。一种颇具前景的方案是冻结VLA，转而由LLM智能体主导：它以语言进行规划，使用解析式基元在自由空间中运动，仅在富含接触的片段调用VLA，并将适应过程写入语言记忆。然而应用于长时程任务时，该方案会出现两处缺陷。（1）能力来自测试时的整体任务探索，其代价随阶段数呈乘法增长：若某一阶段需要T轮尝试，一个K阶段的任务大约需要T^K轮尝试，且一次失败无法揭示是由哪一阶段所致。（2）该方案缺乏对转移的表示：VLA基元带有退出条件却没有进入条件，因此子任务可能以一种其后续任务无法使用的形式成功完成。我们提出BATON。针对（1），BATON将子任务作为探索单元：每个子任务在廉价的短时程模式下进行探索，其解被存入记忆；长时程轨迹由这些解组合而成，而非整体性地被发现。代价变为可加的（T*K），且每次失败均可归因于单一阶段。针对（2），BATON为探索配备了转移感知记忆。在子任务内部，验证器智能体管控调用转移：仅当腕部视图确认场景就绪后才调用VLA。在子任务之间，移交转移恢复被前一阶段残留扰动的进入状态，前瞻转移则选取其结果能被后续任务继承的策略。整个过程不更新任何参数。在长时程基准RoboMemArena上，BATON相较当前最优方法将任务成功率提升11.6%，将累积成功率提升14.9%。

## Abstract
Long-horizon robot manipulation chains many contact-rich skills into one multi-stage task. Vision-language-action (VLA) models increasingly master the individual skills, yet the chain still fails: errors compound beyond the policy's ability to correct, and one subtask silently constrains the next. A promising recipe freezes the VLA and puts an LLM agent in charge: it plans in language, moves in free space with analytic primitives, invokes the VLA only for contact-rich segments, and writes adaptation into language memory. Applied to long horizons, it breaks twice. (1) Competence comes from whole-task exploration at test time, whose cost is multiplicative in stages: if one stage needs T episodes, a K-stage task needs about T^K, and a failure does not reveal which stage caused it. (2) It has no representation of transitions: the VLA primitive carries an exit but no entry condition, so a subtask can succeed in a form its successor cannot use. We present BATON. Against (1), BATON makes the subtask the unit of exploration: each is explored in the cheap short-horizon regime and its solution stored in memory; a long-horizon trajectory is then composed from these solutions rather than discovered whole. Cost becomes additive (T*K) and every failure is attributed to a single stage. Against (2), BATON equips exploration with a transition-aware memory. Within a subtask, a verifier agent governs the invocation transition: the VLA is called only after the wrist view confirms the scene is ready. Across subtasks, a handoff transition restores an entry state disturbed by the predecessor's residue, and a lookahead transition selects the strategy whose outcome the successor can inherit. No parameters are updated. On the long-horizon benchmark RoboMemArena, BATON improves task success by 11.6% and cumulative success by 14.9% over the SoTA.

# BATON 论文详细总结

## 一、论文核心问题与研究背景

### 1.1 问题界定
- **任务背景**：长时程机器人操控（long-horizon robot manipulation）需要将多个接触密集（contact-rich）的子技能串联成一个多阶段任务（如"开抽屉 → 抓罐子 → 放入微波炉"），整条链路可达千步量级。
- **现状反差**：视觉-语言-动作模型（VLA，如 π0.5）能很好地掌握单个技能，但在子任务链式组合时表现崩溃——例如，π0.5 在 RoboMemArena 的千步级家庭任务上能完成约一半的中间阶段，但仅能完成约 10% 的完整任务（来自文献 [18]）。
- **失败根源（两条）**：
  - **误差累积**：端到端 VLA 仅从规范化初始状态通过模仿学习获得，测试时各阶段起始状态由前序阶段决定（分布外），无法识别与修正漂移。
  - **执行耦合**：一个子任务如何执行会固定下一个子任务的起始状态；局部成功的执行可能留下使后续任务不可行的残骸（如打开抽屉后夹爪朝向偏差导致下一抓取失败）。

### 1.2 现有方案及其在长链路下的两度失效
"冻结 VLA + LLM 编码智能体"（如 Harness VLA）的组合曾成功用于短时程任务：智能体用语言规划、用解析式基元在自由空间运动，仅在接触段调用冻结的 VLA，并将经验以语言形式写入记忆。然而在长时程下失败两次：
- **❶ 探索成本乘性膨胀**：能力来自测试时全任务探索。单阶段约需 T 轮探索，K 阶段链路则需约 **T^K** 轮（呈指数增长）；失败还无法定位到具体阶段。
- **❷ 转场缺失**：VLA 基元有退出条件（stop predicate）但无进入条件；一个子任务可能以"对下一个不可用"的形式成功（如只开了缝隙的抽屉无法让手伸入）。

## 二、方法论

### 2.1 核心思想
将 **子任务作为探索单元**，将 **转场作为记忆的一等公民**；不更新任何参数，VLA 全程冻结；所有学习以语言形式记录、读取、复用。

### 2.2 总体架构
- **底座**：继承 Harness VLA 的"冻结 π0 家族 VLA + LLM 编码智能体"配置；分析式 IK 基元 + 一个被封装的 `VLA_ACT` 学习基元（带 prompt 与停止谓词）。
- **三个智能体角色**：
  - **Explorer（探索者）**：在短时程模式下探索单个子任务的解。
  - **Verifier（验证者）**：基于腕部摄像头图像判定场景是否就绪、移交状态是否恢复。
  - **Scheduler（调度者）**：读取剩余计划 `P_{>k}`，从多个候选策略中选出能被后续任务继承的那一个。

### 2.3 关键技术一：层次化子任务探索（Hierarchical Subtask Exploration）
- **公式 (2)：任务分解**
  $$\mathcal{T} = u_1 \triangleright \sigma_{1,2} \triangleright u_2 \triangleright \sigma_{2,3} \triangleright \cdots \triangleright \sigma_{K-1,K} \triangleright u_K$$
  其中 `u_k` 为子任务，`σ_{k,k+1}` 为移交边界。
- **先分解**：由智能体把长指令草拟为 K 个短时程子任务及 K−1 个边界，可继承以往任务中已存在的子任务/边界。
- **逐子任务引导（Bootstrapping）**：对每个无记忆条目的子任务，在短时程模式下试错——尝试分阶段序、预接触位姿、VLA 调用时机；失败写入**失败记忆**，首次成功固化为粗轨迹（含解析感知查询而非坐标）。
- **由内向外组合**：相邻已验证单元先行串联（如"开顶层抽屉 → 关它"），成功即作为新单元再与其邻居组合，逐轮放大直至覆盖整条链。
  - 边界探索代价加性：T^K → **K·T**。
  - 每条 K−1 个边界仅在两侧首次相遇的那一轮被检查一次。
  - 失败定位到具体阶段或边界，而非整个千步回合作废。

### 2.4 关键技术二：转场感知记忆（Transition-aware Memory）
三类转场，分别对应三类存储条目：

- **调用转场（Invocation Transition，子任务内部）**
  - **公式 (3)**：`u_k = a_k ▷ σ^{act}_k ▷ v_k`，其中 `σ^{act}_k` 为显式就绪条件。
  - 由 Verifier 基于腕部摄像头实时判定场景就绪（如抓握器手指必须位于把手两侧才能拉门；释放前手部必须位于容器四边之内），未就绪则重置再试，无法就绪则记入失败记忆而非强行调用。
  - 该条件随技能首次成功写入，并在测试阶段每次调用前读取，可拦截长链路末端的漂移。

- **移交转场（Handoff Transition，子任务之间，前向）**
  - 当前驱扰动了后继所需的进入状态（如开微波炉门后夹爪倾斜，下一抓罐子无法夹稳），边界记录**进入条件**（gripper 垂直、张开、位于罐子上方）。
  - Verifier 在边界以解析基元修复（re-orient / re-open / re-stage）。
  - 与经典技能形式化中的 initiation set 思想一致，但以语言零样本表达于边界，而非离线学习。

- **前瞻转场（Lookahead Transition，子任务之间，反向）**
  - 同一子任务可有多个竞争策略（侧抓、捏边、整把托起），正确选择取决于后续任务——放入微波炉只能用侧抓（高度限制），长距离倾倒则需整把托起（避免中段脱落）。
  - Scheduler 读取 `P_{>k}`，汇聚边界约束，从记忆中检索满足约束的竞争策略；若全不满足，则送回 Explorer 并附上约束重探。

### 2.5 统一记忆结构
按公式 (2) 的"节点-边"方式组织：
- **节点**（技能）：含失败条目、多个竞争粗轨迹，每个轨迹内嵌自己的调用转场就绪条件。
- **边**（边界）：仅在组合不"白送"时写入，含进入条件与执行约束，合称**移交契约** C_{k,k+1}。
- 边以转场类型为键（而非以任务为键），因此同一转场可跨任务复用（"释放入窄口容器"从篮子迁移到收纳箱）。
- 违反契约被写回并把违规策略在该契约下排除；约束随任务集增长保持加性。

## 三、实验设计

### 3.1 基准平台
- **RoboMemArena** [18]：26 个家庭长时程任务，平均 **>1000 步**、3–9 个验证阶段，部分可观测厨房场景；68.9% 子任务为记忆依赖型；阶段级谓词支持 TSR/CSR 测量。
- **四类任务**：Transferring（4 项，源-目映射）、Occlusion（11 项，遮挡下位置/状态）、Counting（7 项，重复计数）、Sequence（4 项，前置决定后继）。

### 3.2 实验设置
- **底座**：冻结 π0 家族 VLA + LLM 编码智能体（沿用 Harness VLA 配置）。
- **协议**：所有探索在单一种子 **seed 50** 完成；评测在两个留出种子 **seed 51、52** 取平均。

### 3.3 对比方法
- **基准报告**：GPT-5.4（纯 VLM，无操作基座）、π0.5（反应式）、HiF-VLA、MemoryVLA、MemER、PrediMem（含/不含 GT 记忆 oracle）、FrameSamp+Modul。
- **本工作复现**：Harness VLA 原版，以 20 集/任务的预算做整任务探索。

### 3.4 评价指标
- **TSR（Task Success Rate）**：所有验证阶段均满足的任务成功率。
- **CSR（Cumulative Success Rate）**：完成阶段占总阶段的比例。

### 3.5 主要结果
- 平均 **57.7% TSR / 78.8% CSR**，较此前最强报告方法 FrameSamp+Modul（46.1 / 63.9）分别提升 **+11.6 / +14.9** 个百分点；超过 GT 记忆 oracle（46.1 / 64.8）。
- 最大优势集中在 Occlusion（50.0 vs. 39.1）与 Counting（68.8 vs. 31.4）；Sequence 与 Harness VLA 接近（82.0 vs. 83.4）。
- 阶段-任务转化率 73%，全表中最高。
- 仅 Transferring 类被 PrediMem 反超，作者指出部分由任务 19 在留出种子上的 BDDL 场景定义错误所致（任何执行均记零分）。

## 六、主要结论与发现

- **长时程操作的本质问题是"转场"而非"技能"**：单个技能足够好但跨阶段拼接失败，是当前主流方案被卡住的根因。
- **测试时探索的成本形态决定上限**：全任务探索呈乘性（≈T^K）扩展；以子任务为单元则呈加性（≈K·T）。
- **转场是缺失的对象**：调用转场需显式就绪条件；移交转场需可检查的进入条件；前瞻转场需把后续任务的需求反向传导到当前策略。
- **语言层契约即可编码这一切**：无需额外梯度、无需固定后继配对、无需手工公理库；契约以句子形式起草、检查、修订，并随任务集迁移。
- **记忆的键应是转场而非任务**：同一边界（如"释放入窄口容器"）可在多任务间复用，使经验增长保持加性而非乘性。

## 七、方法优势（Strengths）

### 7.1 概念层面的贡献
- **转场首次成为一等公民**：与传统方法将子任务视为原子单元不同，BATON 把"调用进入条件 / 移交进入条件 / 前瞻反传需求"三类转场从隐含实现提升为显式契约，为长时程操控提供了一个新的、可推理的问题维度。
- **零参数更新但能持续学习**：完全依赖语言层记忆读写，避免了重训/微调带来的灾难性遗忘与算力开销；且所有经验对人类可读、可审计。
- **乘性 → 加性的成本形态转变**：通过把全任务探索拆解为 K 段短时程探索再加 K−1 个边界组合，将探索成本从 ≈ T^K（指数）降至 ≈ K·T（线性），这是 BATON 在算力受限条件下可行的关键。

### 7.2 工程与系统层面的贡献
- **可重用的"节点-边"记忆**：以转场类型而非任务名作为键，同一边界（如"释放入窄口容器"、"夹爪复位到垂直张开"）可在新场景中零样本迁移；记忆的边际增量随任务数呈加性增长。
- **失败定位到节点或边，而非整回合**：当某条边界不白送时，只回滚至最近的已验证子任务，不必使整条千步链路作废。
- **多策略并行注册**：同一子任务在历史中可能沉淀多种竞争轨迹（如侧抓、捏边、整把托起），由前瞻转场反向筛选，避免了传统 SVM 等方法"一次定型、不可逆"的局限性。
- **对冻结 VLA 的兼容性极佳**：与 Harness VLA、π0.5 家族、即插即用的 LLM 智能体栈兼容；不锁定特定模型，亦不依赖大规模 GPU 集群。

- **超过 GT 记忆 oracle**：在多任务设定下，BATON（57.7 / 78.8）的 TSR/CSR 仍高于 PrediMem 的 GT 记忆上限（46.1 / 64.8），说明其"按需检索 + 校验"比静态记忆更适配分布外场景。

## 八、局限性（Limitations）

### 8.1 评估层面的不足
- **消融不充分**：三类转场（Invocation / Handoff / Lookahead）与 Hierarchical Subtask Exploration 的独立贡献在主文中缺乏逐项剥离实验；当前结果主要通过 BATON 整体与 Harness VLA 基线对比得出，无法定量识别每部分的边际收益。
- **种子数极少**：仅 2 个留出种子（51、52），且任务 19 在留出种子上存在 BDDL 场景定义错误——这本身就是"分布外敏感性"的反例，提示结果在更大评测池上的稳健性仍待验证。
- **单一基准**：仅在 RoboMemArena 上评估；缺少在 RLBench、Habitat-ManiSkill、真实硬件上的迁移性证据，外推风险较高。
- **类别劣势未深入归因**：Transferring 上 PrediMem 反超，但作者仅部分归因于任务 19 的 BDDL 错误；其余失败案例的根因（如子任务语义模糊、源-目歧义）未拆解。

### 8.2 方法层面的依赖与脆弱性
- **强依赖 VLM 调用作为 Verifier / Scheduler**：腕部摄像头就绪判定、移交状态恢复判定、策略选择均依赖视觉语言模型的黑箱输出；模型幻觉或视角遮挡会直接误导转场判定，论文未给出失败率统计。
- **依赖可靠的解析感知查询**：粗轨迹以"相对于对象几何的解析查询"编码，而非像素坐标。该抽象层依赖环境提供稳定的目标语义检测；当目标遮挡、外观剧变或类别新颖时，解析器失败而迫使重探。
- **前瞻转场需预知剩余计划**：Scheduler 读取 `P_{>k}` 才能反选策略；若任务语言计划存在歧义或被 LLM 误拆，可能导致前瞻契约无效。
- **零样本契约起草的可靠性**：移交契约由 LLM 起草而非经过验证；尽管契约可被"写回修订"，但初始错误仍可能消耗探索预算。
- **LLM 后端版本与提示工程未披露**：影响完全复现与公平性比较。

### 8.3 工程与可扩展性
- **算力账目缺失**：未报告探索阶段的总 LLM token 调用量、wall-clock 时间、单回合延迟；这在长链路测试时探索中可能并不小。
- **记忆膨胀风险**：跨任务积累的"按转场键"记忆条目会持续增长，虽然增长是加性的，但 LLM 读取与匹配开销随条目数线性上升，缺少长度剪枝与摘要机制说明。
- **能力提升天花板受限**：底座仍是冻结的 π0.5，技能粒度上限被 VLA 本身的接触密集能力所封顶；当 VLA 面对训练分布外的全新接触操作时，Explorer 仍无法在零样本下找到解。
- **未涉及真实机器人硬件**：仿真到现实的差距（光照、抖动、传感器噪声、物体物理属性）在文中未被讨论。

### 8.4 理论层面的开放问题
- **T^K → K·T 的声明缺乏严格证明**：论文以直觉性论述说明加性扩展与失败定位，但未给出带置信区间的探索复杂度上界，也未与下界（如必要探索次数）对照。
- **跨任务迁移的有效性边界**：转场键的泛化能力依赖 LLM 的语义相似性判断，"释放入窄口容器"到底能否迁移到化学实验台？尚无实验支撑。
