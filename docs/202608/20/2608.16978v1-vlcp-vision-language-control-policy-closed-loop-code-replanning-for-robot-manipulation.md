## 摘要
将一个前沿的视觉-语言模型改造为机器人策略，通常意味着对其进行微调以输出其在预训练中从未见过的动作表征，这会丢弃使该模型值得使用的绝大部分推理能力。我们走另一条路线，冻结视觉-语言模型不变。它将策略编写为一个简短的 Python 控制函数，无需任何演示数据，也无需微调。然而，一次性地编写这种代码是开环的。现有闭环方法在错误的层级上做出反应：它们重试一个固定的策略或选择不同的子任务，但从不重写失败的代码。VLCP 在失败真正发生的地方——即控制代码层面——闭合回路，且整个过程在单回合内完成。每隔 K 步，视觉-语言模型根据多视角 RGB、本体感受状态以及状态增量重新观察场景，然后基于其刚刚观察到的内容重写控制函数，从而在失败累积之前将其捕获。我们在涵盖 57 个任务的 MuJoCo/RoboVerse 基准上进行了评估。这一无需训练的方法取得了 35.1% 的综合成功率，而同一系统在每回合仅查询一次时的成功率仅为 3.5%。这一十倍的差距在所有场景类别中均具有非重叠的置信区间。该增益源于 27.3% 的回合内失败恢复率：一次本会被开环控制器延续到回合结束的抓取失误，在下一次重规划时被重新观察并修复。该闭环的开销依然较低。中位数 84% 的输入令牌命中缓存，一个回合仅需约 10 次紧凑查询，且任何重规划期间编写的控制块会被持久化到一个跨回合技能库中，供后续提示复用。

## Abstract
Turning a frontier vision-language model into a robot policy usually means fine-tuning it to emit an action representation it never saw in pretraining, which throws away much of the reasoning that made the model worth reaching for. We go the other way and keep the VLM frozen. It writes the policy as a short Python control function, with no demonstrations and no fine-tuning. Writing that code once is open-loop, though. Existing closed-loop methods react at the wrong level: they retry a fixed policy or pick a different subtask, but never rewrite the code that failed. VLCP closes the loop where the failure actually lives, on the control code, within a single episode. Every $K$ steps the VLM re-observes the scene from multi-view RGB, proprioceptive state, and a state delta, then rewrites the control function from what it just saw, so a failure is caught before it compounds.   We evaluate on a 57-task MuJoCo/RoboVerse sweep. This training-free policy reaches $35.1\%$ pooled success, against $3.5\%$ for the identical system queried once per episode. That tenfold gap holds with non-overlapping confidence intervals in every scene family. The gain traces to a $27.3\%$ within-episode recovery rate on failed grasps: a miss an open-loop controller would carry to the end of the episode gets re-observed and fixed at the next replan. And the loop stays cheap. A median $84\%$ of input tokens hit cache, an episode needs only about $10$ compact queries, and control blocks written during any replan persist to a cross-episode skill library reused in later prompts.

# VLCP 论文总结

## 1. 核心问题与研究动机

- **主流方案的代价**：将前沿视觉-语言模型（VLM）改造为机器人策略的通行做法是 VLA（vision-language-action），需要微调使其输出训练中从未见过的动作表征；这种适配会让模型脱离预训练分布，丢失大量原有的推理能力。
- **一次性生成代码的局限**："代码即策略"（code-as-policy）让 VLM 直接编写 Python 控制函数，无需演示与微调，但代码通常在回合开始前一次性写完，本质上是开环——抓取失败一旦发生，错误会无声地延续到回合结束。
- **现有闭环方法的层级错位**：已有闭环方法要么重试同一段固定策略，要么切换子任务，但从不改写真正失败的代码本身；最近的 Act-Observe-Rewrite 也只在"试验之间"重写控制器，而非在单个回合内。
- **本文要回答的问题**：能否在控制代码层面、单回合内闭合回路，让失败的代码在被观察到的那一刻就被改写？

## 2. 方法论

### 2.1 整体思路
- **冻结 VLM**：保持预训练 VLM 不变，让它在每次需要时直接写出一段 `control(obs, J) → actions` 的 Python 函数；动作由仿真器的 PD 控制器消费，雅可比矩阵 $J \in \mathbb{R}^{3\times 7}$ 解析计算后作为即时原语传入。
- **两层闭环**：
  - **块内闭环**（快）：同一段已编译的控制函数每步都会拿到新鲜的 `obs` 与 `J`，对数值状态有反应。
  - **块间闭环**（慢）：每隔 $K$ 步（默认 $K=50$）重新查询 VLM，让它根据多视角 RGB、本体感受状态与状态增量 $\Delta$ **重写**控制函数本身——这是"块间闭环"，正是修复行为错误的层级。
- **回合预算**：500 步一帧，每回合约 10 次重规划。

### 2.2 关键组件
- **视觉的角色**：特权物体位姿只用于初始化首次接近；失败征兆（抓取距离/角度偏差、夹爪闭合后空抓、物体被推移等）必须由同步多视角 RGB 在重规划边界读出。
- **提示词结构（最大化缓存复用）**：
  - **Block A**（静态前缀 ≈ 8k tokens）：机器人/环境文档、技能 API 源码、三个单阶段控制示例。
  - **Block B**（学习的技能库）：按修改时间排序、注入最多 12 个技能模块源码。
  - **Block C**（目标钉）：任务标识与自然语言目标，置于系统提示中以避免被历史截断。
- **用户回合内容**：上一块的起始 RGB + 生成的代码 + $K$ 步动作字典（提供尝试轨迹）；当前同步 RGB；JSON 数值观察摘要；请求下一 $K$ 步的控制函数。
- **跨回合技能库**：任何一次重规划可以附带写出 `# skills/<name>.py` 头部标签的辅助模块，原子写入 `control_policies/skills/`；按需尝试 `import`，失败则回滚并把错误传给下一轮。同一磁盘库也支持并发 LLM 策略实例。
- **历史与缓存**：对话历史最多 20 对（超过则从最前丢弃）；cache 断点设在最后一条助手消息，使下一轮前缀缓存命中率高达 84% 中位数。

### 2.3 操作成本（来自 81 回合、≈721 次重规划的实测日志）
- 每回合中位 10 次 VLM 调用；每次输入中位 43k tokens、缓存前缀 83.8%；输出中位 349 tokens；每次重规划中位 18.8 秒；全部 778 个生成代码块 100% 解析编译通过。

## 3. 实验设计

- **仿真平台**：MuJoCo via RoboVerse，机械臂为 Franka Panda 7-DoF + 平行夹爪。
- **任务集**：57 个任务横跨三大场景族
  - **Object Picks**（10）：来自 LIBERO-Object 的拾取任务。
  - **Kitchen Scenes**（30）与 **Living-Room Scenes**（17）：来自 LIBERO-90，涵盖关节动作、拾取放置、干扰消歧、堆叠与多步序列。
- **重规划模型**：GPT-5.5（封闭源 API），每 $K=50$ 步查询一次。
- **对比方法**：
  - **Open-loop VLCP（K=T）**：同一系统、同一任务集、同一模型，只关闭回合内重规划——唯一只动了"闭环"这一变量，是本文的核心控制消融。
  - **VLA-0**：用完整 LIBERO 演示数据微调的"上界参考"，仅在指令改写泛化实验中出现。
  - **CaP-Agent0**：同期训练-自由代码代理，作为外部参考点（不同基准/接口，仅引用其报告值）。
- **评估指标**：每个family 内的成功率及 Wilson 95% 置信区间；恢复行为在 75 个回合抓放置轨迹上直接量算。

## 4. 资源与算力

- **推理侧**：调用闭源 GPT-5.5 API；论文未给出本地 GPU 型号/数量，因为无需训练。
- **生成日志**：81 回合 ≈721 次重规划，缓存前缀中位 83.8%，每次重规划中位 18.8 秒（包含服务端生成）。
- **未声明训练算力**：因为 VLCP 本身是训练-免费的；只用了一块消费级以上的 GPU 跑仿真（具体型号未在正文披露）。

## 5. 实验数量与充分性

- **主对比**：57 任务 × 2 条件（闭环 K=50 vs 开环 K=T）= 114 回合。
- **恢复分析**：75 个闭环抓放置回合，用于量算回合内恢复率。
- **成本分析**：81 个闭环回合 ≈721 次重规划。
- **指令改写泛化**：6 个 LIBERO-Object 任务，每任务 10 回合（VLA-0 在原指令上 50 回合，改写后 10 回合）。
- **公平性设计**：K=T 消融共用仿真器、控制 API、特权位姿、任务集、模型与回合预算，差异仅有"回合内是否重规划"——这一对照在变量控制上极为严格。
- **可能不足**：主扫描每个任务只跑 1 回合（因 API 成本），改写任务的 VLA-0/VLCP 仅为 N=10，作者也明确指出该样本量下结论"指示性而非统计定论"，并用 Wilson 置信区间显式呈现不确定性。

## 6. 主要结论与发现

- **十倍成功率的差距**：闭环 VLCP 总体 35.1%（95% CI [24.0, 48.1]），开环 K=T 仅 3.5%（[1.0, 11.9]）；在三个场景族中置信区间均不重叠。
  - Object Picks 60.0% vs 10.0%；Kitchen 33.3% vs 3.3%；Living-Room 23.5% vs 0.0%。
- **可机的回合内恢复**：75 个抓放置回合中 55 个至少一次抓取失败；其中 15 个（27.3%）在后续块中重新接近并成功抓起——这是开环控制器按构造无法实现的转移。
- **开销可控**：中位 84% 输入 token 命中缓存；每回合 ≈10 次紧凑查询；全部生成代码 100% 解析通过。
- **泛化稳定性**：VLA-0 在自然改写指令（"put {object} in the basket" 而非 "pick up {object} and place it in the basket"）下总体从 97.3% 降至 75.0%，`butter` 任务甚至从 96% 直接崩到 0%；VLCP 改动版前后均为 40.0%，未呈现系统性的措辞依赖。
- **跨回合技能库**：每次重规划写出的 `# skills/*.py` 都会持久化到共享磁盘并在下一次提示中按"从新到旧"注入，构成无须训练的"持续学习"基质。

## 7. 优点

- **闭环层级选对**：把闭环打在"控制代码"层级，而不是任务/子任务/动作层级，是本文最关键的贡献；与 K=T 消融的对照让这一变量被严格隔离。
- **训练-免费 + 零演示**：保留了预训练 VLM 的全部编码与推理能力，避免 VLA 微调带来的分布偏离。
- **可机的实证机制**：直接通过日志重算出 27.3% 失败抓取被回合内修复的转移，而非停留在直觉论证。
- **可负担的代价**：83.8% 缓存命中率 + 仅 ≈10 次查询，使"每 $K$ 步重写"在闭源大模型上仍可执行。
- **跨回合技能库**：把"单回合闭环"扩展为"跨回合积累"，与 Voyager 的思路一脉相承但粒度更细。
- **方法学纪律**：全程使用 Wilson 置信区间；K=T 消融/控制基线/上界参考/外部参考四种角色清晰区分，不混淆比较对象。

## 8. 不足与局限

- **仅仿真**：仅在 MuJoCo/RoboVerse 中测试，未触及真实机器人感知噪声与动力学；特权物体位姿来自仿真器，剥离了真实感知误差。
- **固定回合并不能买更多时间**：恢复后留给后续子目标（放置、堆叠等）的预算仍然紧张，这也是从 Object Picks 到 Living-Room 成功率下降的根本原因。
- **延迟过高**：每回合 18.8 秒中位的 frontier-model 推理延迟，使 VLCP 只适合相对慢节奏的操控，不适用于高频反应控制。
- **依赖强闭源模型**：作者明确报告小开模型（如 Qwen3-4B）无法可靠生成控制代码或执行有效重规划——这同时限制了可访问性与部署成本。
- **样本量受限**：主扫描每个任务 1 回合；指令改写实验为 N=10，作者也承认统计力有限；多 seed 评估与方差量化被列为下一步。
- **未研究重规划节奏 $K$ 的调度**：只设默认 $K=50$，未对 K 与开销/性能的 trade-off 做系统扫描（如在接触事件附近自适应加密）。
- **与同期工作可比较性受限**：CaP-Agent0 在不同基准（LIBERO-PRO）上评估，导致只能用已知绝对数作外部参考，无法做严格的同基准对比。
