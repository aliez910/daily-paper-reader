## 摘要
将前沿视觉语言模型转化为机器人策略，通常意味着对其进行微调，使其输出一个在预训练中从未见过的动作表示，这会丢掉该模型本身值得被采用的大部分推理能力。我们反其道而行，保持VLM冻结，让它直接将策略写成一段简短的Python控制函数，无需任何演示数据，无需任何微调。然而，一次性写出代码的方式是开环的。现有闭环方法在错误的层级上做出反应：它们重试一个固定的策略，或挑选不同的子任务，但从不重写那段失败的代码。VLCP在失败真正发生的层级——控制代码上——完成闭环，且全部在单个回合内进行。每隔K步，VLM基于多视角RGB、本体感知状态以及状态变化量重新观察场景，然后根据当前所见重写控制函数，从而在失败累积之前将其捕获。
我们在涵盖57个任务的MuJoCo/RoboVerse评测集上进行了验证。该无需训练的策略达到了35.1%的汇总成功率，而相同的系统若每回合仅查询一次，成功率仅为3.5%。这一十倍的差距在所有场景类别中均具有互不重叠的置信区间。这一增益可追溯至27.3%的回合内失败抓取恢复率：开环控制器会将失误一路带到回合结束的失败，在下一轮重规划时被重新观察并修复。闭环过程的代价同样可控：输入token的中位缓存命中率达到84%，单个回合仅需约10次紧凑查询，且任何一次重规划中写入的控制块都会持久化到一个跨回合共享的技能库，供后续提示词复用。

## Abstract
Turning a frontier vision-language model into a robot policy usually means fine-tuning it to emit an action representation it never saw in pretraining, which throws away much of the reasoning that made the model worth reaching for. We go the other way and keep the VLM frozen. It writes the policy as a short Python control function, with no demonstrations and no fine-tuning. Writing that code once is open-loop, though. Existing closed-loop methods react at the wrong level: they retry a fixed policy or pick a different subtask, but never rewrite the code that failed. VLCP closes the loop where the failure actually lives, on the control code, within a single episode. Every $K$ steps the VLM re-observes the scene from multi-view RGB, proprioceptive state, and a state delta, then rewrites the control function from what it just saw, so a failure is caught before it compounds.   We evaluate on a 57-task MuJoCo/RoboVerse sweep. This training-free policy reaches $35.1\%$ pooled success, against $3.5\%$ for the identical system queried once per episode. That tenfold gap holds with non-overlapping confidence intervals in every scene family. The gain traces to a $27.3\%$ within-episode recovery rate on failed grasps: a miss an open-loop controller would carry to the end of the episode gets re-observed and fixed at the next replan. And the loop stays cheap. A median $84\%$ of input tokens hit cache, an episode needs only about $10$ compact queries, and control blocks written during any replan persist to a cross-episode skill library reused in later prompts.

# VLCP 论文总结

## 1. 核心问题与研究动机

- **主流方法的代价**：当前将多模态大模型用于机器人的主流做法是 VLA（Vision-Language-Action），需要在大规模演示数据上微调 VLM，使其输出预训练中从未见过的动作表示。这一适配过程会"拖拽"模型偏离其预训练分布，损失大量原有推理能力——VLA-0 已表明，将动作表示为纯文本而非专用 token 可显著提升策略强度，说明"动作表示越接近预训练分布，模型能力保留越多"。
- **代码是更"原生"的动作表示**：现代 VLM 最擅长的是代码生成。Code-as-Policies 已证明让模型直接写控制程序是可行的，但**一次性写出代码后开始执行是开环的**，一旦抓取失败、策略逻辑有误，错误将静默贯穿整个回合无法恢复。
- **现有闭环方法在错误层级反应**：现有闭环方法仅在任务级或语言级做反应（重试同一策略、调用监控代码、切换子任务），而**不修改真正失败的"工件"——控制代码本身**。如 Code-as-Monitor、DoReMi、Inner Monologue 仅能重试或切换子任务；Act-Observe-Rewrite 虽重写控制器，但只在回合之间进行，无法在回合内中断并修复失败。
- **核心缺口**：缺少一种方法能在**单个回合内**，在**控制代码**层面实现闭环重规划。

## 2. 方法论

### 核心思想
- **冻结 VLM + 代码即策略**：不微调 VLM，让其直接写出短小的 Python 控制函数 `control(obs, J) -> actions`，其中 `J` 为解析雅可比矩阵，提供速度级 IK 原语。控制函数在 block 内每步接收新鲜的观测和雅可比，**块内逻辑固定**；每隔 K=50 步，VLM 重新查询并基于所见重写函数本身。
- **双层闭环**：
  - **块内闭环（观测级）**：编译后的 `control()` 每步获得 `obs` 和 `J`，可对数值状态反应。
  - **块间闭环（代码级）**：每 K 步 VLM 重新观察并重写函数本身——正是这一层使恢复成为可能。
- **失败捕获条件**：观测包括多视角 RGB、本体感知（末端执行器位姿、关节位置）、任务相关物体位姿以及**显式状态变化量 Δstate**，VLM 据此在失败累积前修正逻辑。

### 关键技术细节
- **重规划粒度（K=50）**：500 步回合约分为 10 个块；K 权衡纠错延迟与查询成本，但论文**未做系统 K 值扫描**。
- **提示词结构（三段缓存设计）**：
  - **Block A（静态前缀）**：机器人与环境文档、技能 API 源码、3 个单阶段工作示例。
  - **Block B（学到的技能库）**：按修改时间排序、注入最多 12 个技能模块源码。
  - **Block C（目标锚）**：任务标识与自然语言目标，置于系统提示中以避免历史截断时丢失。
- **用户轮次内容**：上一块起始 RGB（双视角）、生成的代码与 K 个动作字典（提供尝试轨迹）、当前双视角 RGB、JSON 数值观测、请求下一块控制函数。
- **跨回合技能库**：VLM 在重规划时可发出 `# skills/<name>.py` 标记的辅助模块，写入共享磁盘目录；下次重规划时扫描目录并将源码注入 Block B，让后续控制函数可 `import` 此前写好的技能；通过进程级锁支持并发实例。
- **格式契约（强制）**：响应必须是带表头注释的 Python 代码块，恰好一个 `# control` 块（定义 `control(obs, J)`）和零或多个 `# skills/<name>.py` 模块；允许模块级 `_STATE` 字典实现相位记忆。
- **缓存机制**：在最后一个助手轮次设置断点，下一次调用时前缀可命中缓存；静态前缀约 8k token，中位缓存命中率达 84%。

- **任务规模**：**57 任务**，分 3 个场景家族：
  - Object Picks：LIBERO-Object 的 10 个 pick 任务；
  - Kitchen Scenes：LIBERO-90 中的 30 个厨房任务；
  - Living-Room Scenes：LIBERO-90 中的 17 个客厅任务。
- 涵盖关节动作、pick-and-place、干扰消歧、高处/抽屉放置、堆叠、多步序列等。

### 对比方法
- **主对照（受控消融）**：**Open-loop VLCP（K=T）**——同一系统、同一模拟器、同一控制 API、同一特权物体位姿、同一任务集、同 GPT-5.5、同回合预算，仅关闭回合内重规划。该对照等价于 Code-as-Policies/ProgPrompt 范式。
- **上界参考**：VLA-0（在完整 LIBERO 基准上微调），仅在指令重述实验中作为"演示微调上限"使用。
- **外部参考点**：CaP-Agent0（同期训练自由代码智能体，CaP-X 系列），运行于不同基准（LIBERO-PRO），仅引用其报告数字，不做同台对比。

### 模型与回合参数
- 重规划模型：GPT-5.5（专有 API）。
- 回合长度：500 步；K=50；每任务 1 个回合。
- 评估指标：各家族与总体汇总成功率，Wilson 95% 置信区间。

### 指令重述实验
- 选取 6 个 LIBERO-Object 任务，将原始指令"pick up {object} and place it in the basket"改为"put {object} in the basket"，任务和成功条件不变，仅措辞不同。
- VLA-0：原始任务 50 回合/任务，修改任务 10 回合/任务；VLCP：各 10 回合/任务。

## 4. 资源与算力

- **未使用本地 GPU 训练**（系统为训练自由，VLM 冻结且仅通过 API 调用）。
- **推理算力**：使用专有 VLM API（GPT-5.5），论文**未报告 GPU 类型/数量、API 费用等具体算力细节**。

## 5. 实验数量与充分性

### 实验规模
- **主实验**：57 任务 × 1 回合（闭环）+ 57 任务 × 1 回合（开环 K=T）。
- **回合内恢复分析**：75 个闭环 pick-and-place 回合（来自更大日志语料，包含指令重述研究的额外回合）。

- **指令重述实验**：6 任务 × 2 措辞 × {VLCP 10 ep + VLA-0 50/10 ep}。

### 充分性评估
- **优势**：消融设计**非常受控**——K=T 消融与 VLCP 共享模拟器、API、特权位姿、任务集、模型与回合预算，差异仅"是否在回合内重规划"，使 10× 成功率差距可明确归因于闭环机制本身；且恢复率（27.3%）与成功率差距在机制层面闭合。
- **不足**：
  - **每任务仅 1 回合**（因每次回合都触发闭源 VLM API 调用，预算受限），未做多种子重复评估以量化任务方差；

  - **未系统扫描 K**（如 K=20/50/100 等不同重规划粒度）；
  - 不同场景家族样本量不平衡（10/30/17），汇总指标受家族内方差影响；
  - 对 VLA-0 与 CaP-Agent0 仅为外部参考，未做同基准同回合数的严格对照；
  - 恢复分析仅限 pick-and-place 子集，未覆盖其他长时域任务；
  - 仅有单次抓取-放置恢复可视化示例（Figure 4），未给出多任务的恢复轨迹对比。

## 6. 主要结论与发现

- **闭环重规划带来 10× 成功率提升**：在 57 任务上，闭环 VLCP（K=50）达 **35.1%** 汇总成功率，相同系统的开环消融（K=T）仅 **3.5%**；所有场景家族置信区间互不重叠。
  - Object Picks：60.0% vs 10.0%；
  - Kitchen Scenes：33.3% vs 3.3%；
  - Living-Room Scenes：23.5% vs 0.0%。
- **成功率差距可追溯至可测量的机制**：**27.3% 的失败抓取**在后续重规划中被重新接近并提起（75 个 pick-and-place 回合中，55 含失败抓取，15 个被恢复，中位 3 次重规划后恢复）。开环变体因永不重观察，恢复率为 0。
- **闭环廉价可行**：84% 输入 token 命中缓存；中位 10 次紧凑查询/回合；单次重规划中位 18.8 秒；778 个生成控制块 100% 通过解析与编译。
- **指令措辞鲁棒性**：VLCP 在指令重述下汇总成功率不变（40.0% → 40.0%，Δ=0），各任务差异呈双向散布；VLA-0 在原始指令下近天花板（97.3%），重述后降至 75.0%，并在 `butter` 任务上完全崩溃（96% → 0%），提示其部分性能依赖训练阶段见过的具体措辞而非真正任务理解。
- **闭环恢复的代码可读性**：恢复回合中模型诊断性表述失败并修正逻辑（如"上一块在手未降至足够高度前已闭合夹爪……重新居中降低并重新抓取布丁"），验证闭环修正发生在控制代码层而非观测层。

## 7. 优点（亮点）

- **方法学亮点**：
  - **无需训练/示教**：冻结 VLM 直接写控制代码，避免微调造成的分布偏移和推理能力损失；
  - **闭环层级正确**：首次将闭环放在"控制代码本身"这一粒度上，而非任务级或子任务级；
  - **雅可比即原语**：将速度级 IK 抽象为可直接调用的 API，让 VLM 专注于高层逻辑；
  - **跨回合技能库**：受 Voyager 启发的累积式技能复用机制，使技能自然生长，无需重训；
  - **三段缓存提示设计**：显著降低每次重规划的 token 成本与延迟。
- **实验学亮点**：
  - **强受控消融**：K=T 消融与 VLCP 在所有无关变量上同构，使增益归因于"闭环"这一唯一变量；
  - **机制可量化**：直接从日志重构抓取高度与夹爪状态定义失败抓取与恢复，给出 27.3% 这一具体数字而非仅给最终成功率；
  - **代码示例透明**：附录给出提示格式契约、工作示例及一个未编辑的生成技能模块，便于复现；
  - **与 VLA-0 的指令重述对比**提供了关于 VLA 泛化鲁棒性的反直觉证据。

## 8. 不足与局限

- **感知前提依赖强**：使用模拟器提供的特权物体位姿初始化首次抓取，仅在仿真中验证；真实机器人感知噪声、动力学延迟未测试。
- **强模型依赖**：方法依赖前沿闭源 VLM（GPT-5.5），开源小模型（Qwen3-4B）无法可靠生成代码或有效重规划——既限制可达性也提高部署成本。
- **延迟与控制频率受限**：单次重规划中位 18.8 秒，方法适合相对慢速的操作任务，不适合高频反应式控制；K 也未做系统扫描，更短 K 会增加成本但更短纠错延迟，更长 K 反之。
- **评估预算受限**：每任务仅 1 回合、无多种子重复，导致任务方差未量化；指令重述实验每单元仅 10 回合，被作者明确标注为"指示性"。
- **回合预算固定**：恢复可挽救首次失败，但无法购买更多时间——长时域任务即使成功恢复抓取，留给后续放置子目标的时间仍受限，是 Living-Room 成功率明显低于 Object Picks 的原因之一。
- **缺乏更广泛对照**：未与更多近期方法（如 CaP-Agent0 同基准、更多训练自由代码智能体、VLM-Planner 等）在统一协议下做严格比较。
- **可能的偏差**：
  - 主对照为同系统消融，外部泛化性仍需在更异构基准上验证；
  - 27.3% 恢复率仅在 pick-and-place 回合中统计，可能不能推广到其他任务家族；
  - 提示工程、API 设计、示例选择等大量细节可能对结果敏感，但论文未做提示敏感性分析。
