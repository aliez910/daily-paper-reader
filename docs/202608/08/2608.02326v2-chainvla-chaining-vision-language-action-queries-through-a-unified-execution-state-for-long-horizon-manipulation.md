## 摘要
人类在执行长时序操作时，会保留对先前动作所建立成果的记忆，同时持续调整进行中的运动。与此相反，基于动作分块的视觉-语言-动作（VLA）策略在每次查询时都从当前输入重新规划。现有方法要么通过记忆保留长期任务证据，要么通过动作重用与集成保留短期运动，但都未能完整实现跨查询的衔接。我们提出了 ChainVLA，一种具有 1.2B 参数的 VLA 策略，它通过一个联合且可修正的执行状态将连续的查询链式连接起来。进度上下文（Progress Context）将循环式工作状态与稀疏事件记忆相结合，以承载由观测推导出的任务进度；而运动尾部（Motion Tail）则将前一次预测中尚未执行的后续部分输入到状态构建与动作生成中。两者共同作为条件输入一个解码器，使其在最新观测下重新生成每个动作时域，从而让所携带的状态能够引导下一次预测，而无需将其固化。在 RMBench 上，ChainVLA 达到了 62.8% 的平均成功率，并在四个 LIBERO 套件上达到了 98.8% 的成功率；而移除运动尾部或进度上下文后，RMBench 的成功率分别下降至 11.2% 和 3.0%。这种非对称的消融结果与以下观点一致：运动连续性有助于维持观测流的稳定性，而任务进度正是从该观测流中推断出来的。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 1. 核心问题与研究动机

- **核心问题**：长时序（long-horizon）操控任务中，决策既依赖于"先前动作已建立的子任务成果"（任务进度），也依赖于"正在执行运动的连续调整"（运动延续性）。但现有的动作分块（action-chunked）VLA 策略在每次查询（query）时都仅从当前观测、自身感知状态与指令重新规划出一个有限动作时域（horizon），并执行其前缀（prefix）后再次重规划，导致**跨查询衔接不完整**。
- **缺失的两个衔接维度**：
  - **任务级**：早期任务证据可能已不在当前视野中可恢复（如 RMBench 的 Put Back Block 任务中，已放回的目标位置 pad 在当前视角已不可识别，但同一观测与指令可能对应不同历史，需要不同决策）。
  - **运动级**：重规划会丢弃前一次预测中未执行的后续动作（unexecuted continuation），新预测前缀与被替换的运动之间可能出现不连续；运动的不连续又会改变后续观测流，反过来破坏用于推断任务进度的信息。
- **现有方法的不足**：
  - 记忆增强型方法（如 MemoryVLA、Mem-0 等）保留长期任务证据，但不携带前次预测的未执行后续。
  - 动作集成/实时执行型方法（如 Temporal Ensemble、Real-Time Execution、Native Continuation）保留短期运动一致性，但无法承载早期任务证据。
- **中心问题**：如何让 VLA 策略在跨查询时同时链式传递任务进度与运动延续性，同时让每次新预测都对最新观测保持响应。

## 2. 方法论

### 2.1 核心思想
- 提出 **ChainVLA**（1.2B 参数）：一种将连续查询通过**统一且可修正的执行状态（execution state）**链式连接的 VLA 策略。
- 执行状态由两部分组成：
  - **Progress Context**（进度上下文 $g_k$）：承载由观测推导出的任务进度。
  - **Motion Tail**（运动尾部 $u_k$）：承载前一次预测的未执行后缀。
- 每次查询进行"读—更新—写"的状态转换，解码器在最新观测下**重新生成整个动作时域**，使携带的状态作为"可修正的先验（revisable prior）"而非固化计划。

### 2.2 关键技术细节

**a) 执行状态的递归维护**
- 查询转换公式（公式 3）：
  - $(A_k, W_k, C_{k+1}) = F_\theta(x_k, D_k, W_{k-1}, C_k, u_k)$
  - $u_{k+1} = \mathrm{Tail}(A_k)$
- 其中 $D_k$ 为已执行动作历史，$W_{k-1}$ 为循环工作状态，$C_k$ 为稀疏事件记忆。

**b) Progress Context（任务进度承载）**
- **循环 Working State（$W_k$）**：
  - 由 8 个学习的工作查询（working queries）对当前多模态 token 进行交叉注意力更新（公式 4），并维护一个 3 槽 FIFO 缓存（最新 24 个 live token + 当前 8 个）。
  - 条件向量 $\eta_k$ 由本体感知、已执行动作池化、尾部动作池化、查询时间编码共同构成。
- **Sparse Event Memory（稀疏事件记忆）**：
  - 容量 16，每个记录包含 64 视觉 + 8 阶段信息 + 8 时间 token，加检索键与写入查询索引。
  - 写入规则：阶段标注数据由阶段转换触发（rollout 时置信度阈值 0.55）；无标注数据采用固定三查询周期写入。
  - 检索基于 32 个年龄桶的年龄感知余弦相似度（公式 5），返回锚点事件 + 最高分两个非锚点事件。
  - 通过交叉注意力融合为 $Z_k^e$，再与 live token $L_k$ 融合形成策略侧的 Progress Context。

**c) Motion Tail（运动延续性承载）**
- 双重模型侧路径：
  - **Tail tokens**：通过归一化与学习投影将尾部编码为 token 参与 Working State 构建。
  - **轨迹初始化**（公式 6）：以尾部对齐的全时域表示作为条件流解码器的初始均值，加性高斯噪声形成 $eA_{k+1}^{(0)} \mid u_{k+1} \sim \mathcal{N}(\mu_{k+1}, \sigma_u^2 I)$。
- 解码器在最新观测、Progress Context 与 tail tokens 条件下**重新生成每个时域位置**（无任何位置被冻结或复制）。
- 执行端：解码后将重叠步骤与来尾部做线性混合（执行侧衔接，独立于模型侧两个路径）。
- 首查询时尾部路径被掩码。

**d) 训练**
- 按 episode 中查询顺序展开，与 rollout 使用相同的转换。
- 训练时携带的后缀需 detach；尾部路径以 0.5 概率使用。
- 损失：标准条件流动作目标 + 阶段监督（有标注时）+ **重叠一致性正则项**（权重 0.2，用于鼓励跨边界一致性而非固定动作）。
- 该正则项与部署时作为诊断的三步重叠 RMSE（$RMSE_3$）不同。

### 2.3 算法流程（Rollout 一次 Episode）
1. 初始化 $W_{-1}, C_0, D_0, u_0$ 为空。
2. 观测 $x_k=(o_k, r_k, \ell)$ 并编码为 $X_k$。
3. 更新 Working State：$W_k, \bar{W}_k \leftarrow \mathrm{UpdateWorking}(X_k, W_{k-1}, D_k, u_k)$。
4. 阶段摘要 $\bar{s}_k \leftarrow \mathrm{StageSummary}(\bar{W}_k)$。
5. 事件检索 $Z_k^e \leftarrow \mathrm{Retrieve}(C_k, \bar{W}_k, \bar{s}_k, \tau_k)$。
6. 融合 Progress Context $g_k \leftarrow \mathrm{Fuse}(L_k, Z_k^e)$。
7. 采样动作 $A_k \sim \Pi_\theta(\cdot \mid x_k, g_k, u_k)$。
8. 重叠混合 $A_k \leftarrow \mathrm{BlendOverlap}(A_k, u_k)$。
9. 执行前缀 $(a_{k,1}, \ldots, a_{k,h_{exec}})$；追加到 $D_{k+1}$；按规则可能写入事件；携带 $u_{k+1}=\mathrm{Tail}(A_k)$ 进入下一轮。

## 3. 实验设计

### 3.1 数据集与 Benchmark
- **RMBench**：5 个任务，专注于**记忆依赖型操控**（初始状态回忆、目标与顺序记忆、回位记忆、早期阶段决策）。每个任务 100 rollout episodes，作为主要诊断场景。
- **LIBERO**：四个套件（Spatial、Object、Goal、Long），每个套件 10 个任务、每任务 50 episodes，作为广度检查。

### 3.2 对比方法
- **RMBench 对比**：DP、ACT、π0.5、X-VLA、MemER、MemoryVLA、Mem-0、MemoAct、PAM、Goal2Skill 等。
- **LIBERO 对比**：OpenVLA、SpatialVLA、π0-FAST、GR00T-N1、π0、π0.5+KI、PAM、MemoryVLA、CronusVLA、X-VLA 等。

### 3.3 评估指标
- **主要指标**：任务成功率（RMBench 每任务 100 episodes，LIBERO 每任务 50 episodes）。
- **辅助边界诊断**（lower is better）：
  - $CD_p$：重规划时的位置命令间隙（mm）。
  - $CD_R$：姿态命令间隙（度，SO(3) 测地角）。
  - $B_2$：跨边界的命令速度二阶差分（mm）。
  - $RMSE_3$：前次未执行后缀与新计划的三步对齐 RMSE（mm）。
- 配对 rollout：Put Back Block（20 对）、Rearrange Blocks（30 对）、Swap Blocks（30 对），按数量加权池化。

## 6. 主要结论与发现

- **任务性能**：
  - RMBench 平均成功率 **62.8%**（1.2B 参数），高于 5 任务覆盖方法中最佳基线 Mem-0（52.8%，8B+2B），并在每个任务上为最佳或次佳。
  - LIBERO 四套件平均 **98.8%**，每个套件均 >98%（Long 套件 98.2%）。
- **非对称消融**（RMBench）：
  - 去除 Motion Tail：62.8% → **11.2%**。
  - 去除 Progress Context：62.8% → **3.0%**。
  - 同时去除两者：1.6%。
  - 部分去除（如去掉 Live Tokens 47.2%、去掉 Event Readout 32.2%、去掉 Tail Tokens 52.0%、去掉 Traj. Init. 38.0%）虽下降明显但仍远高于去完整组件。
- **关键发现**：两个组件并非"独立可叠加的提升"，去除其中之一后另一方也无法弥补；非对称性提示**运动连续性保护了任务进度所依赖的观测流**。
- **边界诊断**：Full 在 80 对配对 rollout 上 4 项边界指标均低于 w/o Motion Tail，池化降幅 56.6% / 40.4% / 57.4% / 43.1%。
- **后解码控制的反例**：Linear Continuation 与 Temporal Ensemble 的边界值甚至更低（更平滑），但成功率仅 0–3.7%，说明**仅在已解码命令上做平滑不足以替代在生成时即以前次后缀为条件**；边界指标是诊断而非目标。

## 7. 优点

- **概念清晰**：将跨查询状态明确拆分为"回顾性 Progress Context + 前瞻性 Motion Tail"，并与人类执行/部分可观察控制理论对接。
- **可修正而非固定**：每次查询在最新观测下重新生成整个动作时域，所携带状态作为可修正先验，避免将记忆/后缀固化为死命令。
- **完整机制统一**：动作生成、循环状态、稀疏记忆、阶段摘要、检索与写入在同一 DiT 解码器与查询转换内协同，而非外挂子模块。
- **匹配式消融充分**：两侧组件、各自子路径（Live Tokens/Event Readout、Trajectory Init./Tail Tokens）以及替代方案（FIFO 历史+TE）均有受控对照，论证严密。
- **配对边界诊断**：在匹配场景下对比 Full 与 w/o Motion Tail，避免场景差异带来的混淆。
- **关键反例**：通过 Linear Continuation / Temporal Ensemble 显式反驳"平滑=成功"的直觉。
