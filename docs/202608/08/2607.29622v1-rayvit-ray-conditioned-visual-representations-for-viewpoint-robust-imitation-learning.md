## 摘要
视觉模仿学习使机器人能够直接从图像中获取视觉运动技能，然而 RGB 观测缺乏显式的几何线索，导致所学策略对相机扰动较为脆弱。为解决这一问题，我们提出了射线条件视觉 Transformer 编码器（RayViT），这是一种轻量级架构，可将相机几何信息注入预训练的 ViT 主干网络中。RayViT 将相机几何表示为 Plücker 射线图，将其分块为射线特征，并利用门控交叉注意力生成射线条件类别标记。这些射线特征作为密集位置嵌入进行添加，而射线类别标记则替换原始的 ViT 类别标记，以提供几何感知的汇总表征。我们将该方法与辅助余弦相似度损失相结合，以持续提升几何感知标记的性能与鲁棒性。在仿真和真实机器人任务上的实验表明，RayViT 在多任务 RoboCasa 基准的相机扰动下将鲁棒性提升了约 13 个百分点，并在真实世界多任务成功率上相较基线平均多完成 1.78 个阶段。

## Abstract
Visual imitation learning enables robots to acquire visuomotor skills directly from images, yet RGB observations lack explicit geometric cues, making learned policies brittle to camera perturbations. To address this, we propose \textbf{Ray-conditioned Vision Transformer Encoder (RayViT)}, a lightweight architecture that injects camera geometry into pretrained ViT backbones. RayViT represents camera geometry as a Plücker ray map, patchifies it into ray features, and uses gated cross-attention to produce a ray-conditioned class token. These ray features are added as dense positional embeddings, while the ray class token replaces the original ViT class token to provide a geometry-aware summary representation. We combine this approach with an auxiliary cosine similarity loss to consistently improve the performance and robustness for geometry-aware tokens. Experiments on sim- and real-robot tasks demonstrate that RayViT improves robustness by approximately 13 percentage points under camera perturbations in multi-task RoboCasa benchmark and by 1.78 average completed stages in real-world multi-task success rate compared to baselines.

# RayViT 论文详细总结

## 1. 核心问题与研究动机

视觉模仿学习（Visual Imitation Learning）使机器人能够直接从 RGB 图像中获取视觉运动技能。然而，RGB 观测本身缺乏显式的几何线索，仅编码场景外观（appearance），而对相机与世界坐标系之间的几何关系保持"不可知"。这导致基于预训练视觉基础模型（如 DINOv3）所构建的策略倾向于学习**视角特定**的外观到动作的映射，而非视角不变的任务表征，因而对相机扰动（移动、抖动、视点变化）非常脆弱。

现有方法存在两大局限：
- **数据多样性方法**：依赖多视角/多相机采集的演示数据进行增强（如 CamPose），成本高昂、难以扩展到真实环境。
- **显式 3D 表示方法**：依赖点云、点图、深度等 3D 表示（如 RVT 系列、Adapt3R、PMP），存在密度、噪声、尺度统一难，且与纯图像预训练视觉模型兼容性差的问题。

本文的核心动机是：**在不增加传感器、不依赖多视角数据增强的前提下，将相机几何信息以一种轻量化、与预训练 ViT 兼容的方式注入视觉表征**，从而提升视觉模仿学习策略在相机扰动下的鲁棒性。

## 2. 方法论

### 2.1 核心思想

RayViT 的核心思想是利用 **Plücker 射线图（Plücker Ray Map）** 编码相机几何，并以两种互补方式注入预训练 ViT 主干网络：
1. **射线条件类别标记**（Ray-conditioned Class Token）：通过门控交叉注意力生成几何感知的全局摘要 token。
2. **射线位置嵌入**（Ray Positional Embedding）：将分块射线特征以加法形式叠加到 patch token 上，提供密集的 3D 几何锚点。

同时引入**跨视角一致性损失**（Cross-view Cosine Similarity Loss）作为辅助正则化，进一步提升视角鲁棒性。

### 2.2 关键技术细节

**（1）Plücker 射线图构建**

给定相机内参矩阵 $K \in \mathbb{R}^{3\times3}$ 和外参 $(R,t)$，对于像素 $\mathbf{p}=(u,v,1)^\top$：
- 世界系下的相机中心：$\mathbf{o}_w = -R^\top \mathbf{t}$
- 归一化后的射线方向：$\mathbf{d}_w(u,v) = \frac{R^\top K^{-1}\mathbf{p}}{\|R^\top K^{-1}\mathbf{p}\|_2}$
- Plücker 矩：$\mathbf{m}_w(u,v) = \mathbf{o}_w \times \mathbf{d}_w(u,v)$
- 射线编码：$\mathbf{r}(u,v) = [\mathbf{d}_w(u,v), \mathbf{m}_w(u,v)] \in \mathbb{R}^6$

将所有像素的射线堆叠，得到与 RGB 图像空间对齐的 6 通道射线图。

**（2）Patch-aligned 射线特征**

将射线图通过**平均池化**下采样到 ViT 的 patch 分辨率（池化核大小等于 patch 尺寸），保持几何语义，再用两层 MLP + GELU 投影到 ViT 隐空间维度。

**（3）门控交叉注意力模块（Gated Cross-attention Module）**

由两个轻量化的门控交叉注意力块构成（与 ViT 隐藏维度匹配）。一个可学习的 query token 对 patch-aligned 射线特征做交叉注意力，逐步将相机几何汇总为单个 token。参照 Qwen 的设计，在注意力后应用可学习的逐元素 sigmoid 门控，控制几何条件的强度，避免对预训练表征造成过强干扰。最终的 query token 替换原始 ViT 的 [CLS] token。

**（4）射线位置嵌入（与 RoPE 并存的加性注入）**

在 ViT 输入阶段，将 patch-aligned 射线特征**加性叠加**到图像 patch token 上。原始的 RoPE（Rotary Position Embedding）保持不变——因为 RoPE 仅支持图像平面内的局部空间推理，无法捕获视角相关的 3D 结构；射线嵌入填补了这一空白，同时不破坏预训练注意力动态。

**（5）跨视角一致性损失**

为鼓励视角鲁棒的表征，对中间层（默认第 10 层）的几何条件类别 token 施加余弦相似度损失。以**手爪相机视图**（最接近操作目标、背景干扰少）为锚点 $g$：

$$\mathcal{L}_{\cos} = 1 - \frac{1}{N-1}\sum_{v \in \mathcal{V}} \cos(c_v, c_g), \quad \mathcal{L} = \mathcal{L}_{IL} + \lambda \mathcal{L}_{\cos}$$

其中 $\lambda=0.01$ 为默认权重。该损失仅作为辅助正则项，叠加在主策略学习损失上。

## 3. 实验设计

### 3.1 数据集与场景

**仿真基准**：RoboCasa（大规模厨房环境机器人操作基准），覆盖 16 个多样化操作任务，包含拾放（PnP）、开合抽屉、开关炉灶/水龙头/微波炉、咖啡制作等多步长程任务。

**真实机器人任务**（Franka Panda 7-DOF，8 维动作空间）：
- **Cup Stack**：3 个不同颜色/大小的杯子按尺寸堆叠
- **Pick Place**：将梨和海绵放入木托盘
- **Drawer**：开抽屉→放绿色棱柱→关抽屉
- **Insertion**：将蓝色圆柱插入立方体盒子上的圆形孔

真实场景使用 3 个相机（左、右、手爪），变体环境将右侧默认相机替换为位姿差异显著的相机。数据规模：每个真实任务 50 条演示（Insertion 为 100 条）。

### 3.2 Benchmark 设置

- 策略框架：基于分数的扩散策略（Score-based Diffusion Policy）+ decoder-only xLSTM 动作头（8 个 x-Block，8 个注意力头，嵌入维度 768，动作块大小 10）
- 视觉编码器：DINOv3 ViT-Small（主），辅以 EUPE 验证泛化性
- 训练：仿真 50 epoch（单 A100，3 随机种子），分别在第 30、40、50 epoch 评估取最优
- 评估协议：每个任务 50 次仿真回合；真实任务每个模型 20 次 rollout
- 相机扰动协议：两个静态相机在有界方位角、高低角、距离范围内随机扰动

### 3.3 对比基线

- **Adapt3R**：结合预训练 2D 语义特征与 3D 几何（局部化语义而非完整场景）
- **PMP-xyz / PMP**：显式 3D 点图表示（PMP 进一步拼接 2D 语义 token）
- **CamPose**：使用 Plücker 射线图但仅作为附加输入模态，晚期融合语义 token
- **RGB-only（本文消融基线）**：纯图像 DINOv3，无射线条件

### 3.4 自身变体

- **RayViT-cls**：仅通过射线条件类别 token 注入几何
- **RayViT**：进一步加入 patch-aligned 射线位置嵌入

## 6. 主要结论与发现

1. **相机几何注入显著提升鲁棒性**：在 RoboCasa 多任务基准上，RayViT-cls 将扰动下的平均成功率从 RGB 基线的 24.0% 提升到 37.0%（+13 个百分点），性能下降幅度从 18.5 个百分点降至 6.2 个百分点。
2. **完整 RayViT 进一步提升扰动鲁棒性**：性能下降幅度仅为 2.5 个百分点，但默认性能略低于 RayViT-cls（39.8% vs 43.2%），存在轻微权衡。
3. **跨视角一致性损失是关键**：仅在几何感知的 token 上施加余弦损失才能稳定带来性能与鲁棒性双重提升；纯 RGB baseline 上施加该损失无效，说明**几何感知是该辅助目标的前提**。
4. **深度层施加辅助损失效果最佳**：在 ViT 第 10 层附近施加效果优于浅层。
5. **优势不依赖预训练**：从零训练（scratch）时，RayViT 仍优于 RGB（29.2% vs 10.0% 的扰动成功率），表明几何条件化的价值不完全依赖预训练分布。
6. **跨主干迁移性良好**：在 EUPE 上同样有效。
7. **真实机器人验证有效**：平均完成阶段数从 RGB 的 0.91 提升到 2.69，提升 1.78 个阶段；真实场景下 RayViT 优于 RayViT-cls，作者解释为真实图像分辨率更高、patch 序列更长，丰富几何条件更有效。

## 7. 方法与实验设计的亮点

1. **轻量化设计**：射线注入模块仅 ~4M 参数，远小于 DINOv3 ViT-Small 的 21.6M，几乎不增加推理开销。
2. **与预训练 ViT 兼容**：门控交叉注意力 + 加性 RoPE-并存注入，避免破坏预训练表征分布。
3. **无需额外传感器或多视角增强**：仅依赖相机内参和已有外参标定，降低部署门槛。
4. **Plücker 射线图的天然空间对齐**：与 RGB 图像像素级对应，避免点云重建或深度估计。
5. **几何条件作为辅助正则的前提**：揭示了一个有价值的发现——视图一致性目标的有效性以表征本身的几何感知为前提，这对表征学习设计具有方法论意义。
6. **扰动评估协议严谨**：不仅报告平均成功率，还报告"性能下降幅度"作为鲁棒性的直接度量。

## 8. 不足与局限

1. **仅适用于 ViT 主干**：未探索卷积类视觉编码器（如 ResNet、ConvNeXt）的几何条件化，限制了方法的适用范围。
2. **依赖任务相关锚点视图**：跨视角一致性损失需要选择一个任务相关的锚点相机（本文选用手爪相机），这一选择可能不适用于所有任务设置。
3. **依赖相机外参标定**：虽然内参通常易获取，但外参标定在实际部署中仍是额外步骤，可能影响便利性。
4. **真实实验规模有限**：仅 4 个真实任务，无多种子方差报告，无法对真实场景鲁棒性做严格统计推断。
5. **未探索单目或稀疏视角设置**：方法在多视角（≥3 相机）下设计，未验证在更稀疏视角下的表现。
6. **未在大规模异构数据集上预训练几何感知编码器**：作者指出，从零预训练几何条件视觉编码器是一个有前景的未来方向，目前仍是后注入式。
7. **潜在偏差风险**：所有真实任务都使用同一套左/右/手爪相机硬件，跨硬件平台泛化性未验证。
8. **任务复杂度局限**：仿真集中在厨房操作任务，未涉及移动机器人、户外场景等更具挑战性的设置。
