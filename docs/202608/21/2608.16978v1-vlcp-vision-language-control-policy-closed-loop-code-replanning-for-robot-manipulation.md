## 摘要
将前沿的视觉-语言模型改造为机器人策略，通常需要对其进行微调以输出其在预训练中从未见过的动作表征，这会丢掉使该模型值得选用的大量推理能力。我们反其道而行，保持 VLM 冻结不变。它以一段简短的 Python 控制函数形式来编写策略，无需任何示范，也无需微调。然而，一次性编写代码属于开环控制。现有闭环方法在错误的层级上做出反应：它们要么重试某个固定策略，要么选择不同的子任务，却从不重写那段失败的代码。VLCP 将闭环构建在失败真正发生之处——控制代码上，并将其置于单回合之内。每隔 K 步，VLM 依据多视角 RGB 图像、本体感知状态以及状态变化量重新观察场景，然后基于其刚刚所见重写控制函数，从而在失误累积之前将其捕获。

我们在涵盖 57 项任务的 MuJoCo/RoboVerse 基准套件上进行了评估。这种免训练策略的合并成功率达到 35.1%，而相同系统每回合仅查询一次的合并成功率仅为 3.5%。在每一类场景中，这一十倍的差距在非重叠的置信区间下均成立。该增益可追溯至失败抓取 27.3% 的回合内恢复率：开环控制器会将其一路带到回合终点的失误，在下一次重规划时被重新观察并予以修复。并且该闭环依然轻量：输入令牌的中位数缓存命中率达 84%，每个回合仅需约 10 次精简查询，而任意一次重规划中写入的控制模块会持久化保存至一个跨回合技能库，供后续提示词复用。

## Abstract
Turning a frontier vision-language model into a robot policy usually means fine-tuning it to emit an action representation it never saw in pretraining, which throws away much of the reasoning that made the model worth reaching for. We go the other way and keep the VLM frozen. It writes the policy as a short Python control function, with no demonstrations and no fine-tuning. Writing that code once is open-loop, though. Existing closed-loop methods react at the wrong level: they retry a fixed policy or pick a different subtask, but never rewrite the code that failed. VLCP closes the loop where the failure actually lives, on the control code, within a single episode. Every $K$ steps the VLM re-observes the scene from multi-view RGB, proprioceptive state, and a state delta, then rewrites the control function from what it just saw, so a failure is caught before it compounds.   We evaluate on a 57-task MuJoCo/RoboVerse sweep. This training-free policy reaches $35.1\%$ pooled success, against $3.5\%$ for the identical system queried once per episode. That tenfold gap holds with non-overlapping confidence intervals in every scene family. The gain traces to a $27.3\%$ within-episode recovery rate on failed grasps: a miss an open-loop controller would carry to the end of the episode gets re-observed and fixed at the next replan. And the loop stays cheap. A median $84\%$ of input tokens hit cache, an episode needs only about $10$ compact queries, and control blocks written during any replan persist to a cross-episode skill library reused in later prompts.

# VLCP 论文总结：面向机器人操作的视觉-语言控制策略闭环代码重规划

## 1. 核心问题与研究动机

### 1.1 背景：现有 VLA 范式的代价
- 当前将前沿视觉-语言模型（VLM）改造为机器人策略的主流做法是**视觉-语言-动作模型（VLA）**：在大量示范数据上对预训练 VLM 进行微调，使其输出预训练阶段从未见过的低层动作表征。
- 这种微调使模型脱离其原本擅长的分布，**削弱甚至丢失了原本使其具备价值的推理与代码能力**。VLA-0 等工作已用经验数据说明了这种分布漂移带来的代价。
- 一个核心洞察：当代前沿大模型最擅长的表征是**代码**，而**非特殊动作 token**。若能让模型以代码作为策略形式（Code-as-Policy），则可保留其全部预训练能力并免去微调。

### 1.2 现有闭环方法的"错位"
- **代码生成类方法**（Code-as-Policies、ProgPrompt、ELLMER、Robotic Programmer）：策略代码执行后无法再查询，一旦失败便不可恢复。
- **监控重规划类方法**（Code-as-Monitor、DoReMi、Inner Monologue）：仅能重试固定策略或回退至高层规划器，**不能改写失败的控制代码**。
- **VLA 方法**（π0、OpenVLA、VLA-0）：反应式输出动作 token，缺乏可被检视/重写的中间表征，且依赖大量示范数据。
- **Act-Observe-Rewrite**：将完整控制器作为改写单元，但**在 trial 之间**重写，episode 内仍运行同一控制器。
- **核心空缺**：没有方法能在**单个 episode 内**对**控制代码本身**进行闭环重写。

### 1.3 论文主张
> 失败发生在控制代码中，闭环也应建在控制代码上，且应建在 episode 内。

## 2. 方法论

### 2.1 核心思想
- **冻结 VLM**（不微调），让它把策略写成一个简短的 Python 控制函数 `control(obs, J) → actions`，每步读取多视角 RGB、本体感知状态与状态变化量。
- 整个 episode 被切成长度为 **K=50 步的 block**。每个 block 起始时调用一次 VLM，生成新的 `control` 函数；该函数以开环方式运行整个 block。
- **block 内**：同一编译后的函数每步获得新鲜观测 `obs` 与雅可比矩阵 `J`（解析计算的速度 IK 原语），对数值状态闭环。
- **block 间（核心闭环）**：VLM 在每个 block 边界重新观测场景，从多视角 RGB、数值状态、上一个 block 的代码与执行轨迹出发**重写控制函数本身**，从而在执行过程中捕获并修复失败。

### 2.2 关键技术细节
- **观测与 IK 原语**：
  - 多视角 RGB（两台固定相机）+ 末端执行器位姿、关节位置 + 任务相关物体的**特权位姿**（来自仿真器）。
  - 雅可比 `J ∈ R^{3×7}` 与观测一同传入，由生成的代码直接调用 `move_to_target` 等速度 IK 原语。
- **特权位姿的角色**：仅用于种子化首次接触，**故意把定位问题排除**，以隔离闭环纠错这一研究问题；视觉是真正驱动闭环修正的通道。
- **状态变化量（state delta）**：prompt 中显式提供上一步到当前步的状态增量，便于模型识别变化。
- **重规划节奏 K**：K 太小→查询成本高；K 太大→失败 block 跑太久。设 K=50，使 500 步 episode 划分约 10 次重规划。
- **提示结构（最大化缓存复用）**：
  - **Block A（静态前缀）**：机器人/环境文档、技能 API 源码、3 个单阶段控制示例，约 8k tokens。
  - **Block B（学习的技能库）**：磁盘上所有持久化 helper 模块源码，按修改时间倒序，最多 12 条。
  - **Block C（目标钉）**：任务标识与自然语言目标，置于系统提示而非对话历史，避免被截断。
  - **用户回合**：上一个 block 起始的多视角 RGB、生成代码与 K 个动作字典（轨迹）+ 当前同步 RGB + 数值状态 JSON + 下一 K 步控制函数的指令；图像仅在实时回合中，历史回合剥离图像。
- **对话历史与截断**：保留至多 H=20 对历史，超出从最早丢弃；缓存断点设在最后一个助手回合，使下一次调用前缀命中缓存。
- **输出格式契约**：响应必须仅包含带 header 的 python fenced 块——`# control` 恰好一个（定义 `control(obs, J) -> list[dict]`），`# skills/<snake_name>.py` 零或多个可复用模块。
- **跨 episode 技能库**：每次重规划中模型可输出带标签的 helper 模块，原子写入共享磁盘目录 `control_policies/skills/`，若 import 失败则回滚并在下一次重规划中把错误回传给 VLM。技能文件跨 episode 持久，并发实例用进程级锁协调。每次重规划时重建 Block B（按 mtime 排序、注入至多 12 条）。
- **代码有效性**：所有 778 个生成的控制块全部成功解析与编译（100%）。

### 2.3 算法流程（文字描述）
1. 接收 episode 起始观测（含多视角 RGB、状态、目标）。
2. 用 Block A+B+C 装配系统提示，向 VLM 查询第一个 `control(obs, J)` 函数。
3. 编译该函数，运行 K=50 步；每步传入新鲜 `obs`、`J`，由 PD 控制器消费动作字典。
4. block 结束后打包：上一 block 起始 RGB + 代码 + 动作轨迹 + 当前 RGB + 数值状态 + 状态 delta，再调用 VLM 改写新 `control`。
5. 循环直到 episode 结束。
6. 期间任何被声明为 `# skills/...` 的 helper 模块被原子写入磁盘并立即导入；若 import 失败则文件回滚并在下回合反馈错误。

## 6. 主要结论与发现

- **核心定量结果**：在 57 任务 MuJoCo/RoboVerse 套件上，**closed-loop VLCP (K=50)** 总体成功 **35.1% [24.0, 48.1]**；**open-loop (K=T)** **3.5% [1.0, 11.9]**——**约 10 倍提升**。
  - Object Picks：60.0% vs 10.0%。
  - Kitchen Scenes：33.3% vs 3.3%。
  - Living-Room Scenes：23.5% vs 0.0%。
  - 每个族内置信区间均不重叠。
- **机制归因（恢复分析）**：在 75 个拣放 episode 中，55 个至少出现过一次失败抓取；**27.3%**（15 个）在后续 block 重新接近并成功提起目标（中位延迟 3 次重规划）。开环系统由于永不重观测，结构上恢复率为 **0%**。
- **指令泛化**：VLCP 在改写指令下总体成功率不变（**40.0% → 40.0%, Δ=0**），无系统性任务坍塌；VLA-0 在原指令近乎天花板（97.3%）但在 butter 上从 96% 崩至 0%、bbq_sauce 从 96% 降至 50%，总体掉到 75.0%——说明其部分高表现依赖特定指令措辞。
- **效率**：每 episode 仅 ~10 次紧凑查询，84% 输入 token 命中缓存，**100% 代码有效性**；前沿模型推理时延约 18.8 s/replan 是当前控制频率的实际下限。
- **跨 episode 技能库**：任何 episode 中写入的 helper 模块均落盘并被注入后续 episode 的提示，支持后续 episode `import` 复用，构成训练免费框架下的**持续学习底座**。
- **定性观察**：失败 VLA-0 在同条件审查下常出现"卡住"或"重复同样错误"（如在物体后抓、夹爪在容器后打开），而 VLCP 失败时由模型明确诊断失败原因（如"夹爪闭合前手不够低"）并改写代码。

- **高推理延迟**：单次重规划中位 18.8 s，**不适合高频反应式控制**，适合相对慢速的操作任务。
- **评估预算受限**：因每次 episode 都触发闭源 VLM 调用，主扫描每任务仅 1 episode，未做多种子方差分析；指令重表述实验中 N=10，统计力度有限。
- **对底层 VLM 能力敏感**：论文明确指出较小开源模型（如 Qwen3-4B）无法可靠生成控制代码或有效重规划，**限制可及性并提高部署成本**。
- **缺乏 K 的系统扫描**：K=50 是工程选择，未对节奏–成本权衡做系统消融；任务自适应调度（如接触事件附近更密集重规划）留作未来工作。
- **绝对成功率随任务长度下降**：Object Picks 60% → Kitchen 33% → Living-Room 24%，说明长视野任务仍有大量剩余失败 episode 未被恢复。
- **横比基准的非可比性**：与 CaP-Agent0 的跨基准比较只能引用报告值，无法作出严格的可比声明。
