## 摘要
最近的视觉-语言-动作（VLA）模型几乎普遍将机器人本体感受状态作为输入，却以互不兼容的方式将其接入——序列化到文本提示中、投影到视觉-语言前缀中，或直接馈送给动作专家模块——而且几乎总是仅使用单一的当前帧。三个问题仍悬而未决：（1）当前状态是否确实能提升闭环控制，以及在哪类任务上有效；（2）状态历史有多大帮助，其收益究竟反映了真实的时间变化，还是仅仅来自额外的条件容量；（3）状态应当在哪里进入模型——视觉-语言主干网络还是动作生成模块。我们通过在一个流匹配 VLA 上进行的受控实验回答这些问题，全程固定主干网络、训练数据、动作表示与评估流程。我们实现了五种具有代表性的接口——离散状态提示、VLM 前缀、动作前缀、状态专家和特征调制——在实现细节上严格对齐，并在涵盖三类任务家族的 45 个原子任务以及 20 个组合任务上对它们进行评估；随后我们将状态历史长度从 1 帧扫到 96 帧，以考察历史状态信息如何影响模型性能。实验系统地回答了上述三个问题，并提炼出可供检验的、面向状态感知 VLA 的设计原则。

## Abstract
Recent Vision-Language-Action (VLA) models almost universally take robot proprioceptive state as input, yet wire it in incompatible ways -- serialized into text prompts, projected into the vision-language prefix, or fed directly to the action expert -- and almost always as a single current frame. Three questions remain open: (1) whether, and on which tasks, current state actually improves closed-loop control; (2) how much state history helps, and whether its benefit reflects genuine temporal variation rather than added conditioning capacity; and (3) where state should enter the model -- the vision-language backbone or the action-generation module. We answer these questions through controlled experiments on a flow-matching VLA, fixing the backbone, training data, action representation, and evaluation protocol throughout. We implement five representative interfaces -- discrete state prompt, VLM prefix, action prefix, state expert, and feature modulation -- under matched implementation details, and evaluate them on 45 atomic tasks spanning three task families plus 20 composite tasks; we then sweep the state-history length from 1 to 96 frames to examine how historical state information affects model performance. The experiments yield systematic answers to all three questions, distilled into testable design principles for state-aware VLAs.

# 论文总结：VLA 模型应如何使用本体感受状态

## 1. 核心问题与研究背景

**研究动机：**
- 当前 Vision-Language-Action（VLA）模型几乎都接收机器人本体感受状态（proprioceptive state）作为输入，但接入方式差异巨大且缺乏共识：
  - 表示层面：π₀.₅ 将状态离散化后序列化为文本 token，OpenVLA-OFT 和 GR00T N1 则将其投影为连续嵌入
  - 注入层面：部分设计将状态送入 VLM 主干，部分直接送入动作专家
  - 时间层面：绝大多数方法仅使用当前单帧，几乎没有研究状态历史的作用
- 这些差异往往与骨干网络、预训练数据、动作表示等纠缠在一起，使得不同 VLA 之间的实验结果不可比
- 与视觉、语言不同，本体感受状态缺乏大规模预训练，是 VLA 中最少被深入研究的输入

**三个核心待回答的问题：**
1. 当前状态是否真的能提升闭环控制？在哪些任务上有效？
2. 状态历史多大程度上有帮助？其收益来自真实的时间变化还是仅仅来自额外的条件容量？
3. 状态应该注入 VLM 主干还是动作生成模块？

**研究意义：** 通过控制变量法系统回答上述问题，为未来 state-aware VLA 提供可验证的设计准则。

## 2. 方法论

**测试平台：** 采用 π₀.₅（一个 VLM + 流匹配动作专家的组合）作为统一测试床，全程固定骨干网络、训练数据、动作表示和评估流程。

**本体感受状态表示：**
- 原始状态维度为 16（末端执行器位姿 + 机器人底座位姿 + 夹爪关节位置）
- 除离散状态提示外，所有连续接口都通过一个共享的两层 projector 将每帧独立编码为连续 token
  - VLM 前缀使用维度 d=2048
  - 动作前缀、状态专家、特征调制使用 d=1024

**五种状态接口设计：**

| 接口 | 注入位置 | 表示形式 | 新增参数（K=1）|
|------|---------|---------|---------------|
| **State Prompt (sp)** | VLM 文本提示 | 离散化为 256 bin 的文本 token（约 66 个）| 0 |
| **VLM Prefix (vp)** | VLM 双向前缀 | 连续 token 嵌入 | 4.26M |
| **Action Prefix (ap)** | 动作因果前缀 | 连续 token 嵌入 | 1.08M |
| **State Expert (se)** | 独立 transformer 流 | 独立序列建模 | 199.30M |
| **Feature Modulation (fm)** | 动作专家 cross-attention | γ/β 调节每层特征 | 123.84M |

**关键技术要素：**
- **槽位匹配控制（Slot-matched control）**：通过"重复当前状态"（repeat-current）控制，消除因增加 token 数量带来的额外条件容量影响，剥离出真正的时间结构贡献
- **配对评估协议**：固定场景、物体实例、相机视角、仿真随机化种子，确保比较的公平性
- **任务家族预分区**：在训练前按控制语义而非性能事后划分任务，避免循环论证
- **三层声明层次**：(a) 独立训练系统的整体接口对比；(b) 槽位匹配下的真实历史 vs 重复当前帧对比；(c) 固定检查点的探针实验追踪状态如何到达动作生成

## 3. 实验设计

**基准平台：** RoboCasa365（基于 RoboCasa 仿真框架）
- 多样化厨房场景、机器人初始配置、物体实例、操作任务
- 三视角视觉输入（左外、右外、手腕相机）

**两层评估协议：**

**A. 原子任务基准（45 个任务）**
- 任务按控制语义预先分为三类家族：
  - **A 类（重排/取放）**：15 个任务，大范围末端执行器与底座定位
  - **B 类（铰接物体交互）**：15 个任务，门/抽屉/铰链操作，需持续接触与运动阶段建模
  - **C 类（旋钮/开关）**：15 个任务，小工作空间高精度局部控制
- 每个家族独立训练专家策略；每任务 50 次闭环 rollout；固定种子调度

**B. 组合任务基准（20 个任务）**
- 使用 lifelong_learning_phase2 设置，每任务由 2–3 个原子子目标串联
- 一个策略联合训练所有 20 个任务；评估同分布组合控制
- 默认末端执行器位姿表示，同时在关节角度表示下重复关键对比
- 每任务 25 次闭环 rollout

**对比方法：**
- No-state baseline（无状态基线）
- 五种状态接口（sp/vp/ap/se/fm）
- 历史深度从 1 到 96 帧的扫描
- 槽位匹配的 repeat-current 控制

**主要指标：** 闭环任务成功率（SR）

## 6. 主要结论与发现

### RQ1：当前状态是否能提升控制？
- **当前状态总体上有益**：所有 5 个接口的宏观成功率均高于无状态基线（54.6%），提升范围 +1.1 到 +3.1 点
- **sp 是唯一具有统计支撑的宏观提升**（[0.2, 6.1] 置信区间排除零）
- **无任务无关的最佳接口**：家族排名反转
  - A 类（重排）：sp 最佳（68.7%，+7.0）
  - B 类（铰接）：vp 最佳（68.8%，+6.1）
  - C 类（旋钮/开关）：se 最佳（42.8%，+3.3），vp 反而低于基线（-1.2）
- **计算成本差异显著**：sp 训练成本高出两个数量级，se 和 fm 算力代价小但宏观估计几乎相同（57.6%）

### RQ2：状态历史是否有用？需要多少？
- **短历史有益，长原始历史有害**：非单调趋势，K=8 是实际操作点
- 家族 A、B 对增加上下文相对耐受，但家族 C 在长历史下严重退化
- 原子任务的结论迁移到组合任务：8 帧在多数接口下提升性能，最显著的动作侧提升
- **增益来自真实时间结构**：槽位匹配控制显示，重复当前状态明显劣于真正有序历史，置信区间排除零
- **结论对状态表示形式稳健**：关节角度表示下也保留相同定性优势

### RQ3：状态应注入哪里？
- **关键发现：注入路由存在交叉偏好**
  - **K=1（单帧）**：VLM 侧接口最优（组合任务中 vp 达 34.4% vs ap 28.2%）
  - **K=8（短历史）**：动作侧接口最优（组合任务中 ap 达 39.0%，提升 +10.8 点）
- K=1→8 的最大提升都出现在动作侧注入
- 探针分析显示：VLM 侧状态改变了多模态上下文，作用早期；动作侧状态直接在动作专家内作用

**综合设计原则：**
- **单帧状态注入 VLM**
- **短历史路由到动作头**
- **更深的历史需验证**（不再默认安全）

## 7. 优点与亮点

1. **严格的控制变量实验设计**：固定骨干、数据、动作表示、评估协议，使差异可归因于状态设计本身，是该领域罕见的系统化消融
2. **三种声明层次分明**：完整接口对比 + 槽位匹配容量控制 + 固定检查点机制探针，分离系统级效用与机制
3. **任务家族预分区**：避免按性能事后分组的循环论证，确保跨家族结论反映控制需求差异而非数据分布差异
4. **配对评估协议**：固定种子调度 + 同任务同上下文，最大限度减少评估噪声
5. **统计严谨性**：使用配对任务自助 95% 置信区间，避免仅看点估计的误导
6. **多维度对照**：E2E 控制性能 + 算力代价 + 机制探针，提供全面的设计权衡视图
7. **可复用的评估协议**：底层评测流程可直接用于未来 state-aware VLA 的审计
8. **跨表示形式验证**：在 EEF 位姿与关节角度两种状态下重复关键实验，结论的稳健性得到验证

## 8. 不足与局限

1. **缺乏真实机器人验证**：所有实验基于仿真，可能无法完全反映真实硬件的噪声、漂移和接触动力学
2. **状态模态局限**：仅考虑运动学状态（关节角度、末端位姿、夹爪），未涵盖力觉、触觉等其他本体感受模态
3. **单一骨干依赖**：仅在 π₀.₅ 上验证，结论对其他 VLA 架构（如 OpenVLA、GR00T）的泛化性未确认
4. **多数比较单种子**：除 sp 的宏观统计外，其他接口-深度组合均为单种子点估计，统计力度有限
5. **接口容量不均衡**：se（+199M）和 fm（+123M）与 sp（0）容量差异巨大，难以完全归因于"接口设计"而非"参数容量"
6. **探针实验为相关性而非因果**：边界敏感性是描述性证据，并非因果中介证明
7. **历史深度扫描的探索性**：未对多重比较进行校正（multiplicity adjustment），家族 C 长历史下退化的具体机制未深入
8. **复合任务为同分布评估**：Phase 2 仅测 in-distribution 组合控制，未评估对未见任务语义的泛化
9. **路由交叉的因果机制未完整建立**：尽管有固定检查点探针支持数据流解释，但"为什么 K=1 偏好 VLM 而 K=8 偏好动作"仍属于观察性模式
