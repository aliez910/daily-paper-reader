## 摘要
人类在执行长时程操作时，会保留对先前动作所建立成果的认知，同时不断适应正在进行的运动。相比之下，动作分块的视觉-语言-动作（VLA）策略在每次查询时都基于当前输入进行重复规划。现有方法要么通过记忆保留长期任务证据，要么通过动作复用与集成保留短期运动，导致跨查询的衔接不完整。我们提出了 ChainVLA——一个拥有 12 亿参数的 VLA 策略，通过一个联合且可修订的执行状态将连续查询链式连接起来。其中，Progress Context（进度上下文）将循环工作状态与稀疏事件记忆相结合，以承载源自观测的任务进度；Motion Tail（运动尾部）则将前一次预测中尚未执行的部分馈入状态构建与动作生成过程。二者共同约束一个解码器，使其在最新观测下重新生成每个动作时域，从而让所携带的状态在不固定的前提下引导下一次预测。ChainVLA 在 RMBench 上达到 62.8% 的平均成功率，在四个 LIBERO 套件上达到 98.8%；而移除 Motion Tail 或 Progress Context 分别将 RMBench 成功率降至 11.2% 和 3.0%。这些不对称的消融结果与以下假设一致：运动连续性有助于保留从中推断任务进度的观测流。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 1. 核心问题与研究动机

- **问题定位**：长时程机器人操作需要同时利用「任务进度」与「运动连续性」两类信息，但现有动作分块（action-chunked）VLA 策略在每次查询时仅根据当前输入重新规划，**未在相邻查询之间显式交接**这两类信息。
- **两类已有方案的不足**：
  - 记忆增强型（MemoryVLA、Mem-0、MemoAct 等）：保留长期任务证据，但不携带前次预测的未执行片段。
  - 时间集成 / 实时执行 / 原生延续型（Temporal Ensemble、Flow Matching 等）：保留短期运动连续性，但不能保留早期任务证据。
- **关键洞察**：执行后的运动轨迹反过来决定了下一查询可用的观测流——**运动连续性实际上保护了用于任务进度推断的观测序列**，二者并非独立，而是连续耦合的。
- **本文提出的核心问题**：如何在不固定当前规划的前提下，让 VLA 策略把"任务进度 + 运动延续"在相邻查询间链式衔接？

## 2. 方法论

### 2.1 整体框架
ChainVLA 是一个 **1.2B 参数**的 VLA 策略，骨干网络为 Florence-2-large，动作解码器为 Conditional-Flow（DiT）解码器。其核心是引入了一个**联合且可修订的执行状态** $s_k = (g_k, u_k)$，在每个查询边界完成「读 → 更新 → 写」循环。

### 2.2 两大核心组件
- **Progress Context（进度上下文）$g_k$**：承载源自观测的任务进度，由两部分融合而成
  - **Working State（工作状态）**：循环神经网络式更新，含当前 live tokens $L_k$、FIFO 缓存 $B_k$、执行动作 token $P_k$ 和 Motion Tail token $U_k$；通过 cross-attention 融合，并以池化向量 $\bar W_k$ 提供检索摘要。
  - **Sparse Event Memory（稀疏事件记忆）**：仅在触发条件下写入（阶段切换 / 每 3 次查询），容量 16；通过 $\bar W_k$、Stage Info $\bar s_k$ 与时间编码构造 age-aware 余弦相似度检索，读取 anchor + top-2 非 anchor 事件后融合成 readout token $Z_k^e$。
- **Motion Tail（运动尾部）$u_k$**：将前一次预测中尚未执行的后缀（即 $a_{k, h_{exec}+1}, \dots, a_{k, H}$）直接带入下一次查询；通过两条模型侧路径生效
  - 编码为 tail token 进入 Working State 构造；
  - 通过 $u_{k+1}$ 对齐的全时域均值 $\mu_{k+1}$ 条件初始化解码器 $e_{A,k+1}^{(0)} = \mu_{k+1} + \sigma_u \epsilon_{k+1}$。
- **关键设计**：解码器在最新观测下**重新生成每一个时域位置**（无任何位置被冻结或复制），所携带的状态只作为可修订的先验。

### 2.3 查询转移方程
$$
(A_k, W_k, C_{k+1}) = F_\theta(x_k, D_k, W_{k-1}, C_k, u_k), \quad u_{k+1} = \text{Tail}(A_k)
$$
训练时 $u_{k+1}$ 经 detach 后条件化下一查询；推断时直接使用。Episode 结束时所有携带状态清零。

### 2.4 训练目标
- 标准 conditional-flow 动作目标；
- 阶段监督损失（带阶段标注时）；
- **overlap-consistency 正则项**（权重 0.2）：惩罚相邻预测在时域对齐重叠部分的不一致性，但不固定新动作；
- 训练过程中下一个查询以 50% 概率使用前一个查询的 detached tail。

## 6. 主要结论与发现

- **总体性能**：RMBench 平均 62.8%（每个任务均进入前两名），LIBERO 平均 98.8%（每套件 > 98%）；
- **不对称消融结果**：去除 Motion Tail → 11.2%；去除 Progress Context → 3.0%；二者全去 → 1.6%；
- **子组件重要性**：
  - Progress Context 中 Event Readout 影响最大（Put Back 从 96 → 25），Live Tokens 47.2，w/o Stage Ann. 53.4；
  - Motion Tail 中 Trajectory Init. (38.0) 比 Tail Tokens (52.0) 更关键；
- **机制解释**：移除 Motion Tail 后，paired Put Back 边界位置 gap 从 0.66 mm 升至 17.32 mm；pooled 降幅 $CD_p$ 56.6%、$CD_R$ 40.4%、$B_2$ 57.4%、$RMSE_3$ 43.1%；
- **关键洞察**：运动连续性通过维持观测流稳定从而保护任务进度推断，并非作为独立目标；
- **后解码平滑无效**：Linear Continuation 边界指标最低但成功率仅 0–2%，Temporal Ensemble 同样失败 → 边界平滑只是诊断而非目标，决定性因素是**解码前**的状态条件化；
- **替代方案不足**：FIFO History + Temporal Ensemble 仅 35.6%，比 Full 低 27.2 个百分点。

## 7. 优点

- **机制层面**：提出统一的「执行状态」概念，把跨查询交接问题清晰分解为 Progress Context（任务证据）与 Motion Tail（运动延续）两个互补分量，并给出形式化定义（执行状态 $s_k = (g_k, u_k)$）。
- **设计层面**：解码器在最新观测下**完全重生**每个时域位置，所携带状态作为可修订先验而非固定计划，兼具记忆性与反应性。
- **实验设计**：所有消融条件均匹配训练协议（backbone、数据、步数、batch、seed），使消融结论可信；引入四类边界诊断指标提供机制证据；并通过后解码平滑控制实验区分"是否使用"与"如何使用"前次预测。
- **效率层面**：仅 1.2B 参数即在 RMBench 超越 8B+2B 的 Mem-0，且 LIBERO 上达到 SOTA 级水平，参数效率高。
- **写作层面**：附录详尽（Algorithm 1、A1–A5 表、干预细节、诊断公式与配对数据），可复现性强。

## 8. 不足与局限

- **统计层面**：所有内部条件仅使用单随机种子，无方差或显著性检验；
- **评估层面**：
  - 仅在固定频率仿真下评估，未在真实硬件或异步 / 实时部署下测试；
  - 未研究控制频率变化对方法的影响；
  - 边界诊断指标为局部量，不能反映整条轨迹质量或累积状态偏差。
- **可比性层面**：外部基线为源文献报告值，**未在统一协议下重跑**，导致跨方法对比可能存在 backbone、演示数据、优化预算、评估标准的不对齐；
