## 摘要
视觉模仿学习使机器人能够直接从图像中获取视觉运动技能，但RGB观测缺乏显式的几何线索，导致所学策略在相机扰动下表现脆弱。为解决这一问题，我们提出了**射线条件视觉Transformer编码器（RayViT）**，这是一种将相机几何信息注入预训练ViT骨干网络的轻量级架构。RayViT将相机几何信息表示为Plücker射线图，将其分块化为射线特征，并利用门控交叉注意力生成射线条件类别标记。这些射线特征被作为密集位置嵌入加以添加，而射线类别标记则取代原始的ViT类别标记，以提供具备几何感知的汇总表征。我们将该方法与辅助余弦相似度损失相结合，从而持续提升几何感知标记的性能与鲁棒性。在仿真和真实机器人任务上的实验表明，与基线方法相比，RayViT在多任务RoboCasa基准测试中面对相机扰动时将鲁棒性提升了约13个百分点，并将真实世界多任务成功率的平均完成阶段数提高了1.78。

## Abstract
Visual imitation learning enables robots to acquire visuomotor skills directly from images, yet RGB observations lack explicit geometric cues, making learned policies brittle to camera perturbations. To address this, we propose \textbf{Ray-conditioned Vision Transformer Encoder (RayViT)}, a lightweight architecture that injects camera geometry into pretrained ViT backbones. RayViT represents camera geometry as a Plücker ray map, patchifies it into ray features, and uses gated cross-attention to produce a ray-conditioned class token. These ray features are added as dense positional embeddings, while the ray class token replaces the original ViT class token to provide a geometry-aware summary representation. We combine this approach with an auxiliary cosine similarity loss to consistently improve the performance and robustness for geometry-aware tokens. Experiments on sim- and real-robot tasks demonstrate that RayViT improves robustness by approximately 13 percentage points under camera perturbations in multi-task RoboCasa benchmark and by 1.78 average completed stages in real-world multi-task success rate compared to baselines.

# RayViT：用于视角鲁棒模仿学习的射线条件视觉表征 — 论文总结

## 1. 核心问题与整体含义

- **研究背景**：视觉模仿学习（Visual Imitation Learning）使机器人能够从 RGB 图像演示中直接学习视觉运动策略，依赖 DINOv3 等大规模预训练视觉基础模型提取语义特征。
- **核心痛点**：RGB 观测**缺乏显式几何线索**，预训练表征对相机位姿变化不可知。学得的策略倾向于记忆"外观到动作"的视角特异性映射，因此在相机视角发生扰动（相机被障碍物遮挡、安装在运动机器人上、外参数变化等）时性能急剧下降。
- **现有方案的不足**：
  - **多视角数据增广**：成本高、难以在真实场景中扩展（Jiang et al. 2025）。
  - **显式 3D 表示**（点云、点图）：需要深度传感器或额外重建，密度/噪声/物理尺度难以统一，且与纯图像预训练视觉基础模型不兼容。
- **本文切入角度**：利用 Plücker 射线图（Plücker ray map）从相机内/外参计算得到像素级射线几何，仅需相机标定，不依赖深度传感器或额外重建，即可将 3D 几何信息注入预训练 ViT。

## 2. 方法论：RayViT

### 2.1 核心思想

将相机几何（Plücker 射线图）通过两条互补路径注入**预训练 ViT 骨干网络**（默认 DINOv3 ViT-Small，21.6M 参数），同时引入跨视角一致性辅助损失，从而在保留预训练语义表征能力的前提下显著提升对相机视角变化的鲁棒性。

### 2.2 Plücker 射线图构建

- 对每个像素 $\mathbf{p} = (u, v, 1)^\top$，由内参 $\mathbf{K} \in \mathbb{R}^{3\times 3}$、外参 $(\mathbf{R}, \mathbf{t})$ 计算相机中心 $\mathbf{o}_w = -\mathbf{R}^\top \mathbf{t}$ 与归一化方向 $\mathbf{d}_w(u, v)$。
- 每个像素编码为六维 Plücker 坐标 $\mathbf{r}(u,v) = [\mathbf{d}_w(u,v),\ \mathbf{m}_w(u,v)] \in \mathbb{R}^6$，其中 $\mathbf{m}_w = \mathbf{o}_w \times \mathbf{d}_w$ 为射线矩。
- 射线图与 RGB 图像空间对齐，构成像素到像素的外观-几何对应关系。

### 2.3 射线条件类别标记（Ray-conditioned Class Token）

- **Patch-aligned Ray Features**：将射线图以 patch 尺寸的均值池化下采样到 ViT patch 分辨率（采用无参数均值池化以保留几何语义），再通过两层 MLP + GELU 投影到 ViT 隐维度。
- **Gated Cross-attention Module**（2 个轻量级块，4 个注意力头，3.85M 参数）：
  - 一个可学习查询 token 通过交叉注意力聚合所有 patch-aligned 射线特征。
  - 在注意力后施加**可学习元素级 sigmoid 门控**（借鉴 Qwen 的 Gated Attention 设计），自适应调节几何信息注入强度，避免压倒预训练表征。
  - 最终的查询 token 取代原始 [CLS]，作为具备几何感知的全局视觉摘要送入策略网络。

### 2.4 射线位置嵌入（Patch-aligned Geometric Positional Embedding）

- 将 patch-aligned 射线特征**加性注入**到第一层 Transformer block 之前的图像 patch token 上。
- **保留 RoPE（旋转位置编码）不变**：RoPE 提供图像平面内的局部空间推理能力，射线注入提供每个 patch 的绝对 3D 几何锚定，两者互补。
- 两个变体：
  - **RayViT-cls**：仅通过射线条件 CLS token 注入几何。
  - **RayViT**：进一步加入 patch 级射线位置嵌入。

### 2.5 跨视角对齐损失（Cross-view Alignment Objective）

- 在 ViT 中间层（第 10 层，权重 $\lambda = 0.01$）对各视角 CLS token 计算**余弦相似度损失**：
  $$\mathcal{L}_{\cos} = 1 - \frac{1}{N-1}\sum_{v \in \mathcal{V}} \cos(\mathbf{c}_v, \mathbf{c}_g), \quad \mathcal{L} = \mathcal{L}_{\text{IL}} + \lambda \mathcal{L}_{\cos}$$
- 以夹爪相机（in-hand view）作为锚点 $\mathbf{c}_g$，因其最接近操作目标且背景干扰最少。
- **关键发现**：该辅助损失只在 token 已具备几何信息时才稳定提升性能（对纯 RGB baseline 无显著效果）。

### 2.6 策略架构

- 动作头采用**基于评分的扩散策略（Score-based Diffusion Policy）**，配合 decoder-only xLSTM（8 个 x-Block，动作块大小 10），使用 DDIM 4 步采样。
- 语言条件由**冻结的 CLIP ViT-B/32** 提供。

## 3. 实验设计

### 3.1 仿真实验

- **基准与任务**：**RoboCasa** 大规模厨房仿真基准，**16 个多任务**（开/关抽屉、灶台、水龙头、微波炉；拾放咖啡杯、勺子等），覆盖短/长时序操作。
- **训练设置**：每个任务 50 条人类演示，训练 50 epoch，3 个随机种子，报告第 30/40/50 epoch 的最佳结果；批量大小 256。
- **视角扰动协议**：在原始 Default 设置外，构建 Variant 设置——两个静态相机在方位角、俯仰角、距离上**随机扰动**。
- **基线对比**（4 个）：
  - **Adapt3R**（3D 特征与 2D 特征结合，需深度）。
  - **PMP-xyz**（纯 3D 点图表征）。
  - **CamPose**（射线图作为晚期融合输入模态）。
  - **RGB**（本文图像-only 变体，无任何射线注入）。
- **附录还对比了 PMP**（PMP-xyz 与图像 token 拼接）。

### 3.2 真实机器人实验

- **平台**：7-DOF Franka Panda，8 维动作空间（关节位置 + 夹爪）。
- **相机**：左右视角 ZED Mini 立体相机 + 夹爪 Intel RealSense D405，输入分辨率 256×256；扰动环境用一台"新右侧相机"替换默认右相机。
- **4 个任务**：Cup Stack（4 阶段）、Pick Place（4 阶段）、Drawer（4 阶段）、Insertion（3 阶段）；每个任务 20 次 rollout 评估，按完成阶段数计分。

## 6. 主要结论与发现

- **视角鲁棒性大幅提升**：在 RoboCasa 多任务 Variant 设置下，RayViT 平均成功率 37.3%（性能下降仅 2.5 pp），相比 RGB baseline 的 24.0%（下降 18.5 pp）提升 **约 13 个百分点**。
- **真实机器人**：平均完成阶段数从 RGB 的 0.91 提升至 RayViT 的 2.69，**提升 1.78**；Variant 设置下从 0.91 提升至 2.69。
- **几何注入路径缺一不可**：
  - 射线 CLS 注入（RayViT-cls）已能显著提升鲁棒性。
  - 加入 patch 级射线位置嵌入（RayViT）在更复杂的真实场景（更高分辨率、更长 patch 序列）中收益更大。
- **跨视角一致性损失的"前置条件"**：必须在 token 已具备几何感知时才有效，对纯 RGB 无收益；说明几何接地是辅助表征学习的必要前提。
- **方法通用性**：在 DINOv3 与 EUPE 两种预训练骨干上、在随机初始化场景下均保持优势，验证几何注入机制的迁移性。
- **与 3D 表示方法的对比**：稠密几何本身不足以保证视角鲁棒，必须显式建模相机引起的变换——Adapt3R 与 PMP-xyz 在 Variant 下下降幅度（13.2–21.3 pp）均高于 RayViT（2.5 pp）。

## 7. 优点

- **即插即用的轻量设计**：仅增加约 4M 参数（门控注意力 3.85M + 射线投影 0.15M），不改变 ViT 主体结构与 RoPE，保留预训练语义能力。
- **无需额外传感器**：仅依赖相机内/外参，无需深度、点云或多视角增广即可引入 3D 几何。
- **双路径互补注入**：射线条件 CLS token 提供全局几何摘要，patch 级射线嵌入提供逐 patch 的 3D 锚定，两者协同增强表征。
- **门控机制稳定训练**：可学习 sigmoid 门控防止几何信号压倒预训练分布，保留原始视觉先验。
- **辅助损失设计巧妙**：跨视角余弦对齐 + 夹爪锚点选择，引导策略学到视角不变的任务表征。
- **实验覆盖全面**：仿真+真实、消融+参数研究、不同骨干、扰动协议公开，对比基线选择具有代表性。

## 8. 不足与局限

- **骨干网络受限**：仅适用于 ViT 系列预训练编码器，未探索卷积类视觉骨干；论文也明确将其列为未来工作。
- **依赖多视角设置**：跨视角一致性损失需要"任务相关的锚点视角"（本文取夹爪相机），对单视角或稀疏视角场景适应性存疑。
- **相机外参标定依赖**：射线图需要外参，对未标定的低成本相机部署存在门槛（虽然论文指出许多竞争方法也需要标定）。
- **Variant 设置范围未完全量化**：扰动协议虽明确是 azimuth、elevation、距离的随机扰动，但具体范围与分布未在主文中给出。
- **Checkpoint 选择偏差**：取第 30/40/50 epoch 最佳，可能高估实际部署性能；缺少对最终 epoch 一致性的报告。
- **真实机器人演示规模有限**：Drawer、Pick Place、Cup Stack 仅 50 条演示，Insertion 100 条；与 RoboCasa 大规模演示相比可能限制泛化性。
- **未讨论失败模式与安全性**：未分析在极端视角（遮挡、剧烈晃动、动态相机）下策略的失败案例与潜在风险。
- **任务局限于桌面操作**：仅在桌面级厨房/拾放任务验证，未涉及移动机器人、室外、灵巧操作等更广泛场景。
