## 摘要
人类在执行长时序操作任务时，能够保留早期动作所建立的知识，同时持续适应正在进行的运动。相比之下，基于动作块划分的视觉-语言-动作（VLA）策略在每次查询时都基于当前输入重新进行规划。现有方法要么通过记忆保留长期任务证据，要么通过动作复用与集成保留短期运动，导致跨查询衔接不完整。我们提出 ChainVLA，一个 12 亿参数的 VLA 策略，通过一个联合且可修订的执行状态将连续查询串联起来。Progress Context（进展上下文）将循环式的 Working State（工作状态）与稀疏事件记忆相结合，以承载从观测中提炼的任务进展；Motion Tail（运动尾部）则将前一次预测中尚未执行的后续片段输入到状态构建与动作生成中。二者共同调节一个解码器，使其在最新观测下重新生成每个动作时间范围，使所携带的状态能够指导下一次预测而不将其固化。ChainVLA 在 RMBench 上达到 62.8% 的平均成功率，在四个 LIBERO 套件上达到 98.8%；而移除 Motion Tail 或 Progress Context 分别将 RMBench 成功率降至 11.2% 和 3.0%。这些不对称的消融实验结果与以下观点一致：运动连续性有助于保留从中推断任务进展的观测流。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 一、核心问题与整体含义

### 1.1 研究背景
长时序机器人操控任务要求策略能够在多次重规划之间保持"任务进展"与"运动连续性"两个层面的衔接。人类执行此类任务时，会同时保留已建立的任务成果与正在进行的运动，并根据反馈进行修订。

### 1.2 现有方法的不足
- **动作分块 VLA 策略**（如 ACT、Diffusion Policy、π0 等）采用"严格前缀"回归式重规划机制：每次查询基于当前观测重新生成 H 长度的动作块，仅执行前 h_exec 个动作后再次查询。
- **缺失的跨查询衔接**体现在两个层面：
  - **任务层面**：早期任务证据可能已不在当前观测中，但模型无法访问历史；
  - **运动层面**：重规划会丢弃前次预测中尚未执行的后续片段，新动作可能与被替换的运动不一致。
- **两类现有方案的局限**：
  - 记忆增强策略（MemoryVLA、Mem-0 等）保留长期任务证据，但不携带预测侧的延续信息；
  - 时间集成/原生延续（Temporal Ensembling、RTFM 等）保持短期运动一致性，但无法保留早期任务证据。

### 1.3 核心问题
如何在 VLA 策略中同时链式传递任务进展与未执行动作延续，同时让每次新预测仍对最新观测保持响应？

## 二、方法论

### 2.1 核心思想：统一可修订执行状态
ChainVLA 是一个 **1.2B 参数**的 VLA 策略，将相邻查询通过一个**联合且可修订的执行状态** $s_k = (g_k, u_k)$ 串联起来。

执行状态包含两部分：
- **Progress Context（进展上下文）$g_k$**：回顾性部分，由 Working State（循环工作状态）与 Sparse Event Memory（稀疏事件记忆）共同构成。
- **Motion Tail（运动尾部）$u_k$**：前瞻性部分，携带前次预测中尚未执行的连续动作。

查询转换形式化为：
$$
(A_k, W_k, C_{k+1}) = F_\theta(x_k, D_k, W_{k-1}, C_k, u_k),\quad u_{k+1} = \text{Tail}(A_k)
$$
其中 $D_k$ 为已执行动作历史，$W_k$ 为工作状态，$C_k$ 为事件记忆，$u_k$ 为传入的运动尾部。

### 2.2 Progress Context 的实现

**Recurrent Working State（循环工作状态）**：
- 包含当前 live tokens $L_k$ 与有界 FIFO 缓存 $B_k$；
- 8 个可学习工作查询经交叉注意力更新 live tokens，并通过 $m^{live}_{k-1} \in \{0,1\}$ 掩码控制回溯有效性；
- 已执行动作 $D_k$ 通过 $\phi_P$ 编码为 $P_k$，传入的运动尾部 $u_k$ 编码为 $U_k$，共同参与工作状态更新；
- 池化摘要 $\bar{W}_k = \text{Pool}([L_k, B_{k-1}, P_k, U_k])$ 驱动后续事件检索。

**Sparse Event Memory（稀疏事件记忆）**：
- 容量为 16 条记录，每条记录存储 64 视觉 token、8 个 Stage Info token、8 个时序 token 及检索键 $\kappa_i$ 与写入查询索引 $b_i$；
- 首次有效查询作为锚点固定保留；有任务阶段标注时（仅 RMBench），按阶段切换触发写入；无标注时（LIBERO），按每 3 次查询的固定周期写入；
- 检索打分采用年龄感知余弦相似度：
$$
\rho_{k,i} = \cos(\text{LN}(q^e_k),\ \text{LN}(\kappa_i + \text{Emb}_{age}(\text{clip}(k - b_i))))
$$
- 检索出锚点记录与得分最高的两个非锚点记录，通过交叉注意力融合为 readout tokens $Z^e_k$；
- 最终 Progress Context $g_k = \text{Fuse}(L_k, Z^e_k)$。

### 2.3 Motion Tail 的实现
Motion Tail 沿两条**模型侧路径**作用于下一查询：
1. **工作状态路径**：尾部动作经动作空间归一化与可学习投影编码为 tail tokens $U_{k+1}$，参与 Working State 构造；
2. **动作生成路径**：尾部动作与完整动作表示对齐，初始化解码器的均值：
$$
\mu_{k+1} = \mathcal{I}(u_{k+1}),\quad \epsilon_{k+1} \sim \mathcal{N}(0,I),\quad e^{(0)}_{A,k+1} = \mu_{k+1} + \sigma_u \epsilon_{k+1}
$$
- 解码器（DiT 条件流主干）**重新生成每个动作位置的输出**（不复制、不冻结任何位置），保证尾部仅作为可修订先验；
- **执行侧处理**：解码后对重叠步进行线性混合（execution-side handoff），但此操作与模型侧条件化是分开的。

### 2.4 训练目标
- 标准条件流动作生成损失；
- 阶段监督损失（仅 RMBench 提供标注时使用，标签不进入动作解码器）；
- 重叠一致性正则化（权重 0.2），惩罚相邻预测在时间对齐重叠区域内的不一致；
- 训练时按 episode 顺序展开，相邻查询间以 0.5 概率使用前次 detached 尾部；尾部输入与梯度截断。

## 三、实验设计

### 3.1 基准与对比方法

**主基准：RMBench**（Memory-Dependent Robotic Manipulation Benchmark）
- 5 个双手操作任务：Rearrange Blocks、Put Back Block、Swap Blocks、Swap Tools（部分文献含第 5 任务：Observation-Repeat）；
- 每个任务需从初始布局、目标与顺序记忆、回位记忆、早期阶段决策等能力中识别策略表现；
- 训练集为每个任务 50 条演示，训练 20,000 步；
- 评估 100 个 rollout。

**广度基准：LIBERO**
- 四个套件：Spatial、Object、Goal、Long；
- 每个套件微调一个模型，10 个任务各评估 50 个 rollout。

**对比方法**：
- 动作分块基础方法：DP、ACT、π0.5、X-VLA；
- 记忆系统方法：MemER、MemoryVLA、Mem-0、MemoAct、PAM、Goal2Skill；
- LIBERO 对比：OpenVLA、SpatialVLA、π0-FAST、GR00T-N1、π0、π0.5+KI、CronusVLA 等。

### 3.2 评估指标
- **主要指标**：任务成功率；
- **边界诊断指标**（4 项，越低越好）：
  - $CD_p$：边界位姿命令位姿位置不连续；
  - $CD_R$：边界姿态命令方向不连续；
  - $B_2$：跨边界的命令速度变化（二阶差分）；
  - $RMSE_3$：前次未执行尾部与新计划在 3 步重叠上的位置 RMSE。

### 3.3 消融与对照
- **Progress Context 侧**：w/o Stage Annotation、w/o Live Tokens、w/o Event Readout、w/o Progress Context；
- **Motion Tail 侧**：w/o Tail Tokens、w/o Trajectory Initialization、w/o Motion Tail；
- **整体去除**：w/o Both（保留观测与已执行动作）、FIFO History + Temporal Ensemble 替代基线；
- **输出层对照**：Linear Continuation（仅保留执行侧混合）、Temporal Ensembling（后处理集成）。

## 六、主要结论与发现

### 6.1 性能结论
- **RMBench**：ChainVLA 平均 62.8%，显著优于五任务完整覆盖的次优方法 Mem-0（52.8%，8B+2B 参数）；
  - Put Back Block：96（vs Mem-0: 90、MemoryVLA: 50）；
  - Swap Blocks：74（次优）；
  - 各任务均位列前二。
- **LIBERO**：四套件平均 98.8%，每个套件均高于 98%，Long 套件达 98.2%。

### 6.2 消融结论（不对称效应）
- 仅保留 Progress Context（去 Motion Tail）：11.2%；
- 仅保留 Motion Tail（去 Progress Context）：3.0%；
- 两者全去（w/o Both）：1.6%；
- 完整模型：62.8%。
- **关键发现**：两半并非独立可叠加的增益，两个半独立状态都远低于完整模型；这说明二者是**串联关系**而非并联。

### 6.3 运动连续性与任务记忆的关系
- 移除 Motion Tail 后，边界位姿差距在 Put Back 单边界上从 0.66 mm 上升至 17.32 mm；
- 80 对配对边界诊断的池化降低幅度：$CD_p$ 56.6%、$CD_R$ 40.4%、$B_2$ 57.4%、$RMSE_3$ 43.1%；
- **核心解释**：运动连续性是 Progress Context 赖以运作的前提；剧烈抖动会让机械臂访问训练时未见过的视角，从而破坏记忆检索的输入分布。

### 6.4 平滑不等于性能
- Linear Continuation 与 Temporal Ensemble 都能降低边界不连续指标，但在 Put Back 与 Swap Blocks 上成功率仅 0–3%；
- 仅靠输出侧平滑不能替代模型侧条件化，因为平滑作用于已解码命令而无法改变解码结果。

## 七、优点

1. **概念清晰**：明确区分了"任务进展（回顾性）"与"未执行运动（前瞻性）"两个互补维度，并将其形式化为可修订执行状态；
2. **结构可修订**：所有跨查询状态在新观测下都允许被覆盖（解码器重新生成每个动作位置），避免固化计划带来的脆弱性；
3. **组件分工合理**：Working State 维护当前查询上下文，Sparse Event Memory 维护跨多查询的里程碑；Motion Tail 仅连接紧邻查询；
4. **消融设计严谨**：删除操作同时撤销训练损失、输入路径与部署处理，三类替换基线（FIFO 历史 + TE、Linear Continuation、Temporal Ensemble）有效隔离了机制来源；
5. **诊断指标丰富**：4 项边界度量在配对场景下定量刻画运动连续性，并配合单实例插图（Put Back 边界处机械臂轨迹差异）直观展示；
6. **参数高效**：1.2B 参数即在两个基准上达到或超过显著更大的同类方法。

## 八、不足与局限

1. **单种子评估**：所有内部条件仅训练一个随机种子，未报告方差或显著性区间，结论仅为点估计；
