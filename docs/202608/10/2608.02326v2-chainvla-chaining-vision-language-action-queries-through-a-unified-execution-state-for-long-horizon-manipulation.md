## 摘要
人类在执行长时序操作时，既能保留早期动作所建立的状态认知，又能持续调整正在进行的运动。与之相反，基于动作分块的视觉-语言-动作（VLA）策略在每次查询时都从当前输入重新规划。现有方法要么通过记忆保留长期任务信息，要么通过动作复用与集成保留短期运动，导致跨查询的衔接并不完整。我们提出 ChainVLA，一种具有 12 亿参数的 VLA 策略，通过一个联合且可修正的执行状态来链式衔接连续查询。其中，进度上下文（Progress Context）将循环工作状态与稀疏事件记忆相结合，以承载由观测推导出的任务进度；运动尾段（Motion Tail）则将前一次预测中尚未执行的后续部分馈入状态构建与动作生成中。两者共同调节一个解码器，使其在最新观测下重新生成每个动作时域，使所携带的状态能够引导下一次预测，而不必将其固化。ChainVLA 在 RMBench 上达到 62.8% 的平均成功率，在四个 LIBERO 套件上达到 98.8%；而去除运动尾段或进度上下文分别使 RMBench 成功率降至 11.2% 和 3.0%。这种不对称的消融结果支持以下观点：运动的连续性有助于保留从中推断任务进度的观测流。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文总结

## 1. 论文核心问题与整体含义

- **研究主题**：长时序机器人操作（long-horizon manipulation）中，视觉-语言-动作（VLA）策略的跨查询衔接问题。
- **核心痛点**：人类执行长时序任务时同时依赖两类信息——前期动作建立的任务进度（task progress）和当前正在进行的运动连续性（motion continuation）。而现有 action-chunked VLA 策略在每次查询时都从当前观测重新规划（replan），导致：
  - **任务层面**：早期任务证据可能已离开当前视野但仍对决策关键（如 RMBench 的 Put Back Block 任务）。
  - **运动层面**：重新规划丢弃了前一次预测的未执行后缀，新预测的动作可能与被替换的运动不一致。
- **现有方法的局限**：
  - 记忆增强型策略（MemoryVLA、Mem-0、MemER 等）只保留任务证据，不携带运动延续。
  - 动作集成/复用类方法（Temporal Ensemble、Real-Time Execution、Native Continuation）只保留短期运动，无法保留早期任务证据。
- **核心问题**：如何在保留新预测对最新观测响应性的同时，把任务进度和未完成运动链式跨过查询边界？

## 2. 方法论

### 整体框架
- ChainVLA 是一个 **1.2B 参数** 的 VLA 策略，通过一个**联合、可回看（revisable）的执行状态** $s_k = (g_k, u_k)$ 链式衔接连续查询。
- 其中：
  - $g_k$（**Progress Context**，回顾性）：承载从观测推导出的任务进度。
  - $u_k$（**Motion Tail**，前瞻性）：承载前一次预测中尚未执行的后缀动作。
- 骨干网络：**Florence-2-large** + **Conditional Flow 解码器（DiT backbone）**。

### 关键技术细节

**(1) Progress Context（$g_k$）** = Working State + Sparse Event Memory
- **Recurrent Working State**（$W_k = (L_k, B_k)$）：
  - 8 个可学习的工作查询 token 通过 cross-attention 与当前多模态 token 交互，并保留上一查询的 live token $L_{k-1}$（通过 validity mask $m^{live}_{k-1}$ 控制 episode 起点）。
  - 含一个容量受限的 FIFO 缓存（3 槽，每槽 8 token），保留最近 live token。
  - 同时接收执行动作 token $P_k$ 和 Motion Tail token $U_k$ 作为条件。
- **Sparse Event Memory**（$C_k$）：仅在触发写入时更新。
  - 每个事件包含 64 视觉 + 8 Stage Info + 8 时间 token，外加检索 key 与写入查询索引。
  - 容量上限 16 条，按阶段转换（stage-annotated）或每 3 个查询一次（annotation-free）写入。
  - 检索时使用 age-aware 余弦相似度评分（$\rho_{k,i} = \cos(q^e_k, \kappa_i + Emb_{age}(k - b_i))$），返回 anchor + 2 个最高分非 anchor 记录，cross-attention 融合为 $Z^e_k$。
  - 最终 $g_k = \text{Fuse}(L_k, Z^e_k)$。

**(2) Motion Tail（$u_k$）**
- 在严格前缀执行机制下（$h_{exec} < H$），前一次预测 $A_k$ 执行了 $h_{exec}$ 步后剩余 $H - h_{exec}$ 步被缓存为 $u_{k+1}$。
- **两条模型侧路径**：
  - **路径 A**：动作空间归一化后编码为 tail token $U_{k+1}$，参与 Working State 构建。
  - **路径 B**：对齐到全时域动作表示后作为解码器条件初始化：$\mu_{k+1} = \mathcal{I}(u_{k+1})$，$e^{(0)}_{A_{k+1}} = \mu_{k+1} + \sigma_u \epsilon_{k+1}$。
- **关键设计**：解码器在最新观测下**重新生成**每一个时域位置，使携带的状态成为可修正的先验而非固定计划。
- **执行侧混合**：解码后对重叠步骤进行线性融合。

**(3) 训练目标**
- 标准 conditional-flow 动作损失 + 阶段监督（stage-annotated 时）+ 重叠一致性正则化（权重 0.2）。
- 训练时按 episode 查询顺序展开，前一次预测的 tail 被 detached 后以概率 0.5 用于下一次查询。

## 6. 主要结论与发现

- **性能表现**：ChainVLA 在 RMBench 上达到 **62.8%** 平均成功率（每任务最优或次优），在 LIBERO 上达到 **98.8%** 平均成功率（每套件 >98）。
- **关键发现 1——部分状态远不足够**：
  - 去掉 Progress Context → **3.0%**（仅比 w/o Both 的 1.6% 略高）。
  - 去掉 Motion Tail → **11.2%**。
  - 两者叠加不到 62.8%，说明这不是两个独立改进，而是一个完整的链式机制。
- **关键发现 2——运动连续性保护观测流**：去 Motion Tail 后，任务进度模块虽然完整，但成功率仍暴跌。原因可能是边界处动作不一致使机械臂进入训练分布外的位姿，导致后续观测偏离演示，从而破坏检索/写入所需的任务证据。
- **关键发现 3——后解码平滑不足以替代模型侧条件**：Linear Continuation 在所有边界指标上都低于 Full，但成功率仅 0–2%；Temporal Ensemble 也相似。说明"平滑"不等于"任务成功"，必须让前一次预测真正参与下一次解码。
- **关键发现 4——事件记忆的写入机制**：固定每 3 步写入仍有 53.4% 成功率，说明 ChainVLA 不依赖阶段标注也能保持有用的事件链；但 Put Back Block 上事件读出贡献显著（96→25），说明长期证据对该任务最关键。

  - 每次 ablation 同时撤回训练与部署处理路径，测量的是"系统依赖"而非"孤立机制效应"。
  - 配对场景的边界测量表明"低边界误差与高成功率相关"，但论文自己明确指出这是关联而非因果。
- **诊断指标局限**：$CD_p$、$CD_R$、$B_2$、$RMSE_3$ 只在边界局部采样，无法反映整条 episode 的轨迹质量或累积状态偏差。
- **设计选择未调优**：视野长度 $H$、前缀 $h_{exec}$、记忆容量 16、写入置信度阈值 0.55、固定 3 步写入间隔、重叠一致性权重 0.2 等均为一次性设定，未报告敏感性。
- **可扩展性问题**：方法依赖显式阶段标注或固定间隔写入，未来在阶段边界模糊的长任务上是否仍稳健尚不明确。
- **模型规模对比**：参数规模 1.2B 远小于部分对比方法（如 MemoryVLA 7B+0.3B、Mem-0 8B+2B），文中虽强调效率，但未深入讨论规模与性能的权衡曲线。
