## 摘要
机器人操控是一项复杂的任务，需要视觉理解、物理推理、规划与闭环控制。通用基础模型（FMs）在其中某些方面已经变得非常强大，尤其是视觉与推理能力。为了将这些能力应用于通用机器人策略，现有方法通常通过在机器人数据上微调，使现有 FM 转化为能输出底层动作的视觉-语言-动作（VLA）模型。然而，由于可用于微调的数据和算力有限，VLA 模型往往比前沿的 FM 小几个数量级，这反过来又限制了它们的通用能力。受 FM 通过视觉界面操作软件的能力不断提升所启发，我们追问：相同的这种能力是否足以控制机器人？我们提出了 VIA（Visual Interface Agent for robot control，机器人控制的视觉界面智能体），一个将机器人控制重新定位为智能体任务的框架：由现成的 FM 驱动的智能体通过基于浏览器的 3D 界面操控机械臂，过程中它截取屏幕、发出直观指令、观察结果并进行调整。该智能体不进行任何机器人特定的微调，也无权访问任何特权状态信息：它只通过视觉输入进行感知，并通过一小组通用工具进行动作。VIA 继承了智能体的通用推理、闭环错误恢复以及基于观察进行规划和重新规划的能力。它在 Claude Code 和 Codex 上零样本完成了多样化的桌面操控任务套件。借助最强模型（Fable 5），它在三个 LIBERO-Goal 任务上达到了 96.7% 的成功率，并在一项长程彩虹拼装任务上达到了 100% 的成功率。性能随底层模型的规模与能力的提升而提升。这些结果表明，只要给定合适的界面，前沿智能体已经具备可直接迁移到机器人控制的技能：在某种意义上，你的编程或计算机使用智能体已经是一个潜在的机器人控制智能体。

## Abstract
Robot manipulation is a complex task that requires visual understanding, physical reasoning, planning, and closed-loop control. General-purpose foundation models (FMs) have grown remarkably capable of some of these, especially vision and reasoning. To leverage this for generalist robot policies, current methods typically involve converting existing FMs into vision-language-action (VLA) models by fine-tuning on robot data to output low-level actions. However, VLAs are often orders of magnitude smaller than frontier FMs given the limited data and compute available for fine-tuning, which in turn limits their general capability. Inspired by the growing ability of FMs to operate software through visual interfaces, we ask whether that same competence suffices to control a robot. We present VIA (Visual Interface Agent for robot control), a framework that recasts robot control as an agentic task: an off-the-shelf FM-powered agent drives a manipulator through a browser-based 3D interface by taking screenshots, issuing intuitive commands, observing the outcome, and adjusting. The agent receives no robot-specific fine-tuning and no access to privileged state information: it perceives visual input and acts through a small set of general tools. VIA inherits the agent's general reasoning, closed-loop error recovery, and ability to plan and re-plan from what it observes. It solves a diverse suite of tabletop manipulation tasks zero-shot with both Claude Code and Codex. With the strongest model (Fable 5) it achieves 96.7% success on three LIBERO-Goal tasks and 100% on a long-horizon rainbow assembly task. Performance improves with the scale and strength of the underlying model. These results suggest that frontier agents already possess skills that transfer directly to robot control given the right interface: your coding or computer-use agent is, in a sense, secretly a robot-control agent.

# VIA：面向机器人控制的视觉界面智能体 —— 论文总结

## 1. 核心问题与研究背景

- **核心瓶颈**：当前将基础模型（FMs）应用于通用机器人操控的主流方法是将其微调为视觉-语言-动作（VLA）模型（如 RT-2、π0、OpenVLA），直接输出底层动作。然而受限于机器人数据稀缺与算力开销，VLA 模型规模往往比前沿 FM 小数个数量级，导致其在物理推理、长程规划与泛化能力上明显落后于其底层 FM。
- **Code-as-Policies（CaP）路线局限**：通过让 FM 编写调用感知 API 与预定义技能原语的代码，虽利用了 FM 的代码能力，但 FM 并不直接感知真实场景，且系统性能高度依赖人工设计的感知/控制抽象层（物体检测器、姿态估计器、手工技能原语），一旦高阶原语被替换为低阶操作，成功率会急剧下降。
- **关键假设与动机**：受 FM 通过视觉界面操控软件的能力（computer-use agents）启发，作者提出核心问题——只要提供合适的视觉接口与人类可读的工具，**现成的通用智能体能否无需任何机器人特定适应即可控制机械臂？**
- **论文核心定位**：将机器人控制重新定义为一种"视觉智能体任务"，把机器人当作另一个可被操作的应用程序，从而直接受益于前沿 coding / computer-use agent 在感知、推理、规划、闭环纠错上的全部能力。

## 2. 方法论

### 2.1 整体思路

- 构建一个**浏览器内 3D 机器人控制界面**，让通用 FM 智能体只通过"截图 + 通用 MCP 工具"的闭环循环完成操控，**零微调、零特权状态**。

### 2.2 视觉界面（Section 3.1）

- 基于多路已标定 RGB-D 相机重建的 **3D 点云**作为主工作区，搭配 Blender/3D 游戏风格的可交互可视化层，便于利用 FM 在 3D 设计软件上的先验知识。
- 左侧并排显示**第三人称俯视相机**与**腕部相机**两个实时图像流，分别用于全局场景理解与精细操作观察。
- 智能体通过**截取整个 UI 截图**来观察，**绝不直接读取点云原始向量**——观察方式与人类操作 Blender 时完全一致。

### 2.3 6-DoF 目标夹爪 + 航点（Waypoint）控制

- 场景中有一个**蓝色虚拟目标夹爪（target gripper）**，通过鼠标点击/拖拽或键盘精确输入，可将其位姿（位置 + 朝向 + 开/闭）调整为期望的 6-DoF 目标。
- 一次 `execute_waypoint()` 调用，会触发一个简单 PI 控制器，使真实夹爪沿直线插补到该目标姿态，且保持物理约束。
- 智能体通过多轮 "Operate → Execute → Repeat" 闭环完成任务（详见 Fig.2 中打开抽屉任务的示例）。

### 2.4 MCP 工具集（Section 3.2，Table 1）

按四大类组织，强调**极简主义**与**智能体人体工学**：

- **观察类（Observation）**：`screenshot`（全 UI 截图）、`hover(u,v)`（在 (u,v) 显示十字光标并返回该点在点云中的 3D 坐标，用于点击前预检或读取关注点坐标）、`gripper_get_pose`、`gripper_show_rotation_gizmo`（叠加旋转 gizmo，帮助智能体理解旋转方向）、`camera_get_pose`。
- **动作类（Action）**：`gripper_teleport_via_click`（在点云或相机画面上点击，"快速" 将夹爪移至关注点附近——沿当前接近轴后退约 0.07 m）、`gripper_drag`（带可选 x/y/z 锁定沿机器人坐标系拖动）、`gripper_translate`（按精确米制偏移平移，单次偏移限 ±0.1 m）、`gripper_advance_or_retreat`（沿当前接近轴前进/后退，每步约 0.006 m）、`gripper_rotate`（绕 gizmo 轴精确旋转 ±90°，推荐小步 10–45°）、`gripper_toggle`（单独开/闭夹爪，禁止与位姿变化并入同一 waypoint）、`gripper_reset`。
- **相机类（Camera）**：`camera_orbit_via_key`、`camera_pan_via_key`、`camera_zoom(u,v)`、`camera_reset`。
- **执行类（Execution）**：`execute_waypoint`、`end_episode`。
- **设计原则**：(i) 每个工具都是对人类鼠标/键盘操作的最小封装，不引入额外抽象；(ii) 由于智能体只能通过离散截图观察，原本依赖连续拖拽的 gizmo 旋转、相机轨道等操作被改造为接受精确角度/距离键入的版本，便于 agent 推理。

### 2.5 智能体驱动与提示（Section 3.3, 3.4）

- 直接使用 **Claude Code（CC）** 与 **Codex** 两个现成的 coding agent 作为通用视觉 agent——作者强调选用它们只是因为它们是最易用、封装了最强模型的智能体，并非为了 Code-as-Policies。
- 借助 MCP 协议通信，由 agent 自主管理上下文与历史，继承其长程规划能力。
- 仅提供一段约 **650 词的系统提示**（见 Appendix B.1），涵盖接口基础、任务分解、闭环验证与常见失败模式（如夹得太高）。
- **每条任务指令有两种变体**：
  - **Minimal prompt**：仅陈述目标与成功条件，测试零样本能力。
  - **Detailed prompt**：在三个 LIBERO-Goal 任务上额外提供一份"示例航点列表"（纯文本/Markdown 形式，而非遥操轨迹），用于展示文本示范对性能的提升。
- **扩展方向**：(1) 利用 agent 自身的代码能力进行**自动工具改进**；(2) 通过文本/多模态反思进行**不更新权重的学习**，作者演示通过任务特定 prompt 即可显著提升性能。

### 2.6 与已有范式对比

- **相对 VLA**：无需微调，从而避免微调对 FM 通用能力的灾难性遗忘，并且能够随 frontier agent 升级而直接受益。
- **相对 CaP**：不提供任何感知或技能原语，仅暴露**通用 6-DoF 航点 + 原始传感器视图**，将感知与推理尽可能下放给 FM。按 Fu et al. (2026) 的抽象层级划分，VIA 处于其最低抽象级之下。
- **相对 computer-use agents**：仅把机器人包装为 agent 可操作的"另一个应用"，所有 computer-use 上的进展可直接迁移到机器人控制。

## 3. 实验设计

### 3.1 数据集 / 场景

全部基于 **robosuite 仿真器**，包含 6 个桌面操控任务（Fig.3）：

| 任务 | 来源 | 考察能力 |
|---|---|---|
| Stack（红方块叠到绿方块上）| robosuite | 基础 pick-and-place |
| Turn on stove（旋转炉灶旋钮 90°）| LIBERO-Goal | 关节物体操控 |
| Open drawer（打开 3 抽柜中间一格）| LIBERO-Goal | 精度与拉拽 |
| Put bowl on plate（碗放到盘子正中央）| LIBERO-Goal | 物理推理 + 高精度放置 |
| Rainbow（7 个不同色块排成彩虹）| 作者自建 | 长程多物体组装与规划 |
| T-block（用 3 块积木搭 T 形）| BuilderBench 复现 | 物理拼图 + 精度（约 8 mm 容差）|

- 成功判定：除 Rainbow 由人工视觉判定外，其余均使用二元成功检测器。
- Rainbow 与 Stack 为无内置成功检测的任务，前者由人类评判最终排列，后者由 robosuite 检测叠放完成。

### 3.2 对比方法

论文为 agent × 模型 × prompt 三维配置实验，**没有与 VLA、CaP、其他学习策略做直接对比**，而是横向对照不同代理/模型/提示词的效果：

- **代理**：Claude Code、Codex
- **模型**：CC-Opus（Opus 4.8）、CC-Fable（Fable 5）、Codex-5.5（GPT-5.5）、Codex-5.6-Sol（GPT-5.6-Sol）
- **推理档**：所有 agent 运行在 `xhigh` 推理档
- **提示词**：Minimal / Detailed 两种变体

### 3.3 评估协议

- 每个 (agent, model, prompt, task) 组合在 **10 个种子**（含初始物体位姿随机化）下评估。
- 单次 episode 上限 **1 小时**（包含模型推理与图像传输），但绝大多数任务在远小于此时间内完成。
- 除非特别说明，**禁止 memory 读写**，杜绝跨 episode 经验积累。

## 4. 资源与算力

- 论文**未给出训练时长或 GPU 型号/数量**，因为 VIA 不进行任何模型微调或训练，所有推理都通过商业模型 API 完成。
- 显式给出的"算力"指标是**单次成功 episode 的 API 费用**（Table 4）：多数任务几美元一次 episode，整体均值 **Codex-5.6-Sol $4.1 < Codex-5.5 $7.2 < CC-Opus $9.5 < CC-Fable $15.1**。即在商业 API 计费下，最强前沿模型也更昂贵。
- 论文还报告了**平均工具调用次数**（Table 3）作为"算力"的间接代理——CC-Fable 多用调用换取更高成功率，Codex 因**激进的上下文自动压缩**而成本更低。

## 5. 实验数量与充分性

- **充分性表现**：
  - 横向上覆盖 agent（2）× 模型（4，含 2 个 Codex 与 2 个 CC）× 提示词变体（最多 2）× 任务（6）× 种子（10）= 数百次 episode。
  - 在 LIBERO-Goal 的 3 个任务上专门进行"详细提示 vs 最小提示"的消融，体现文本示范效果（CC-Opus 由 77% 提升至 100%）。
  - 在 Stack、Open drawer 等任务上做了几乎"逐种子"的定性分析（agent 会因初始分布选择从左到右或从右到左拼彩虹）。
- **可能的不足**：
  - **没有与 VLA（如 π0、OpenVLA、Diffusion Policy）或 CaP 类基线在同一任务上做对照实验**，因此"零样本即可超越微调策略"这一强结论缺少直接定量比较支撑；
  - Rainbow 与 T-block 未在 Codex 下做 detailed prompt 实验（表内标记为 `–`），覆盖略不完整；
  - 评测全部在 robosuite 仿真器中完成，**未包含真实机器人实验**。

## 6. 主要结论与发现

1. **零样本可解性**：在最小提示下，VIA 在六任务上的平均成功率为 **60%（Codex-5.5）–88%（CC-Fable）**，证明通用 FM agent 在合适接口下可直接迁移为机器人策略。
2. **强模型强表现**：CC-Fable 在 3 个 LIBERO-Goal 任务上达到 **96.7%**（29/30 seed 成功，唯一的失败再多拉几厘米即可成功），并以**最小提示**就追平了 CC-Opus 用 detailed prompt 才取得的成绩；其在 7 块积木的长程 Rainbow 任务上达到 **100%**。
3. **文本示范有效**：在 LIBERO-Goal 上，提供一份纯文本形式的航点示例即可将 CC-Opus 从 77% 提到 100%，但 Codex-5.5 并未受益。
4. **能力按模型规模 scaling**：CC-Opus→Fable 在所有任务上均提升；GPT-5.5→5.6-Sol 在 Put bowl on plate 上从 40% 倍增至 80%。更强模型意味着更少提示工程。
5. **规划行为可观察**：agent 在 Rainbow 中会先估算每块积木位置，按最少移动次数选择拼装顺序，有时从左到右，有时从右到左。
6. **T-block 仍是难点**：仅 10–40%，因为策略需正确识别"将底块旋转 45° 以增大支撑面"并且要保证 ≤ 8 mm 精度放置。
7. **效率与成本**：Codex 因上下文自动压缩更省钱；CC-Fable 用更多调用换更高成功率；总体单次成功 episode 成本几美元。
8. **可自然扩展**：通过 agent 自身推理实现"自动工具改进"与"基于反思的提示优化"，是低成本的学习路径。

## 7. 优点 / 亮点

- **范式新颖**：把机器人控制明示地重定义为"computer-use 任务的特例"，打通两条原本独立的研究线（agent 与机器人控制），并直接受益于前沿 agent 的持续升级。
- **完全无需机器人微调**：避免 VLA 微调对 FM 通用能力的灾难性遗忘，同时解耦算力/数据瓶颈与基础模型能力之间错位的扩展限制。
- **接口与工具以"人类可读"为锚**：直接对应 Blender/3D 游戏/遥操接口，使 agent 直接迁移其在大量 3D 软件上的先验；MCP 工具采用最小抽象 + 离散截图友好的精确键入，体现极强的"agent ergonomics"意识。
- **充分利用闭环纠错与可重规划**：每个工具调用后都返回新截图，agent 借此反复验证并修正，而不是 open-loop 执行。
- **实验设计相对均衡**：横跨 4 种主流前沿模型 × 6 类能力差异显著的任务 × 2 种提示词变体，给出成功率、调用次数、API 费用三维指标，并结合定性观察（如 Rainbow 的拼装方向选择）。
- **展示文本示范等同于演示数据**：纯 Markdown 航点示例即可显著提升性能，为低成本"数据"生成与自动提示优化打开空间。
- **接口本身借鉴了已发表的人用遥操 UI**（SPHINX, Sundaresan et al. 2025），具备迁移到真实机器人数据采集与重置场景的潜力。

## 8. 不足与局限

- **算力与延迟依赖 frontier 模型**：推理慢且贵，限制了在动态任务（如接球）上的适用性，目前仅适合准静态任务。作者亦明确承认，需等待更小、更便宜的 FM 成熟才能降低门槛。
- **缺少与 VLA / Diffusion Policy / CaP 的定量对比**：在相同 6 个任务上没有给出 baseline 数字，"前沿 agent 已可取代微调策略"的强结论缺少数值支撑，仅为定性论证。
- **仅在 robosuite 仿真中评估**：与真实世界的差距未验证；论文仅在 Future Work 中提到"扩展到真实机器人"是首要下一步。
- **精度上限**：在高精度任务（T-block，约 8 mm 容差）上仅 10–40%，说明当前控制器（PI + 线性插补）过粗，作者也呼吁更精密的控制器。
- **Rainbow 任务依赖人工评判**：成功判定存在主观性，且作者在文中坦承 Rainbow 对典型学习策略而言需"上千底层步骤"，但并未与这类策略同台对比以定量展现 VIA 的优势。
- **实验覆盖略有缺口**：Codex 在 Rainbow 与 T-block 上未评估 detailed prompt；不同任务仅给出 10 个种子的统计，方差信息不完整（未提供置信区间）。
- **MCP 工具集仍偏人类 GUI 风格**：部分工具（如 `gripper_drag` 的 (u,v)→(u,v) 拖拽）需要智能体在像素空间精确推理，对小模型并不友好，这与其"agent ergonomics"主张之间存在张力，论文未做更细的失败案例分析。
- **安全与工程约束未深入讨论**：例如急停、碰撞检测、腕相机遮挡等实际部署时绕不开的问题，仅在 Future Work 中一笔带过。
- **论文中提到 Claude Fable 5/Opus 4.8、GPT-5.5/5.6-Sol 等模型为 2026 年发布的虚构/前瞻性模型**（论文 arXiv 日期为 2026-07-13），读者在评估其工程实用性时需结合当下真实可用模型。
