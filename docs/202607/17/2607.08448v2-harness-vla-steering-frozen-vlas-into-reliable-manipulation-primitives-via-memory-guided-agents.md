## 摘要
以语言为条件的操作既需要精确的接触丰富控制，也需要对语言、场景和长时段进行鲁棒推理。端到端的视觉-语言-动作（VLA）模型具备强大的局部视觉运动技能，但它们基于分布内任务轨迹训练，在部署扰动（如语义重定向、目标重新绑定、空间布局变化以及不稳定的局部接触）下常常失效。LLM编码智能体提供了互补的语义和组合推理能力，但纯分析性基元在处理不规则抓取、受限放置以及关节物体交互时表现欠佳。我们提出了Harness VLA，一个记忆增强的智能体框架，它将一个冻结的VLA暴露为可重试的接触丰富基元，并将其与一个小型固定的分析基元库（包括落位、暂存、运输、导航和释放）组合在一起。框架不扩展技能库，而是从任务特定的执行轨迹、全局成功规则和失败模型中学习这些固定基元的操作范围。通过将语义重新落位、非接触执行和VLA再暂存提升至规划器层面，同时将冻结的VLA保留用于局部接触丰富阶段，Harness VLA无需微调即可将预训练VLA扩展到其原始轨迹分布之外。在受扰动的桌面、家庭厨房以及从整洁到随机化的双手操作测试中，Harness VLA相较于最强相关基线，在LIBERO-Pro和RoboCasa365上分别提升了38.6和25.4个百分点，并在RoboTwin C2R上达到了58.4%。

## Abstract
Language-conditioned manipulation requires both precise contact-rich control and robust reasoning over language, scenes, and long horizons. End-to-end Vision-Language-Action (VLA) models provide strong local visuomotor skills, but they are trained on in-distribution task trajectories and often fail under deployment perturbations such as semantic retargeting, goal re-binding, spatial-layout shifts, and unstable local contacts. LLM coding agents provide complementary semantic and compositional reasoning, but purely analytic primitives struggle with irregular grasping, constrained placement, and articulated-object interaction. We present Harness VLA, a memory-augmented agentic framework that exposes a frozen VLA as a retryable contact-rich primitive and composes it with a small fixed library of analytic primitives for grounding, staging, transport, navigation, and release. Rather than expanding the skill library, the harness learns the operating range of these fixed primitives from task-specific execution traces, global success rules, and failure models. By lifting semantic re-grounding, non-contact execution, and VLA re-staging to the planner while reserving the frozen VLA for local contact-rich phases, Harness VLA extends pretrained VLAs beyond their original trajectory distribution without finetuning. Across perturbed tabletop, household kitchen, and clean-to-randomized bimanual manipulation, Harness VLA improves over the strongest relevant baselines by 38.6 and 25.4 percentage points on LIBERO-Pro and RoboCasa365, respectively, and reaches 58.4% on RoboTwin C2R.

# Harness VLA 论文详细总结

## 一、核心问题与研究动机

- **语言条件操控的两难困境**：机器人操控任务同时需要**精确的接触密集控制**（不规则抓取、关节物体操作）以及**长视野的语言/场景推理**（语义绑定、目标重定向、空间布局适应），端到端方案难以兼得。
- **端到端 VLA 模型的局限**：π0、π0.5、OpenVLA、AtomVLA 等模型在分布内轨迹上训练后，对指令重定向（T）、位置交换（S）等部署扰动非常敏感——语言通道近乎"装饰性"，模型倾向于重复训练时的行为而非跟随新指令，单次接触失败即可导致整个回合崩溃（详见 LIBERO-Pro 上多数 VLA 接近 0% 成功率）。
- **LLM 编码智能体的局限**：Code-as-Policies、ProgPrompt、Cap-X 等依赖分析基元（IK、夹爪控制），可处理语义与组合推理，但在不规则抓取、受限放置、关节物体交互上力不从心；通常需要持续扩展技能库。
- **核心洞察**：接触操作时用 VLA，语义推理、长视野组合、非接触执行交由 LLM 规划器；预训练 VLA 不需微调也能"超越"原始轨迹分布。

## 二、方法论

### 2.1 总体思路：非对称层级架构
- 把**冻结的 VLA 封装为单一的可重试接触基元 `VLA ACT`**，与一组**固定的分析基元库**（`MOVE TO`、`MOVE POSE`、`ROTATE WRIST/PITCH`、`SET GRIPPER`、`RELEASE`、`NAVIGATE TO`、`MOVE BASE`）组合，由 LLM 智能体主导调用。
- **不扩展技能库**，而是通过执行轨迹学习每个固定基元的"操作边界"——何时调用 VLA、何时调用分析控制器、失败后如何重新暂存。

### 2.2 关键组件
- **统一基元接口**：每个基元以 JSON 对象调用，在环境中执行至内部后置条件满足后返回，刷新 RGB-D 与机器人状态。规划器只输出 JSON，不直接输出底层动作。
- **文件中介的 REPL 协议**：环境 worker 拥有模拟器状态，规划器只通过 `command.json`、`state_NN.json`、`log_NN.json`、`done_NN.flag` 等文件交互，使回放可审计、规划器无法访问特权状态。
- **两层记忆**：
  - **Task Specific Memory**：单个参考种子（seed 0）上自举得到的 JSONL 程序轨迹 + JSON 语义摘要（策略、避坑提示），所有空间坐标被替换为符号化感知查询以便在新布局中重新定位。
  - **Global Memory**：跨任务的成功规则（如"使用完整任务指令构造 VLA 提示"）与失败模型（如"空抓检测""虚假成功检测""不稳定暂存"），防止已知错误重复。
- **两阶段生命周期**：
  - **探索自举阶段**：在参考种子上仅一次自由探索（含 RESET、宽裕时间预算），将成功轨迹写入 Task Specific Memory，泛化经验蒸馏到 Global Memory。
  - **严格评估阶段**：禁用 RESET、压缩步数预算；规划器检索 Task Specific Memory 作为结构先验，并用当前 RGB-D 实时重新落地所有几何坐标。

### 2.3 算法流程（文字描述）
1. 读取 `command.json` 槽位 + RGB-D + 任务语言 + Task Specific Memory + Global Memory。
2. 多模态 LLM 输出**单个 JSON 基元调用** `ct ∈ P`。
3. 物理引擎执行至后置条件，返回新观测 `o_{t+1}`。
4. 将本步诊断结果（成功/可恢复失败/不可恢复）即时回写记忆。
5. 循环至目标谓词满足或预算耗尽。

### 2.4 VLA ACT 的特别设计
- 输入：任务条件提示 + 实时相机图像；输出：动作块；可配置早停谓词 τ 与动作块预算。
- 由规划器**暂存**（用分析基元把机器人先放到有利姿态）后再调用，而非一次性黑盒。
- 接触失败可在本地重试，不中断整条轨迹。

## 三、实验设计

### 3.1 基准套件（四类）
- **LIBERO**（标准桌面套件 SPATIAL/OBJECT/GOAL/LIBERO-10）：40 任务 ×10 种子 = 400 次回放。
- **LIBERO-Pro**（同一任务族下的指令重定向 T 与位置交换 S 扰动）：80 单元 ×10 种子 = 800 次回放。
- **RoboCasa365**（厨房规模、家居、关节物体、复合长视野任务，target50 split）：340 次回放。
- **RoboTwin C2R**（双臂洁净→随机化迁移）：50 任务 ×5 种子 = 250 次回放。

### 3.2 基线对比
- **标准 LIBERO**：OpenVLA、NORA、π0、AtomVLA、πRLinf（冻结 VLA 直接基线）。
- **LIBERO-Pro**：在指令重定向/位置交换扰动下，涵盖 OpenVLA、π0、π0.5、NORA、MolmoAct、X-VLA、AtomVLA、Cap-X、RATS、最强冻结 VLA πRLinf。
- **RoboCasa365**：π0、π0.5、WorldDreamer、RLDX-1（冻结 VLA 基线）。
- **RoboTwin C2R**：GR00T-N1.7、π0.5、StarVLA、LingBot-VLA（同时也是 Harness VLA 的冻结后端）。

### 3.3 评估协议
- **少样本**：在 seed 0 上自举任务特定记忆，评估于 s1–s10（RoboCasa365 中两个复合 split 使用 s1–s5）。
- **零样本**：分两子类——(i) LIBERO-Pro Goal 的"无任务记忆"零样本对比；(ii) RoboTwin C2R 的"洁净→随机化"迁移（清洁种子获得记忆，随机设置直接回放，不允许在随机侧重新自举或微调）。

- **公平性细节**：

  - 全程无微调、无部署时技能扩展。

## 六、主要结论与发现

- **LIBERO 标准套件**：Harness VLA（CC）取得 96.0% 总成功率（O BJECT 100%、LIBERO-10 93%），与冻结 VLA πRLinf（95.3%）保持竞争力。
- **LIBERO-Pro（关键提升）**：在指令重定向与位置交换扰动下，总成功率从 πRLinf 的 50.0% 提升到 Harness VLA（CC）的 82.4%，相较最强基线 RATS（43.8%）提升 **38.6 个百分点**。
- **RoboCasa365**：相对 RLDX-1（30.0%）提升 **25.4 个百分点**，达到 Codex 实例的 55.4% 与 CC 实例的 48.6%。
- **RoboTwin C2R**：相对 LingBot-VLA 直评（50.4%）进一步提升至 **58.4%**；零样本对比 LIBERO-Pro Goal 在指令重定向下 79.0%（Cap-X 仅 16.8%），位置交换下 31.0%（Cap-X 25.6%）。
- **机制发现**：
  1. 规划器级语义重新落地让同一冻结 VLA 在扰动下沿用新指令行为。
  2. 同一 `VLA ACT` 多次规划驱动调用显著优于一次性黑盒（即使少量调用即超过冻结基线）。
  3. 分析基元主导运输/暂存/释放，VLA 主导接触阶段，二者按环境自适应分配（LIBERO 84.2% 分析 vs 15.8% VLA；RoboTwin 52.6% vs 47.4%；RoboCasa 64.7% vs 35.3%）。

## 七、方法与实验的亮点

- **不微调前提下扩展 VLA**：通过规划器侧的语义重新绑定 + 空间重新落位，把冻结 VLA 的能力边界外推到训练分布之外。
- **固定小基元库的"会学习使用它"的范式**：与持续扩库（如 ASPIRE）形成互补，证明仅靠记忆引导的组合即可获得大幅鲁棒性。
- **工程上可审计的 REPL 协议**：以文件为唯一接口，便于回放、调试与人审，便于与不同 LLM 骨干即插即用。
- **跨基准统一抽象**：异构 VLA（πRLinf/RLDX-1/LingBot-VLA）封装为同一 `VLA ACT`，便于在不同 embodiment 间复用 Harness。
- **机制分析层次清晰**：调用-成功率曲线 + 任务完成归因 + 案例帧序列三层证据支撑"分工假说"。
- **零样本与少样本双视角对比**：能区分"在线规划器推理"和"任务级记忆"各自的贡献。

## 八、不足与局限

- **高低层之间的开放反馈回路**：规划器与低层 VLA 之间目前通过文本/JSON 弱耦合，缺乏在线强化学习或偏好对齐来闭环精调。
- **缺乏环境奖励/人类偏好的联合微调**：作者明确点出未来需要 GRPO 等样本高效 RL。
- **缺少细粒度图像描述**：在高度杂乱的长视野场景中，结构化推理受限。
- **少样本记忆依赖 seed 0 的可行性**：若参考种子本身就不可解，记忆为空，迁移上限受限；任务级记忆的可重复性与质量未给出统计误差。
- **专家种子筛选偏差**：RoboTwin C2R 中任务实例经过"专家验证"以保证可行，可能高估方法的真实泛化边界。
- **环境对比仍有限**：未覆盖真实硬件、移动操作（如人形）、动态障碍、长程语言对话型任务。
- **算力与训练成本不透明**：未公布 LLM/VLA 推理侧的硬件与时延数据，难以评估实际部署成本。
- **闭源 LLM 骨干依赖**：Codex/Claude Code 为黑箱，规划器的决策可解释性仍受限于提示工程与 LLM 输出稳定性。
