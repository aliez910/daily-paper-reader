## 摘要
机器人操控是一项复杂任务，需要视觉理解、物理推理、规划以及闭环控制。通用基础模型（FMs）在其中一些能力上已变得相当出色，尤其是视觉和推理方面。为了将其应用于通用机器人策略，现有方法通常通过对机器人数据进行微调，将既有基础模型转化为视觉-语言-动作（VLA）模型以输出底层动作。然而，鉴于微调所能使用的数据和算力有限，VLA 模型的规模往往比前沿基础模型小数个数量级，这反过来又限制了其通用能力。受基础模型通过视觉界面操作软件的能力日益增强的启发，我们提出这样一个问题：同样的能力是否足以控制机器人？本文提出 VIA（用于机器人控制的视觉界面智能体），一个将机器人控制重构为智能体任务的框架：一个开箱即用的、由基础模型驱动的智能体通过基于浏览器的三维界面操控机械臂，具体方式是截取屏幕、发出直观指令、观察结果并进行调整。该智能体不进行任何针对机器人的微调，也不访问特权状态信息：它通过视觉输入进行感知，并通过一小组通用工具执行动作。VIA 继承了智能体所具备的通用推理、闭环错误恢复以及基于观察进行规划和重新规划的能力。它在 Claude Code 和 Codex 上零样本解决了多种桌面操控任务。借助最强的模型（Fable 5），它在三个 LIBERO-Goal 任务上取得了 96.7% 的成功率，并在一项长时程彩虹组装任务上达到了 100%。性能随底层模型的规模和能力而提升。这些结果表明，前沿智能体已具备只需合适接口即可直接迁移到机器人控制的技能：你的编程或计算机使用智能体，从某种意义上说，本身就是一个机器人控制智能体。

## Abstract
Robot manipulation is a complex task that requires visual understanding, physical reasoning, planning, and closed-loop control. General-purpose foundation models (FMs) have grown remarkably capable of some of these, especially vision and reasoning. To leverage this for generalist robot policies, current methods typically involve converting existing FMs into vision-language-action (VLA) models by fine-tuning on robot data to output low-level actions. However, VLAs are often orders of magnitude smaller than frontier FMs given the limited data and compute available for fine-tuning, which in turn limits their general capability. Inspired by the growing ability of FMs to operate software through visual interfaces, we ask whether that same competence suffices to control a robot. We present VIA (Visual Interface Agent for robot control), a framework that recasts robot control as an agentic task: an off-the-shelf FM-powered agent drives a manipulator through a browser-based 3D interface by taking screenshots, issuing intuitive commands, observing the outcome, and adjusting. The agent receives no robot-specific fine-tuning and no access to privileged state information: it perceives visual input and acts through a small set of general tools. VIA inherits the agent's general reasoning, closed-loop error recovery, and ability to plan and re-plan from what it observes. It solves a diverse suite of tabletop manipulation tasks zero-shot with both Claude Code and Codex. With the strongest model (Fable 5) it achieves 96.7% success on three LIBERO-Goal tasks and 100% on a long-horizon rainbow assembly task. Performance improves with the scale and strength of the underlying model. These results suggest that frontier agents already possess skills that transfer directly to robot control given the right interface: your coding or computer-use agent is, in a sense, secretly a robot-control agent.

# VIA：用于机器人控制的视觉界面智能体 —— 论文总结

## 1. 核心问题与研究动机

- **核心问题**：通用机器人操控需要视觉理解、物理推理、长时程规划和精确的闭环控制。如何在**不依赖机器人专用微调**的前提下，让前沿基础模型（FMs）的能力直接迁移到机器人策略中？
- **背景与现状痛点**：
  - 当前主流路线是把视觉-语言模型（VLM）微调为视觉-语言-动作模型（VLA，如 RT-2、π0、OpenVLA）。但受限于机器人数据和算力，VLA 往往比前沿 FM 小**数个数量级**，物理推理和长时程规划能力受限，泛化能力也常弱于其基座 FM。
  - 另一条路线是 Code-as-Policies（CaP / ProgPrompt）：让 FM 生成代码调用感知 API 和人工设计的技能原语。但 FM 通常**不直接感知场景**，且系统被**人工设计的高层抽象**瓶颈化（Fu et al., 2026 表明替换为低层原语后成功率显著下降）。
- **本文假设**：随着 FM 已经能通过视觉界面操控软件（computer-use agents），同样的能力只要配上**合适的视觉接口和工具**，就能直接控制机器人。

## 2. 方法论

### 2.1 核心思想

将机器人控制重构为一个**智能体视觉任务**：开箱即用的 FM agent 通过浏览器 3D 界面操控机械臂——截屏观察→推理→发出直观指令→观察结果→调整，构成多轮 observe-act 闭环。**无需机器人微调、无特权状态信息**，所有感知由 FM 自身完成。

### 2.2 系统架构

- **视觉接口**：基于 RGB-D 相机重建的 3D 点云 + 第三人称 / 腕部两路原始相机画面，通过浏览器渲染（类似 Blender / 3D 游戏）。界面允许通过 orbit / pan / zoom 切换任意视角。
- **目标位姿控制**：界面中有一个"蓝色目标夹爪"，可通过鼠标点击点云传送、按键精确平移 / 旋转、gizmo 调整姿态，构成一个 6-DoF waypoint；满意后调用 `execute_waypoint` 由 PI 控制器将真实夹爪插值移动过去。
- **MCP 工具集**（共 14 个，按类别）：
  - **观察类**：`screenshot`、`hover(u,v)`（返回点击点 3D 坐标 + 十字准星预览）、`gripper_get_pose`、`gripper_show_rotation_gizmo`、`camera_get_pose`。
  - **动作类**（仅修改目标夹爪，不影响真机）：`gripper_teleport_via_click`、`gripper_drag`、`gripper_translate`、`gripper_advance_or_retreat`、`gripper_rotate`、`gripper_toggle`、`gripper_reset`。
  - **相机类**：`camera_orbit_via_key`、`camera_pan_via_key`、`camera_zoom(u,v)`、`camera_reset`。
  - **执行类**：`execute_waypoint`、`end_episode`。
- **设计原则**：极简化（每个工具尽量 1:1 封装人类操作）和智能体人体工学（把连续鼠标拖拽转为离散精确输入，因 agent 看的是离散截图）。
- **智能体驱动**：直接使用 Claude Code（CC）和 Codex，不针对机器人做任何特化；系统 prompt 仅约 650 字，涵盖接口基础、闭环验证、常见失败（如抓取过高）等。**不提供任何感知或技能原语**，所有视觉理解完全交给 FM agent。

### 2.3 算法流程（每回合）

1. **Operate**：agent 通过截图分析场景，连续调用动作 / 相机工具调整蓝色目标夹爪到期望位姿，每步工具调用后都返回新截图供验证。
2. **Execute**：调用 `execute_waypoint`，由 PI 控制器将真实夹爪插值移动到目标位姿。
3. **Repeat**：观察执行结果，必要时重新规划或重试，直到 `end_episode` 或达到 1 小时超时。

## 3. 实验设计

- **仿真环境**：robosuite 模拟器；所有任务桌面操作。
- **任务集（6 项）**：
  - **Stack**：robosuite，红方块放到绿方块上。
  - **Turn on stove**：LIBERO-Goal，旋转炉灶旋钮。
  - **Open drawer**：LIBERO-Goal，拉开中间抽屉。
  - **Put bowl on plate**：LIBERO-Goal，需精准抓取碗壁并对心放到盘子中心（仅 ~8 mm 容差）。
  - **Rainbow**：自建，把 7 个彩色块排成彩虹，测试长时程规划。
  - **T-block**：BuilderBench 复现，用 3 个同尺寸块搭 T 形，需物理推理。
- **评测方式**：除 Rainbow 由人工目视判定外，其余采用二值成功检测器。
- **Agent × 模型配置**：
  - Claude Code + Opus 4.8（CC-Opus）/ Fable 5（CC-Fable）
  - Codex + GPT-5.5 / GPT-5.6-Sol
  - 全部使用 xhigh 推理强度，禁用跨 episode 记忆。
- **Prompt 变体**：最小提示（仅任务目标和成功条件）和详细提示（附加示例 waypoint 列表）。每个配置 × 每个任务跑 **10 个 seed**，单 episode 上限 1 小时。
- **对比方法**：**无直接 baseline 对比**；隐式对比对象是 VLA（π0、OpenVLA 等）和 CaP（讨论中引用 Fu et al., 2026 等）。
- **评测指标**：成功率、平均 MCP 工具调用次数、估算 API 成本（美元）。

## 4. 资源与算力

- **训练算力**：**无**。本方法**不做任何微调**，全部依赖开箱即用 FM agent，故无 GPU 训练时长 / 数量等数据。

## 6. 主要结论与发现

- **零样本多任务通用**：在最小 prompt 下，平均成功率 60%（Codex-5.5）~ 88%（CC-Fable），证明现成 FM agent 直接迁移到机器人控制可行。
- **强模型结果突出**：CC-Fable 仅靠最小 prompt 在 LIBERO-Goal 三任务上达到 **96.7%**（29/30），其唯一失败因抽屉少拉了几厘米；Rainbow 长时程任务 **100%** 成功。
- **随模型能力提升而提升**：CC 从 Opus 4.8 升到 Fable 5，整体成功率 70% → 88%；Codex 在 Put bowl on plate 上 40% → 80%；趋势与 FM scaling 规律一致。
- **文本演示有效**：给 CC-Opus 加详细 waypoint 示例，LIBERO-Goal 任务从 77% 提升到 **100%**，但 Codex-5.5 未受益。
- **效率与成本**：Codex 普遍比 CC 便宜；CC-Fable 工具调用更少但单价更贵。
- **范式结论**：前沿 computer-use / coding agent "本质上就是" 机器人控制 agent；FM 在通用能力上的进步会自动迁移到机器人。

## 7. 优点与亮点

- **范式新颖**：把机器人控制彻底转化为 agentic 视觉任务，跳过 VLA 微调和 CaP 抽象层，思路简洁优雅。
- **极简工具 + 通用接口**：工具集仅 14 个，但保留了人类级别的自由度；点云 + 相机视图的设计类似 Blender / 3D 游戏，**契合 FM 训练分布**。
- **真正的零样本**：没有机器人数据微调、没有 prompt 中塞入的感知原语；甚至没有要求 FM "看穿"机器人栈。
- **可扩展性来源清晰**：成功直接归因于底层 FM / agent 的能力提升，自然继承 computer-use agent 在感知、推理、上下文管理、工具使用上的进展。
- **可解释与可调试**：每步工具调用都返回截图，便于人工回放失败原因；也允许 agent 自动反思（reflection）来优化 prompt。
- **通用闭环能力免费继承**：错误恢复、重规划、长时程记忆管理由 agent 框架自带提供。
- **多模型 / 多任务对照**：同时在 CC 与 Codex 上验证，增强了结论的泛化可信度。

## 8. 不足与局限

- **仅仿真验证**：全部实验在 robosuite 中，**未在真实机器人上部署**；真实世界的相机噪声、光照、延迟、物理不确定性均未触及。
- **依赖最强前沿模型**：当前需要 Claude Fable 5 / GPT-5.6 级别的能力才能稳定工作，**推理慢、成本高**（部分任务单次成功 episode 成本 > $30），不适合实时或大规模部署。
- **仅适合准静态任务**：由于 agent 是基于截图 + 离散工具调用的闭环，难以应对动态任务（如接球、跟踪移动目标）。
- **缺直接 baseline 对比**：未与 π0 / OpenVLA / CaP-X 等方法在同一任务集上做公平 head-to-head 比较，定量说服力受限。
- **评测偏差风险**：
  - Rainbow 任务人工目视判定；
  - "Open drawer" 文中指出 Codex 全部因抽屉拉得不够被判失败，若放宽条件数字会显著不同——评测标准对不同模型敏感；
  - 仅 10 seeds，统计置信区间未给出。
- **消融不充分**：未系统拆解各组件（如工具的 ergonomic 设计、点云 + 相机双视图、prompt 中的 "closed-loop verification" 提示）的贡献。
- **agent 失败模式未深入分析**：例如为什么 Codex 不从详细 prompt 受益、T-block 全部模型为何仅 10-40% 成功，文中以"精度不够"一笔带过。
- **可复现性受限**：依赖闭源前沿模型（Claude / GPT 内部版本）及其定价，未来模型升级或下架将难以复现结果。
- **生态依赖**：完全依赖 MCP 协议与特定 agent（Claude Code / Codex）的兼容性，绑定较重。
