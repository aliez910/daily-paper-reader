## 摘要
机器人操作策略依赖于预训练视觉模型，这些模型要么给出全局场景嵌入，要么给出密集的 patch 网格。两者都将任务相关特征与任务无关特征混在一起。以对象为中心的槽位表征是一种结构化的替代方案：它们将特征分组为少量的逐对象槽位。我们在 ManiSkill3 PickCube-v1 上测试这种结构能带来多大收益，采用冻结编码器并在留出的随机种子上进行评估。在固定策略、目标 token、渲染与标定，仅改变编码器的条件下，冻结的以对象为中心的 SPOT 表征（DINO ViT-B/16 + Slot Attention）达到了 55.0±2.9% 的成功率，比密集的 DINO 全局特征基线（32.6±1.5%）高出 22.4%，且可训练策略相同，无需对编码器进行微调。仅增加 token 数量并无帮助：拥有 16 倍 token 的密集 patch 网格表现并不优于全局特征。加入显式的二维空间目标与原生分辨率渲染后，整个系统提升至 68.7±4.2%，略低于特权三维 oracle 的上界（71.7±4.1%）。随后，一种自动化的运动学失败分类法将空间精度（Near-Miss，接近失误）失败与对象跟踪（No-Grasp，未抓取）失败区分开：空间定位减少了 Near-Miss，但 No-Grasp 不变。同样的分类法可迁移到更困难的 StackCube-v1，并指出遮挡是主要瓶颈。

## Abstract
Robotic manipulation policies rely on pre-trained vision models that give either a global scene embedding or a dense patch grid. Both mix task-relevant and task-irrelevant features. Object-centric slot representations are a structured alternative: they group features into a few per-object slots. We test what this structure buys on ManiSkill3 PickCube-v1, with a frozen encoder and a held-out-seed evaluation. Holding the policy, goal token, rendering, and calibration fixed and changing only the encoder, a frozen object-centric SPOT representation (DINO ViT-B/16 + Slot Attention) reaches 55.0$\pm$2.9% success, 22.4% above a dense DINO global-feature baseline (32.6 $\pm$ 1.5%), with the same trainable policy and no encoder fine-tuning. More tokens alone do not help: a dense patch grid with 16x the tokens performs no better than the global feature. Adding an explicit 2D spatial goal and native-resolution rendering raises the full system to 68.7$\pm$4.2%, just below a privileged 3D-oracle upper bound (71.7$\pm$4.1%). An automated kinematic failure taxonomy then separates spatial-precision (Near-Miss) failures from object-tracking (No-Grasp) failures: spatial grounding reduces Near-Miss while leaving No- Grasp unchanged. The same taxonomy transfers to the harder StackCube-v1 and points to occlusion as the main bottleneck.

# 论文总结：More Structure, Not More Capacity: Object-Centric Representations for Visuomotor Imitation Learning

## 1. 核心问题与整体含义

- **研究对象**：视觉运动模仿学习（visuomotor imitation learning）中视觉编码器的**表征结构**对策略泛化能力的影响。
- **问题背景**：现有机器人操控策略通常依赖预训练视觉模型（如 DINO）的两种典型输出——**全局场景嵌入（[CLS] token）**或**密集 patch 网格**。这两种表征都将任务相关与任务无关的特征混在一起，容易学到"捷径"（shortcut）：利用训练集共现线索（如背景、纹理、相对位置），一旦遇到训练时未见的物体/目标摆放位置便失效。
- **核心假设**：作者提出**"结构优于容量"**——在冻结编码器条件下，将特征压缩为少量以对象为中心的槽位（slot）所产生的结构化归纳偏置，比单纯增加 token 数量更能驱动对未见配置的泛化。
- **与同类工作的关联**：与图像分类中 ViT 寄存器机制、3D 感知跨域编码器、视线估计等"捷径学习"研究形成同一模式——解药在于**结构性干预**而非参数扩展。

## 2. 方法论

### 2.1 整体流程
- 双 RGB 相机（基座 + 侧视，224×224）→ 冻结 SPOT 编码器 → 14 个对象槽位 → 与本体感知、目标、动作 token 拼接 → 因果 Transformer 策略 → 动作块预测。

### 2.2 冻结的 SPOT 编码器
- **架构**：DINO ViT-B/16 主干 + Slot Attention 模块，组合为 SPOT（DINO 主干冻结，从 COCO 预训练权重中直接继承）。
- **核心机制**：将每视角 196 个 patch 压缩为 K=7 个对象槽位 $S \in \mathbb{R}^{7\times256}$；K=7 为公开发布检查点固定值，未做调参。
- **Slot Attention 公式**：
  - 相似度：$M_{i,j} = \frac{k(X_i) \cdot q(S_j)}{\sqrt{D}}$
  - 槽位维度 softmax 竞争：$W_{i,j} = \frac{\exp(M_{i,j})}{\sum_l \exp(M_{i,j})}$
  - 通过 GRU 更新：$S^{(t)} = \text{GRU}(S^{(t-1)}, W^\top v(X))$
- **关键点**：归一化在**槽位维度**而非 patch 维度，迫使每个 patch 强激活至多一个槽位，形成"对象级绑定"的硬瓶颈。
- 双相机各 7 个槽位拼接为 $S_{vis} \in \mathbb{R}^{14\times256}$。

### 2.3 Token 构造（每时间步 17 个 token）
- 14 个视觉槽位 token；
- 1 个本体感知 token（7-DoF 关节位置，经 MLP 编码）；
- 1 个目标 token（三种条件见下）；
- 1 个可学习的动作 token（用于读出）。

### 2.4 目标条件三种设定
- **Pure Visual**：无目标 token，策略仅靠视觉槽位；
- **2D Spatial Projection**：将 3D 目标经相机内外参投影到像素坐标 $g=[u_b, v_b, u_s, v_s] \in [0,1]^4$，3 层 MLP 编码（**依赖仿真器真实目标位置**，非自监督）；
- **3D Oracle**：直接读取仿真器 3D 世界坐标，作为**特权上界**。

### 2.5 因果 Transformer 策略
- 借用 LeRobot 中 VQ-BeT 的 minGPT 风格解码器，连续动作预测（无 VQ）；
- 8 层 8 头，隐藏维度 256，**下三角因果掩码**；
- 时间窗口 T=5 帧，共 85 token；
- 动作块 H=10 步，8 维（7 维关节 + 1 维夹爪），7 维 Z-score 归一化，夹爪用硬阶跃函数解码。

### 2.6 表示基线
- DINO Global [CLS]：每相机 1 token（共 2）；
- DINO 4×4 patches：每相机 16 token（共 32），空间子采样；
- DINO 14×14 dense：每相机 196 token（共 392），受显存限制被迫 T=1, H=1；
- Object-Centric (SPOT)：每相机 7 slot（共 14）。

## 3. 实验设计

### 3.1 数据集 / 仿真器
- **仿真平台**：ManiSkill3，physx_cpu 后端，**确定性强**。
- **主任务**：PickCube-v1（Franka Panda 抓红色方块并放置到随机 3D 目标）。
- **跨任务迁移测试**：StackCube-v1（红方块叠到绿方块上）。
- **演示数据**：仿真器运动规划器生成的 1000 条专家演示，重放成功率 100%。

### 3.2 评估协议（关键创新点）
- **留出种子（held-out seed）协议**：训练用种子 0–9999，评估用种子 ≥10000，两者**不相交**，测量对**新摆放位置**的泛化而非记忆；
- 每 50 epoch 保存一次检查点，扫 200 个留出集 episode 取最优；
- 最优检查点跑 3 次独立稳定性评估，各 300 episode，报告均值 ± 标准差；
- **剔除**少于 10 步结束的 episode（视为平凡成功）；
- 整组实验本质上是**冻结表征的"解码器探测"**：只训练轻量解码器，衡量表征中可被中等非线性解码器提取的任务信号。

### 3.3 对比方法
- **表征对比**：4 种（DINO Global / 4×4 / 14×14 dense / SPOT 槽位），固定策略、目标、渲染、标定；
- **融合策略对比**：token 拼接 vs 双向跨注意力（无目标 token 条件下）；
- **时间窗口对比**：T ∈ {5, 20, 40} 纯视觉条件下；
- **空间定位 + 分辨率消融**：5 档（纯视觉 / 2D 目标-近似标定-128² / 2D 目标-精确标定-128² / 2D 目标-精确标定-224² / 3D Oracle）；
- **跨任务**：StackCube-v1 应用同一架构与失败分类法。

### 3.4 自动化运动学失败分类法
- **不依赖视觉数据**，仅用动作方差、`is_grasped` 标志、TCP 到目标距离；
- 5 个互斥类别（按优先级）：Idle（动作方差低）、No-Grasp（未抓取）、Drop（抓后脱落）、Near-Miss（最小距离 <0.1 m 但放置失败）、Unknown；
- **编码器无关**，可直接跨任务、跨配置复用。

## 6. 主要结论与发现

- **核心结果**：在匹配条件下，冻结的 SPOT 槽位表征（14 token）取得 **55.0 ± 2.9%** 成功率，**比 DINO Global 基线高 22.4 个百分点**（32.6%），且与密集 4×4 patch（31.7%）相当；密集 14×14（392 token）因显存被砍为 T=1, H=1 而崩溃至 1.0%。
- **结构 vs 容量**：仅增加 token 数无济于事；结构化对象级绑定才是关键。
- **融合与时间维度均无帮助**：双向跨注意力训练时表现明显优于拼接（约 60% vs 38.6%），但留出集上**均为 31.0%**——额外参数在见过种子上拟合，**不迁移**到未见摆放。T ∈ {5, 20, 40} 成功率无差异。
- **空间定位 + 原生分辨率**：精确标定 224² 全系统达 **68.7 ± 4.2%**，接近 3D Oracle 上界 71.7 ± 4.1%。
- **失败诊断**：
  - Near-Miss（空间精度）失败随空间定位从 31% → 21% → 2.5%；
  - No-Grasp（对象跟踪）失败基本不变（15/15/24 episode），揭示**两种瓶颈需要不同修复**；
- **跨任务**：StackCube-v1 性能仅 5.3%，**No-Grasp 占 72%**——主因是机械臂遮挡下冻结 SPOT 无时间记忆，定位到**遮挡**为该任务主要瓶颈。

## 7. 优点与亮点

- **匹配条件控制严格**：策略、目标 token、渲染、标定都固定，只改变编码器——是真正"剥离表征变量"的实验设计；
- **留出种子协议**：避免评估与训练同分布，更接近真实部署；
- **冻结特征 + 轻量解码器**：契合小预算实践，可在 11 GB 单卡上完成；
- **自动化、可迁移的失败分类法**：提供比二元成功率更可操作的诊断信号，且**跨任务无需修改**；
- **清晰的工作流建议**：面向小预算实践者的具体处方（用对象中心槽位、token 拼接而非跨注意力、给策略显式空间锚点）；
- **与捷径学习文献的呼应**：把"ViT 全局监督下学到低频捷径"模式扩展到操控领域，提供跨设置的统一解释。

## 8. 不足与局限

- **遮挡下的槽位稳定性**：SPOT 无时序记忆，遮挡后无法恢复对象（StackCube 72% No-Grasp 即源于此）；
- **2D 目标非自监督**：依赖仿真器真实目标位置，未能从槽位掩码自推导，未来工作需要做；
- **融合对比不完整**：仅在无目标 token 的低性能条件下比较，未在有空间锚点时验证拼接是否仍优于跨注意力；
- **任务与场景覆盖单一**：仅 2 个 ManiSkill3 任务（且无视觉分布偏移测试），未涉及真实机器人或不同物体类别；
- **dense 14×14 崩溃的归因模糊**：因显存被迫 T=1、H=1，不能直接归为"token 数量"问题，作者虽已指出但仍可能造成阅读混淆；
- **数据规模有限**：1000 演示 + 3×300 episode 评估，结果的统计显著性受一定限制；
- **算力信息缺失**：未披露 GPU 型号、训练时长、收敛 epoch 数等可复现性细节；
- **小目标像素冲突**：128² 渲染下近距离时方块与目标共享像素单元，是 224² 提升的主因之一，提示渲染分辨率对精细操控有显著影响但未单独深入消融。
