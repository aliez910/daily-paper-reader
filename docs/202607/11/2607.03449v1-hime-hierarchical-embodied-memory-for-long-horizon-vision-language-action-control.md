## 摘要
当前的视觉-语言-动作（VLA）模型在机器人操控方面表现出色，但由于依赖即时观测，往往难以处理需要长期记忆与推理能力的非马尔可夫任务。现有解决方案面临"频率-能力悖论"：推理能力更强的模型对于实时控制而言过于缓慢，而更快的模型则缺乏足够的推理能力。为解决这种架构错位，我们提出了 HiMe，一种分层具身记忆框架，将具身智能解耦为用于执行的高频执行器（Executor）、用于工作记忆的哨兵（Sentry）以及用于长期策略的规划器（Planner）。我们还引入了一种基于跨模态语义模式与主动管理机制的动态知识系统，使机器人能够通过"添加、更新与删除"操作维持记忆的可塑性。这种分层设计有效平衡了实时执行与慢思考规划之间的冲突，显著提升了长时域任务的成功率。实验表明，该方法不仅优于扁平记忆基线，还展现出基于人类偏好自我修正内部知识的新颖能力。

## Abstract
Current Vision-Language-Action (VLA) models excel at robotic manipulation but often struggle with non-Markovian tasks requiring long-term memory and reasoning due to their reliance on immediate observations. Existing solutions face a ''frequency-competence paradox,'' where stronger reasoning models are too slow for real-time control, while faster models lack sufficient reasoning capabilities. To resolve this architectural misalignment, we propose HiMe, a Hierarchical Embodied Memory framework that decouples embodied intelligence into a high-frequency Executor for execution, a Sentry for working memory, and a Planner for long-term strategy. We also introduce a dynamic knowledge system based on cross-modal semantic schemas and active management mechanisms, allowing robots to maintain memory plasticity through ''Add, Update, and Delete'' operations. This hierarchical design effectively balances the conflict between real-time execution and slow thinking planning, significantly improving success rates in long-horizon tasks. Experiments demonstrate that this approach not only outperforms flat memory baselines but also exhibits the novel ability to self-correct its internal knowledge based on human preferences.

- **核心痛点**：当前主流 VLA 模型（如 π₀、OpenVLA）在机器人操控上表现优秀，但均建立在**马尔可夫假设**之上，即策略 π(aₜ|oₜ, l) 仅依赖当前瞬时观测 oₜ 和语言指令 l，无法维持对环境的持久信念。
- **非马尔可夫任务的瓶颈**：长时序任务（如"先检查盒子，再收集 Alice 的玩具"）需要追溯数百步之外的隐含信息，当前 VLA 模型难以胜任。
- **频率-能力悖论（Frequency-Competence Paradox）**：
  - **大模型路线**（如 LVLM 作为高层记忆容器）：推理强但延迟高，无法满足实时控制；
  - **小模型路线**（如直接在 VLA 内植入记忆模块）：速度快但泛化与推理不足，零样本能力差。
- **已有方案的不足**：训练式记忆受限于上下文窗口与长程因果依赖优化难度；被动式记忆则无法应对动态演化（用户偏好变化、环境状态更新）。

## 2. 方法论：HiMe 分层具身记忆框架

## 6. 主要结论与发现

- **整体性能**：HiMe 在三个任务上平均任务进度 **90%**，显著超越 Flat Memory（65%）和 Transient Memory（66%），逼近 Human Oracle（94%）。
- **Sentry 的双重价值**：
  - **一致性**：将任务切换频率从 14% 提升到 26%（即使在无记忆 Planner 上），避免视觉噪声引发的抖动切换；
  - **质量**：通过聚合工作记忆，平均任务进度从 68% 提升到 90%，减少 Planner 的幻觉重规划。
- **跨模态记忆的必要性**：
  - 纯图像记忆在 Object Search 占优（86% vs 74%），体现空间定位能力；
  - 纯文本记忆在 Counting 占优（91% vs 78%），体现语义逻辑能力；
  - 跨模态融合两者优势，平均 90%。
- **主动管理的必要性**：FIFO 仅 68%，无管理 86%，主动 CRUD 达 90%，说明**存储更多不等于更好**，需保持一致性与精简性。
- **效率优势**：HiMe 平均每个子目标仅 1.4–2.6 次 Planner 调用，相比 Flat Memory 的 4.8–85.4 次，**减少约 3 倍** API 调用；Memory Hit Rate 从 68% 提升至 92–98%。
- **新能力涌现**：当用户偏好冲突时，HiMe 能**自我修正内部知识库**（如将"Alice 喜欢玩具鸭"修正为"Lucy 喜欢毛绒玩具"），这是现有检索式方法不具备的能力。
- **可扩展性瓶颈**：多轮实验中随轮次增加（1→3 轮），任务进度从 92.5% 降至 66.7%，提示**长期一致性维护仍是挑战**。

- **用户研究缺乏**：自纠错能力仅展示个案，**缺乏系统化的人机交互实验**量化偏好冲突场景下的鲁棒性；
- **算力披露不足**：未明确报告训练总 GPU 时长与完整硬件清单，复现成本难以估算；
- **Sentry 保守性问题**：Recall 偏低（最长 8 帧下仅约 35%），固定间隔回退是工程折中而非根本解，可能在高动态任务中引入冗余；
- **执行器依赖**：低层 Executor 仍需任务级 fine-tuning（60 条示范），**未实现零样本跨任务迁移**；
- **未明确评估安全与失败恢复**：长时序任务中失败检测、恢复策略未系统讨论；
