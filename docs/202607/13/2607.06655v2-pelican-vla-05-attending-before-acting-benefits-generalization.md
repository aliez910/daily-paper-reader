## 摘要
在本报告中，我们提出了 Pelican-VLA 0.5，一个统一的 VLA 模型，在单一架构内集成了视觉-语言理解、未来帧生成与动作预测。Pelican-VLA 0.5 实现了注意力层面的泛化：在不使用目标标注、分割掩码、注意力监督或任务特定微调的情况下，其动作通路已能聚焦于与操作相关的物体及接触区域。这一行为在未见过的场景和未见过的机器人本体上仍然存在，并显著强于其他开源 VLA 基线方法。我们验证了该能力源自插入于感知与动作之间的可学习瓶颈令牌（Bottleneck Token）：通过将任务相关的视觉信息经由紧凑的瓶颈进行路由，令牌接口在预训练阶段诱导出以操作为中心的注意力，并在不同策略结构（包括 MoT 风格的架构）中持续有效。

## Abstract
In this report, we present Pelican-VLA 0.5, a unified VLA model that integrates vision-language understanding, future-frame generation, and action prediction within a single architecture. Pelican-VLA 0.5 achieves attention-level generalization: without object annotations, segmentation masks, attention supervision, or task-specific fine-tuning, its action pathway already focuses on the manipulation-relevant object and contact region. This behavior persists across unseen scenes and unseen robot embodiments, and is substantially stronger than in other open-source VLA baselines. We verify that this ability originates from the learnable Bottleneck Token inserted between perception and action: by routing task-relevant visual information through a compact bottleneck, the tokens interface induces manipulation-centric attention during pre-training and remains effective across different policy structures, including a MoT-style architecture.

## 1. 论文核心问题与整体含义

### 1.1 研究背景
- 视觉-语言-动作（Vision-Language-Action, VLA）模型是当前机器人通用操作的主流范式，其终极目标是让机器人在面对**新物体、新场景、新任务、新本体（embodiment）** 时仍能稳定执行指令。
- 当前主流 VLA 模型（π0、π0.5、OpenVLA、GR00T 等）在特定基准上表现良好，但**泛化能力**仍是核心瓶颈：在新环境中往往依赖任务专属数据采集与微调，难以真正零样本迁移。

### 1.2 核心问题
- 作者对代表性 VLA 模型的注意力图进行可视化分析后发现：现有模型的**动作通路（action pathway）注意力呈现弥漫扩散**状态——同时关注机械臂、背景、任务无关物体，未能稳定聚焦于"待操控目标"和"潜在接触区域"。
- 由此产生的核心问题：**VLA 模型能否在预训练阶段就自发形成"以操作为中心（manipulation-centric）"的注意力表征？是否能以此支撑真正的零样本泛化？**

### 1.3 整体含义
- 论文提出"**注意力级泛化（attention-level generalization）**"的概念，主张泛化能力不仅依赖底层动作轨迹拟合，更依赖于任务相关信息能否以**可迁移形式**被表征并有效路由到动作生成通路。
- 工作将"看什么（注意力）"与"怎么动（动作）"解耦，认为前者可在预训练中通过架构设计诱导，后者则仍需数据与微调支撑——这是迈向完全零样本 VLA 的**中间阶段**。

## 2. 方法论

### 2.1 核心思想
- **统一架构**：在单一共享 Transformer 主干（Qwen3-VL 4B）中同时实现 **视觉-语言理解 + 未来帧生成 + 动作预测**，而非采用双系统或 Mixture-of-Transformers 分离"推理专家"与"动作专家"。
- **关键设计：可学习 Bottleneck Tokens（BotTokens）**：在感知通路与动作通路之间插入 K=32 个可学习令牌，作为紧凑的**信息瓶颈接口**。动作后缀只能通过它们向上游视觉上下文读取信息，从而被"强迫"仅路由最相关的操控语义。

### 2.2 输入序列与注意力几何
- 输入被分为四个连续段：
  - **Prefix**：当前多视角（3 路 224×224）与语言指令，由 Qwen3-VL 编码得到视觉-语言 token（双向注意力）。
  - **Middle**：用冻结的 Cosmos-Tokenizer 提取近历史（t-15, t）的 Cosmos 潜变量，提供像素级与动力学信息。
  - **Bottleneck（S）**：K=32 个可学习 BotTokens，从 N(0, 0.02²) 初始化，并以 p=0.1 的 dropout 增强鲁棒性。
  - **Suffix**：本体状态 token + 经 MLP 融合正弦时间嵌入 τ 的 H=50 个含噪动作 token（流匹配用）。
- **关键掩码规则**：在 "硬瓶颈"模式下，强制移除后缀对所有 prefix/middle 视觉 token 的注意力边，仅保留后缀↔BotTokens 的通路，使所有感知到动作的信息流必须经 S。
- **课程式瓶颈掩码**：训练初期以较大概率保留直接注意力边，随训练步数 t 推进，硬瓶颈施加概率 pt = min(1, t / T_warm)，T_warm = 10k 步，逐渐收紧信息通路。

### 2.3 三重机制保障 BotTokens 有效
- **课程瓶颈掩码（Curriculum Bottleneck Mask）**：让优化从易到难稳定收敛。
- **正交性正则化（Orthogonality Regularizer）**：对 K 个 BotTokens 输出做 ℓ2 归一化后，惩罚 Gram 矩阵偏离单位阵的程度，避免它们坍缩为同方向，迫使其编码**互补**因素。
- **生成门控（Bottleneck-gated Generation）**：将 BotTokens 的均值池化特征送入通道级门 g = σ(W_g · z̄)，对中间段预测的生成特征逐通道调制，使 BotTokens 同时携带"动作相关 + 前瞻预测"双重信息。

### 2.4 多任务训练目标
- **动作流匹配损失** L_action：沿 τ∈U(0,1) 的线性插值轨迹构造含噪动作 x_τ，预测速度场 v_θ(Z)，目标为 ε−a。
- **未来帧生成损失** L_gen：在 Cosmos 潜空间预测 t+15 帧，损失权重 λ_gen = 0.01。
- **BotTokens-语言对比对齐损失** L_task：对称 InfoNCE，将轨迹嵌入（来自 BotTokens 输出均池化）与指令文本嵌入做 batch 内匹配，λ_task = 0.1；同指令样本的 off-diagonal 被屏蔽避免误负样本。
- **正则化损失** L_reg：上述正交性正则项，λ_reg = 0.01。
- 总目标：**L = L_action + λ_gen L_gen + λ_task L_task + λ_reg L_reg**。

### 2.5 缓存式推理
- Prefix/Middle KV 仅依赖视觉-语言上下文，与流时间 τ 无关，**只计算一次**。
- 进入流匹配 ODE 反向积分后，仅保留 K=32 个 BotTokens 的 KV 作为视觉缓存，丢弃 prefix/middle 缓存，N=10 步 Euler 反向积分 τ=1→0。
- 因此高频控制的开销只取决于后缀长度 + BotTokens 数量，而**非完整视觉上下文长度**。

## 3. 实验设计

### 3.1 数据集与场景
- **预训练数据**：超过 6000 小时的异构、跨本体机器人数据混合，包括 AgiBot World Alpha、InternData-A1、Galaxea Open-World Dataset，以及 ~1000 小时自采的 TienKung、UR 遥操作数据，全部通过 LeRobot 数据接口统一。
- **状态/动作维度统一**：所有本体的状态与动作向量均**填充至 32 维**，便于共享动作头训练；动作采用**关节位置空间**（非末端位姿）。
- **Sim 评估平台**：RoboTwin（含 Clean 设置与 Randomized 重随机化设置）+ RoboTwin 2.0（完全未参与预训练，用于零样本测试）。
- **Real 评估平台**：TienKung 人形机器人执行桌面清理任务。
- **跨度本体**：Franka、AgileX Aloha、TienKung、UR5e、AgiBot、Agilex Cobot Magic、RS-02 传送带等多种机器人。

### 3.2 Benchmark 与对比基线
- **RoboTwin 仿真基准**对比 π0[7]、π0.5[6]、X-VLA、StarVLA-OFT、ABot-M0、LingBot-VLA、Qwen-VLA、JoyAI-RA、Hy-VLA 等约 9 个开源 VLA 基线。
- **零样本设置**对比 X-VLA、GR00T N1.6、Being-H0.5、ABot-M0、π0.5、LingBot-VLA、RS-02 等。
- **架构隔离实验**：用相同数据/优化/参数量下训练的 dense MoT 基线作对照。

## 6. 主要结论与发现

### 6.1 现象层面的发现
- **"注意力级泛化"真实存在**：Pelican-VLA 0.5 在无任何目标级监督或任务微调的情况下，动作通路已能聚焦于操控目标与接触区域，且**可迁移到未见场景与未见本体**。
- 这种现象**强于开源 VLA 基线**（π0、π0.5、π0.5、GR00T N1.6、Being-H0.5、ABot-M0、LingBot-VLA、X-VLA 等注意力扩散）。

### 6.2 机制层面的归因
- 通过消融与架构对照，结论高度一致：**该现象由 BotTokens 介导的感知到动作路由方式决定**：
  - 未来帧损失与对比损失单独施加在 dense 模型上均不产生聚焦；
  - 一旦引入 BotTokens，操控中心注意力立即出现；
  - 移除 BotTokens 后该能力不完全消失，说明 BotTokens 将其**内化到了共享主干**。
- BotTokens 还可**迁移到 MoT 等其他策略结构**，并非 Pelican-VLA 专属。
- BotTokens + 对比损失的组合可在早期检查点产生**语言条件化**注意力（指令从"拿碗"改为"开抽屉"则焦点跟随物体改变），但该条件化会随训练推进变弱，作者把它归因于数据中"指令-动作"不匹配的噪声。

### 6.3 训练动态的发现
- 注意力演化呈**两阶段**：
  - 第一阶段：变得空间集中，但偏向机械臂/夹爪等操控者本体（IoU≈0.35，稳定）；
  - 第二阶段：对指令指定目标的对齐度单调上升，IoU 从 0.054 → 0.124，Spearman ρ=0.76（p=0.01）；
  - 该目标对齐在**动作损失饱和后仍持续上升**，说明并非简单由动作目标驱动。
- 微调前后注意力与 BotTokens 表示**高度相似**（相似度 > 0.9），微调主要强化"已形成的注意力→可执行动作"的映射，而非从头建立操控中心表征。

### 6.4 表征-动作鸿沟（Representation-to-Action Gap）
- 零样本情形下，模型已能识别并接近正确目标，但**稳定抓取与精确放置**等细粒度控制失败。
- 作者将该鸿沟主要归因于：
  - 训练数据规模有限（仅 2400h 有效数据）；
  - 动作采用**关节位置空间**，跨本体可迁移性弱；
  - 而非 BotTokens 架构本身。

## 7. 优点

- **问题切入角度新颖**：把"泛化"分解为"注意力的可迁移性"+"动作的可执行性"两个层次，并以此设计验证实验，思路清晰。
- **架构设计紧凑**：单一共享 Transformer + BotTokens 接口，相比双系统/MoT 类方案简洁，并能高效支持缓存式推理。
- **变量控制严谨**：架构隔离实验完全匹配数据/优化/参数预算，使归因锁定到 BotTokens 这一单一机制，证据链干净。
- **消融结构化**：5 级 ladder 逐步引入组件，能够识别哪些损失负责什么。
- **三重正则化（课程掩码 + 正交化 + 生成门控）** 增强 BotTokens 的有效性与多样性，避免坍缩。
- **注意力可视化工具 + 模型权重 + 代码均承诺开源**，便于复现。
- **跨本体 + 跨架构通用性验证**：BotTokens 在 MoT 风格架构上同样有效，提示这是一种**可迁移的接口范式**而非方案专属技巧。
- **微调前后表示相似性量化**给出了"表征-动作鸿沟"的可操作定义。
- **反泄漏审计**：用 TF-IDF + 人工视频复核确保零样本评估不被训练集污染。

## 8. 不足与局限

### 8.1 训练资源与算力披露
- 未给出 GPU 型号/数量、训练总时长、能耗等关键算力细节，可复现性受限。
- 预训练仅 0.4 epoch（约 2400h 有效数据），明确处于**欠训练**状态，结果有可能进一步提升。

### 8.2 数据局限
- 数据规模仅 2400h（混合总量 6000h 仅用了部分），且存在**指令-动作不匹配噪声**——直接削弱了语言条件化注意力的稳定性。
- 动作空间采用**关节位置（joint position）**，本体特异性强，作者也承认这点对跨本体迁移不利。
- 未公开数据清洗与去重策略，"异构 + 噪声"对训练细节的影响未量化。

### 8.3 评估充分性
- **真实机器人实验仅 1 个任务**（桌面清理），trial 数与误差棒缺失。
- **零样本定量结果**仅以"non-zero success on several tasks"等定性描述带过，未给出按"新物体/新场景/新本体"分项的成功率表。
- "Adaptive action execution strategy"被使用，但**细节未公开**，影响公平对比。
- 评测集中于 RoboTwin 系列，对其他仿真平台（RLBench、ManiSkill2、Calvin 等）和真实复杂场景覆盖不足。

### 8.4 架构与表示局限
- "注意力级泛化" ≠ "动作级泛化"，二者鸿沟仍显著；模型尚不能实现真正的零样本操控完成。
- 仅在 Qwen3-VL 4B 上验证，**不同骨干规模/不同 backbone** 下 BotTokens 的有效性未探索。
- BotTokens 数量 K=32 是默认值，未做 K sweep，敏感性未报告。
- BotTokens 移除后仍保留部分能力，说明表征已"内化"，但同时也意味着**架构与表示的因果关系在极端情况下不完全等价**，对设计解释带来一定模糊性。

### 8.5 应用与安全局限
- 实验场景以**桌面级抓取和短范围操作**为主，对于长任务（多步骤工具使用）、柔性物体、液体、非结构化户外环境等**未涉及**。
- 作者未讨论失败模式下的安全约束（如碰撞防护、紧急停止）、动作平滑性、对未预期本体的实机适配成本等实机部署关键问题。
