## 摘要
视觉-语言-动作（VLA）模型将视觉观测和语言指令直接映射为机器人动作，但长时序任务所需的不只是动作预测。智能体必须在物理状态演变过程中协调感知、规划、执行、进度验证与恢复。动作预测或模型生成的技能决策本身并不能保证所提出的操作在当前状态下有效，也无法保证其执行结果会被验证。我们提出了EmbodiedSkills，一个将每个技能决策视为执行提议的统一框架：运行时在执行前检查其前置条件，并在执行后验证结果。共享的可执行技能接口在单个智能体循环中连接了高层技能选择、有界的低层VLA执行以及执行后验证。由于该接口保持固定，低层VLA策略可以在不改变智能体循环的情况下进行替换或适配。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督信号，并在可获得交互反馈时支持可选的在线适配。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化EmbodiedSkills。任务适配的低层VLA策略在50个RoboTwin 2.0任务上达到86.20%的平均成功率，在四个LIBERO套件上达到97.40%的平均成功率。这些结果确立了EmbodiedSkills中所使用任务适配的低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，同一任务适配执行方法达到12.5%的平均成功率。该框架提供了一个可训练且可检查的智能体层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

# EmbodiedSkills 论文总结

## 一、核心问题与研究动机

- **VLA 模型的局限**：现有的视觉-语言-动作（VLA）模型直接将视觉观测和语言指令映射为机器人动作，但长时序（long-horizon）任务需要的远不止动作预测；智能体必须协调感知、规划、执行、进度验证和恢复五大环节，而端到端 VLA 策略通常将子目标决策隐式化，难以定位失败原因。
- **LLM 智能体的局限**：基于 LLM 的机器人智能体虽然显式输出推理步骤和工具调用，但"显式决策"≠"可执行决策"——所提议的技能可能与当前阶段不兼容、依赖过时观测、缺少必要参数，或执行后未能达到预期效果。
- **核心矛盾**：在部分可观测、反馈延迟、接触密集（contact-rich）等条件下，提示工程无法保证执行约束或结果验证；缺乏将"模型级决策"与"物理执行"衔接的中间层。
- **论文主张**：提出一个统一框架，把每一次技能决策当作"执行提案"，由运行时（runtime）在执行前检查前置条件、执行后验证结果，并将这些过程记录为结构化轨迹，使失败显式化、可追溯。

## 二、方法论

### 2.1 整体设计：闭环六阶段 AgentLoop

- 框架由 **高层 VLM 智能体**（基于 Qwen3-VL）和 **低层 VLA 策略**（基于 OpenPI/π0.5）构成，运行在"被守护的有限阶段控制器"（guarded finite-stage controller）上。
- 六个语义阶段：**Observe → Plan → Preflight → Execute → Verify → Recover**，并非刚性串行管线，而是可在状态变化时回访的语义结构。
- 三类控制操作：`RunSkill(k, q)`、`AdvanceStage`、`FinishRun`，所有合法决策均由运行时守卫验证。

### 2.2 可执行技能契约（Executable Skill Contract）

每个技能定义为元组 `k = (X_k, Y_k, pre_k, exec_k, post_k, fail_k)`：
- `X_k, Y_k`：类型化的输入/输出 schema；
- `pre_k`：前置条件（相位兼容、所需工件有效、依赖关系合法）；
- `exec_k`：可执行操作本身；
- `post_k`：成功后如何更新状态；
- `fail_k`：失败时的显式状态和证据。

> 关键思想：模型输出首先是"提案"，必须经过 schema 和前置条件校验后才进入执行；成功结果成为类型化"工件"（artifact），失败则作为显式证据进入下一轮决策。

### 2.3 运行时守护与状态转移

- **状态表示**：`s_t = (z_t, M_t, H_t)`，其中 `z_t` 为当前阶段、`M_t` 为任务工件集合、`H_t` 为有序循环轨迹。
- **策略上下文**：`C_t = (x, z_t, M_t, H_t)`，通过 `Ψ` 压缩历史并保留当前计划与子目标，超出预算的旧条目被丢弃或汇总。
- **三类守卫函数**：
  - `G_skill`：验证技能阶段匹配 + 技能在 `K_{z_t}` 中 + 所有前置条件 `r(s_t)=1`；
  - `G_advance`：验证当前阶段已生成下游所需的证据 `R_{z_t}(s_t)=1`；
  - `G_finish`：终止决策专用门控。
- **状态更新分支**：`s_{t+1}` 由 `U/N/F/B` 四种转移决定（执行成功 / 推进阶段 / 终止 / 阻塞并记录证据）。

### 2.4 有界动作执行（Bounded Action Execution）

- 低层 VLA 将 `(g_t, O_t, F_t)` 映射为动作块 `a_t`，其中 `g_t` 是活跃子目标、`O_t` 是当前观测、`F_t` 是预检证据。
- 动作块定义为 `a_t = (τ_t, U_t, H_t, η_t)`，其中 `U_t = [u^1_t, ..., u^{H_t}_t]` 是水平时间步为 `H_t` 的命令序列。
- 运行时接受条件 `R_act(a_t, s_t)`：要求 `0 < H_t ≤ H_max`、符合策略 schema `Σ_p`、数值有效、且与当前子目标和观测一致（freshness）。
- 一个语义子目标可由多个有界动作块完成——这是"动作块延续"机制的关键。

### 2.5 验证与恢复

- **Verify 阶段**仅评估当前活跃子目标，从新鲜后执行证据中预测语义路由：`V = {Advance, Continue, Reobserve, Replan, Recover, Finish}`。
- **Recover 阶段**复用同一任务状态与失败证据，生成修订后的执行上下文并再次校验后才允许物理动作。

### 2.6 训练机制

- **组件级监督（主要范式）**：在冻结低层 VLA 的前提下，用部署一致（deployment-consistent）的决策轨迹对 Qwen3-VL 调度器、低层 VLA 策略、验证器分别进行 SFT；每个组件只接收其接口所需的输入（planner/verifier/scheduler 各有定制上下文）。
- **可选在线适配**：支持 GRPO 风格的分组相对策略优化，公式 `A_i = (R_i - μ_G)/(σ_G + ε_norm)`，并对生成 token 应用 masked clipped objective `L_online`。
- **轨迹接口统一**：训练与部署使用相同的状态、阶段、工件接口，确保上下文一致性。

## 六、主要结论与发现

- **RoboTwin 2.0**：任务适配的 π0.5 在 50 任务上达到 **86.20%** 平均成功率，超过 LingBot-VA 报告的 π0.5 参考（82.74%），提升 **3.46 pp**；在 39/50 任务上更优，最大提升出现在 Hanging Mug (+20)、Blocks Ranking Size (+15)、Open Microwave (+15)、Move Can Pot (+10) 等接触密集或多阶段任务。
- **LIBERO**：四个套件平均 **97.40%**（vs OpenPI 96.85%，+0.55 pp），其中 LIBERO-Long 提升最显著（92.4 → 93.6）。
- **RMBench**：四个记忆依赖任务平均 **12.5%**，仍优于该基准上公布的 DP/ACT/π0.5/X-VLA（5.0–7.3%），但绝对水平偏低，暴露了模型在强记忆依赖任务上的瓶颈。
- **消融关键结论**：完整方案 86.20% → 去 Verify 48.2% → 去 Subtask 34.4% → 单块执行 19.5%；三者均不可或缺，且验证比子目标条件贡献更大（38.0 vs 51.8 pp 的差距）。

## 七、优点

- **设计理念清晰**：把"模型提议"与"运行时强制约束"解耦，使失败显式、可追溯，避免了单纯依赖提示工程。
- **可训练且可检查**：统一结构化轨迹接口为 planner、verifier、scheduler、低层 VLA 提供独立监督信号；且接口在训练与部署间保持一致，避免上下文偏移。
- **模块化与可替换**：低层 VLA、规划器、验证器、环境适配器均可独立替换或升级，AgentLoop 不变。
- **跨基准一致表现**：在 RoboTwin 2.0、LIBERO 两种结构差异显著的基准上都取得领先，证明执行接口并不绑定于特定任务体系。
- **消融控制严谨**：所有变体共享相同的规划器、低层策略与评测器，仅改变目标机制变量。

- **算力与可复现性披露不足**：未公开 GPU 数量、训练时长、显存占用等关键复现信息。
- **在线优化效果有限**：分组归因粒度粗（同一回报分配给多个不同贡献的决策），因此 GRPO 仅作为"可选细化"而非主要训练范式。
- **语义验证的固有局限**：当进度被遮挡、视觉模糊或需要不可观测属性时，验证器本身可能误判；显式契约只能保证形式合法性，不能保证语义正确性。
- **延迟与多调用开销**：相比单次动作策略，每步引入额外 VLM 调用与后执行观测，实时性存在压力。
