## 摘要
当前，拥有数十亿参数的视觉-语言-动作（VLA）模型主导着 LIBERO 操控基准测试，但该基准实际所需的模型容量仍不明确。我们提出了 MINERVA（MINimal Efficient Robotic Vision-Action policy，最小高效机器人视觉-动作策略），这是一类经过刻意精简设计的视觉运动策略，旨在衡量这一任务特定的容量下限。一个仅 0.54M 参数的策略在四个标准 LIBERO 套件的 2,000 次展开实验中达到了 95.1% 的平均成功率，仅比所报告的 LeRobot $\pi_{0.5}$ 结果低 2.4 个百分点，尽管其参数量少了 7,700 倍。性能在接近 1M 参数时趋于饱和，并在低于 0.25M 参数时急剧下降。在广泛的架构、训练和推理扫描实验中，仅有动作块长度和视觉容量始终超出 $\pm$1 点的训练种子波动范围。在三个随机种子下，流匹配相较于直接 L1 回归并未表现出可检测的优势，而回归在 GPU 上的速度最高可快 3.8 倍。一项任务 ID 置换探针实验表明，标准的 LIBERO 指令条件化主要是在已记忆任务之间进行选择：仅改变任务 ID 映射就会使成功率降至接近随机水平。同样的方案在 89 个 LIBERO-90 任务上取得了 94.6% 的成功率，而 LIBERO-Plus 扰动使性能降至 46%–56%，且对光度变化的鲁棒性几乎为零。该 0.54M 参数的策略在笔记本 CPU 上每个动作块的重规划时间为 5–9 毫秒，比 SmolVLA 快 113 倍，比 $\pi_{0.5}$ 快 1,400 倍，且无需 GPU。这些结果首次给出了 LIBERO 任务特定容量下限的实证估计，并为面向部署高效的机器人策略的容量感知设计与蒸馏提供了动机。

## Abstract
Vision-language-action (VLA) models with billions of parameters now dominate the LIBERO manipulation benchmark, but the model capacity actually required by the benchmark remains unclear. We introduce MINERVA (MINimal Efficient Robotic Vision-Action policy), a family of deliberately compact visuomotor policies designed to measure this task-specific capacity floor. A 0.54M-parameter policy achieves 95.1% average success over 2,000 rollouts on the four standard LIBERO suites, only 2.4 points below the reported LeRobot $π_{0.5}$ result despite using 7,700$\times$ fewer parameters. Performance saturates near 1M parameters and collapses below 0.25M. Across broad architectural, training, and inference sweeps, only action-chunk length and vision capacity consistently exceed a $\pm$1-point training-seed band. Flow matching provides no detectable advantage over direct L1 regression across three seeds, while regression is up to 3.8$\times$ faster on GPU. A task-ID permutation probe shows that standard LIBERO instruction conditioning primarily selects among memorized tasks: changing only the task-ID mapping reduces success to near chance. The same recipe achieves 94.6% success across 89 LIBERO-90 tasks, while LIBERO-Plus perturbations reduce performance to 46--56%, with near-zero robustness to photometric shifts. The 0.54M policy replans every control step in 5--9 ms per chunk on a laptop CPU, 113$\times$ faster than SmolVLA and 1,400$\times$ faster than $π_{0.5}$, without a GPU. These results establish a first empirical estimate of LIBERO's task-specific capacity floor and motivate capacity-aware design and distillation for deployment-efficient robot policies.

# MINERVA 论文总结

## 1. 核心问题与整体含义

- **研究背景**：当前视觉-语言-动作（VLA）模型（如 OpenVLA 7B、π0/π0.5 3–4B）以数十亿参数主导 LIBERO 操控基准，但其训练与部署成本（多 GPU 训练、GB 级权重、大显存推理）高昂。
- **核心问题**：对于任务集固定的部署场景，LIBERO 基准实际需要的模型容量到底是多少？即"任务集的最小充分容量（capacity floor）"是多少？
- **研究意义**：从部署效率（deployment efficiency）角度出发，若能测量出该容量下限，就可在边缘设备（如 CPU、嵌入式）上构建或蒸馏相应大小的策略，避免在不会使用的泛化能力上浪费算力。
- **隐含前提**：基于 LIBERO-PRO 的分析 [13]，标准 LIBERO 评测实质上是"训练场景/任务/指令下的记忆测试"，语言指令主要用于选择已记忆的任务之一。

## 2. 方法论

### 2.1 设计原则
- 既然标准 LIBERO 是记忆测试，则不需要语言编码器、不需要预训练骨干，把全部预算投入"视觉状态估计 + 闭环动作生成"。

### 2.2 模型架构（MINERVA 家族）
- **感知模块**：从零训练的 CNN（不使用任何预训练 backbone），由两个相机视角（agent-view 与 wrist，256² resize 到 144²，训练随机裁剪到 128²）共享；4 个 stride-2 阶段的深度可分离残差块（来自 MobileNet [26]）；FiLM [27] 通过任务嵌入进行调制；空间 softmax 关键点提取 [22]；线性投影后得到每视角特征；8 维本体感知状态经两层 MLP 编码。
- **任务条件**：用 40 项可学习任务 ID 嵌入表（无语言编码器，无 BERT/CLIP）替代自然语言指令。
- **动作头**：以条件流匹配（flow matching [23]）生成动作块 $a = a_{1:H}$，$H=16$。
  - 训练：采样 $\epsilon \sim \mathcal{N}(0, I)$ 和噪声水平 $\tau$，形成插值 $a_\tau = \tau a + (1-\tau)\epsilon$，对速度场做 L2 回归：
    $$L_{\text{fm}} = \mathbb{E}_{a,\epsilon,\tau} \| v_\theta(a_\tau, \tau, c) - (a-\epsilon)\|_2^2$$
  - 推理：10 步 Euler 积分从 $\epsilon \sim \mathcal{N}(0, \sigma^2 I)$ 出发（$\sigma=0.85$，模式搜索）。
  - 头部结构：4 层 DiT [24]，自注意力替换为 MLP mixer [25]；AdaLN-Zero 调制 MLP 跨块共享 [28]。
- **可选直接回归**：训练为直接 L1 回归时，一步前向即可输出块；用于推理加速。
- **辅助训练头**：仅训练时使用 (<9k 参数)，用于预测回合进度。
- **模型系列**：MINERVA-0.5M (0.54M)、1M (0.99M)、5M (4.89M)、10M (9.66M)；小模型用更大教师做"速度场蒸馏" $L = L_{\text{fm}} + \lambda \|v_\theta - v_\phi\|_2^2$，$\lambda=1$。
- **观察历史**：$n_{\text{obs}}=2$；在 7M 参数下从 1 步增加到 2 步，Goal +6 分、Long +4 分。

### 2.3 推理策略
- 每步重规划 + ACT 风格时间集成 [14]：对覆盖该时间步的所有块的预测做指数加权平均（衰减率 0.01）。
- 对比方法：BID 候选选择 [15]、RTC 软修复 [16]、朴素 chunking。

## 3. 实验设计

### 3.1 数据集与基准
- **lerobot/libero 数据集**：4 个标准套件（Spatial / Object / Goal / Long, 共 40 任务），1693 条示范，273k 帧。
- **LIBERO-90 扩展**：89 任务，3959 条示范（单种子扩展实验）。
- **LIBERO-Plus [29]**：10030 个扰动变体，覆盖 7 类扰动因子。
- **评测协议**：默认 50 集/任务 × 10 任务 × 4 套件 = 2000 次 rollout，固定种子，环境硬重置；π0.5 比较为 10 集/任务 × 400 rollout（参考点，非协议匹配）。

### 3.2 对比方法
- 大型 VLA：OpenVLA (7B) [2]、OpenVLA-OFT [6]、π0 [4]、π0.5 (LeRobot 实现，4.1B) [7][8]。
- 中型：Octo (93M) [1]、SmolVLA (450M) [3]、TurboVLA (0.2B) [5]。

## 4. 资源与算力

- **训练硬件**：单个 GH200 或消费级 RTX 5080 GPU。
- **训练时长**：单个模型约 2 小时。
- **训练设置**：90–120k 步，batch 128，AdamW（学习率 1e-4，余弦衰减）。
- **推理硬件**：RTX 5080 笔记本 GPU + 8 线程笔记本 CPU 对比 SmolVLA 与 π0.5。
- **超算资源**：使用了筑波大学 CCS 的 Miyabi 超级计算机（致谢中提及）。

## 5. 实验数量与充分性

- **参数扫描**：9.7M → 0.09M 共 7 个尺度点（图 3）。

- **预算分配扫描**：固定 ~1M 总参数下，视觉/动作头 6 点扫描。

## 6. 主要结论与发现

- **核心结论**：0.54M 参数的 MINERVA 在 4 套件平均成功率 **95.05%**（用 L1 头时 95.75%），比 π0.5（4.1B）仅低 2.4 点，但参数少 7700 倍。
- **饱和与崩塌**：性能在约 1M 参数处饱和（96.75%）；低于 0.25M 急剧崩塌（0.24M → 88.6%，0.09M → 68.3%），且 Long 套件最先崩塌。
- **关键消融发现**：
  - 仅 **动作块长度**（±3.16 / ±2.20）与 **视觉容量**（−1.41，3 种子复制）稳定超出种子带；
  - **流匹配无优势**：3 种子下 +0.34（在带内），但 L1 回归 GPU 上快 3.8×；
  - **自注意力多余**：MLP mixer 在 −26% 参数下达到同等分数；
  - **预算分配规则**：视觉 50–80% 预算同分；视觉饿到 0.13M 损失无恢复。
- **推理策略**：每步重规划 + 时间集成 + 模式搜索（σ=0.85）在 sub-1M 模型上稳定增益 +0.2 到 +2.25 点。
- **置换探针**：仅旋转任务 ID 映射，96.75% → 6.5%；任务 ID 是任务选择的因果信号。
- **LIBERO-90**：同配方在 89 任务、0.995M 参数下达 94.6%（单种子）。
- **LIBERO-Plus**：扰动下掉到 46–56%；5M 模型靠语义/几何扰动（new objects 62→96）拉回；但光度鲁棒性在所有尺度都接近 0（light ≤ 6.5%）。
- **部署成本（Table III）**：0.54M CPU 8.9 ms / chunk；π0.5 CPU 12.8 s / chunk；快 1400×，0.03 GB VRAM。

## 7. 优点

- **问题定位精准**：把"模型够不够大"的争论从"更大更好"转向"任务真正需要多少"，提供清晰的容量度量视角。
- **设计与基准契合**：刻意抛弃语言/预训练 backbone，与"标准 LIBERO 是记忆测试"的判断保持一致。
- **实验结构严谨**：明确给出 ±1 点种子带作为显著性参考，使很多单点消融结论被正确打折。
- **覆盖全面**：架构、训练、推理三层消融 + 三个基准（标准 / LIBERO-90 / LIBERO-Plus）+ 因果探针。
- **预算分配规律明确**：结论可迁移——"小策略的预算花在视觉，不在动作头"。
- **完全开源**：代码、配方、所有 checkpoint 提供。
- **诚实报告局限**：在 Discussion 中明确说明哪些能力被放弃（开放词汇感知、跨任务迁移）、哪些维度未验证（真实机器人）。
- **落地价值**：CPU 上 5–9 ms 重规划时间使 100 Hz 控制环可完全脱离 GPU。

## 8. 不足与局限

- **任务 ID 嵌入的硬约束**：无法处理未训练过的任务，MINERVA 本质上是一个"封闭任务集测量仪器 + 可部署组件"，不是通用策略。
- **单次运行偏多**：Table I 表头模型、LIBERO-90、5 项消融以外的所有扫描点都只有 1 个种子，处于 ±1 点带内；某些结论（如缩放曲线形状）尚缺统计强度。
- **单一仿真器、单一评估种子**：所有结论建立在 LIBERO + 固定种子之上，未做跨仿真器验证。
- **无真实机器人实验**：SO-101 硬件支持虽存在框架内，但本文未报告实机结果。
- **光度鲁棒性近乎为零**：从零训练的 CNN 对光照/背景敏感，所有尺度都未解决；这正是开放词表与扰动协议想要测的能力，恰恰是 MINERVA 主动放弃的。
- **与 π0.5 比较不完全公平**：LeRobot 报告结果基于 10 集/任务，本文 50 集/任务；作者明示为参考点而非 head-to-head。
- **扰动分析复用 LIBERO-Pro [13] / LIBERO-Plus [29] 等已有工作的结论**：作者自身未对扰动后能力提出改进方案。
- **块长选择仍是经验值**：16 是经验最佳而非理论推导；这与论文追求的"测量任务需求"哲学一致，但仍是一个工程上的开放点。
