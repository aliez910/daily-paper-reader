## 摘要
视觉-语言-动作（VLA）模型将视觉观测和语言指令直接映射为机器人动作，但长时程任务需要的不只是动作预测。智能体必须随着物理状态的演变，协调感知、规划、执行、进度验证与恢复。动作预测或模型生成的技能决策本身并不能保证所提出的操作在当前状态下有效，也无法保证其结果将被验证。我们提出EmbodiedSkills，这是一个统一框架，将每项技能决策视为一项执行提案：运行在执行前检查其前置条件，并在执行后验证其结果。一种共享的可执行技能接口在单个智能体循环内连接高层技能选择、受限的低层VLA执行与动作后验证。由于该接口保持固定，低层VLA策略可以在不改变智能体循环的前提下被替换或适配。该接口还将规划、执行、验证与恢复事件记录为结构化轨迹，为各组件提供监督信号，并在可获得交互反馈时支持可选的在线适配。我们在RoboTwin 2.0和LIBERO上以Qwen3-VL和OpenPI/pi0.5实例化EmbodiedSkills。经任务适配的低层VLA策略在50项RoboTwin 2.0任务上达到86.20%的平均成功率，在四个LIBERO套件上达到97.40%的平均成功率。这些结果验证了EmbodiedSkills中所用经任务适配的低层VLA策略的执行性能。在四项依赖记忆的RMBench任务上，同一任务适配执行方法达到12.5%的平均成功率。该框架提供了一层可训练且可检查的智能体层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

# EmbodiedSkills 论文总结

## 一、核心问题与研究动机

**核心问题**：现有的视觉-语言-动作（VLA）模型虽然在单步动作预测上表现良好，但长时程具身任务需要的不只是动作预测，还需协调**感知、规划、执行、进度验证与恢复**等环节。现有方法存在两类不足：

- **端到端 VLA 策略**：将子目标选择、物体绑定、动作执行等中间决策隐式化，失败时难以定位原因（是定位错误、子目标错误、动作执行错误还是恢复失败）。
- **基于 LLM 的机器人智能体**：虽然显式产生工具调用与推理步骤，但"显式决策"并不等于"在当前物理状态下有效且可执行"。模型可能基于过时观察、遗漏必要参数、或对当前阶段兼容性判断错误而提出无效技能。

**核心矛盾**：模型层面的决策与物理执行之间缺乏桥接——需要一种机制使得"被提出的操作在执行前被验证、执行后被验证，且验证证据能反馈给后续决策与学习"。

## 二、方法论：核心思想与关键技术

### 1. 总体框架：可执行技能（Executable Skill）视角

EmbodiedSkills 将每个技能决策视为**执行提案（execution proposal）**而非即执行指令。框架将长时程 VLA 智能体组织为一个**有保护的有限阶段控制器**，围绕六类可执行技能展开：

$$Z = (\text{Observe}, \text{Plan}, \text{Preflight}, \text{Execute}, \text{Verify}, \text{Recover})$$

每个阶段有明确语义角色与退出证据（详见论文 Table 1）。

### 2. 关键技术组件

**(1) 智能体状态与技能决策**

智能体状态 $s_t = (z_t, M_t, H_t)$，其中 $z_t$ 为当前阶段、$M_t$ 为任务产物集、$H_t$ 为有序循环轨迹。策略接收压缩上下文 $C_t = \Psi(x, z_t, M_t, H_t)$，并从状态相关的动作集中选择结构化决策：

$$d_t \sim \pi_\theta(\cdot | C_t, z_t, A_t), \quad A_t = G_{\text{state}}(K_{z_t}, s_t)$$

策略的三类控制：$\text{RunSkill}(k, q)$、$\text{AdvanceStage}$、$\text{FinishRun}$。

**(2) 可执行技能契约**

每个技能被形式化为五元组：

$$k = (X_k, Y_k, \text{pre}_k, \text{exec}_k, \text{post}_k, \text{fail}_k)$$

- $X_k, Y_k$：类型化输入输出 schema
- $\text{pre}_k$：前置条件
- $\text{exec}_k$：可执行操作
- $\text{post}_k$：状态更新规则
- $\text{fail}_k$：失败状态与证据

产物携带 provenance 与 freshness 信息，避免过时预测被静默复用。

**(3) 保护运行时（Guarded Runtime）转移**

策略提出决策，运行时分三类守卫：

- 技能守卫：$G_{\text{skill}}(s_t, d_t)$ —— 检查阶段兼容性、所需输入、合法性
- 前进守卫：$G_{\text{advance}}(s_t, d_t)$ —— 检查当前阶段是否已产生所需证据
- 终止守卫：$G_{\text{finish}}(d_t)$

更新规则为：

$$s_{t+1} = \begin{cases} U(s_t, k(q)), & G_{\text{skill}}=1 \\ N(s_t), & G_{\text{advance}}=1 \\ F(s_t), & G_{\text{finish}}=1 \\ B(s_t, d_t), & \text{otherwise} \end{cases}$$

这将"模型提案"与"运行时执行语义"解耦，模型不负责执行安全，运行时强制执行 schema 验证。

**(4) 受限动作执行（Execute 阶段）**

低层 VLA（如 π0.5）基于活动子目标 $g_t$、当前观察 $O_t$、就绪证据 $F_t$ 生成**有界动作块**（bounded action chunk）：

$$a_t = (\tau_t, U_t, H_t, \eta_t), \quad U_t = [u^1_t, \ldots, u^{H_t}_t]$$

运行时检查 $R_{\text{act}}(a_t, s_t)$：包含 horizon 上限 $H_{\max}$、动作 schema、数值有效性、子目标-观察一致性。一个语义子目标可对应多个动作块。

**(5) 验证与恢复**

Verify 阶段对活动子目标判断后从集合 $V = \{\text{Advance, Continue, Reobserve, Replan, Recover, Finish}\}$ 选择路由。Recover 利用相同的显式任务状态与失败证据产生修订后的执行上下文，并在再次执行前做前置检查。

### 3. 训练机制

- **组件级监督微调**：planner、verifier、scheduler 各自基于部署一致的轨迹做 SFT；低层 VLA 用子任务级示教独立适配。
- **部署一致训练样本**：$x_t = (g, z_t, I_t, e^s_t, K_t, h_t)$，且损失仅施加在策略生成的 token 上，不在 prompt/图像/工具结果上。
- **可选的在线优化**：支持 GRPO 类组相对策略优化（论文给出 clipped objective），但论文明确将其定位为"可选精修机制"，而非主训练范式。

## 六、主要结论与发现

1. **执行性能**：任务适配 π0.5 在 RoboTwin 2.0 50 任务上平均成功率 **86.20%**，超越 LingBot-VA 报告的 82.74%（+3.46 pp），在 39/50 任务上超过参考。
2. **跨基准泛化**：LIBERO 四套件平均 **97.40%**，比 OpenPI 官方值 96.85% 高 0.55 pp，LIBERO-Long 增益最大（+1.2 pp）。
3. **记忆依赖任务**：RMBench 4 任务平均 **12.5%**，高于 DP/ACT/π0.5/X-VLA 的公开结果（5.0–7.3%）。
4. **机制贡献排序**：语义子任务条件化 + 中间验证 + 自适应续执行均不可或缺。去掉验证掉 38.0 pp，去掉子任务掉 51.8 pp，仅 1 chunk/subtask 掉 66.7 pp。
5. **可训练性**：组件级 SFT + 可选 GRPO 优化路径在保持低层策略冻结时仍可改善高层决策。

## 七、优点与亮点

1. **"策略-运行时分离"的清晰架构**：将 LLM/VLM 生成的结构化决策与运行时强制执行约束解耦，避免"提示词背锅执行安全"的常见陷阱。
2. **可执行技能契约**：typed schema + freshness + 失效传播机制，避免过时观察/计划被静默复用，对故障定位友好。
3. **统一轨迹 schema**：组件级监督、跨组件独立适配、可选在线优化共用同一接口，提升可诊断性与可复用性。
4. **跨基准验证**：同时在 RoboTwin 2.0、LIBERO、记忆依赖 RMBench 上验证，证明执行接口不绑定于特定基准。
5. **消融设计"受控"**：四个变体共享相同 planner/低层策略/初始状态/评测器，差异仅在循环结构，结论解释力强。
6. **避免一锅端**：明确区分"组件级监督（主路径）"与"在线优化（可选精修）"，避免对单一优化范式的过度依赖。

## 八、不足与局限

1. **任务适配专家成本**：RoboTwin 2.0 实例使用 per-task 适配的低层 VLA，相比单一通用策略在训练、存储与部署上成本更高。
2. **延迟开销**：额外的 VLM 调用与执行后观察引入相对单遍动作策略的延迟，论文承认这一点但未给出量化数据。
3. **基线覆盖偏窄**：
   - LIBERO 仅与 OpenPI 单一基线对比
   - RoboTwin 2.0 对比的 VLA 基线（π0、X-VLA、π0.5）为引用值而非重新评估
   - RMBench 对比全部为公开结果，未在统一条件下重跑
4. **消融粒度不够细**：缺少"仅有 Verify 无子任务"等交叉组合，难以精确量化各机制的边际贡献。
5. **可信度边界**：契约可阻止无效状态转移，但不能阻止语义上合理但物理上错误的子目标（如错误的物体绑定）；验证在遮挡、视觉模糊时仍受限。
6. **协调开销**：模块化适配虽便于专业化，但长 episode 累积的小规划/执行错误会导致观察、重试与模型调用数增长。
7. **算力与复现信息缺失**：GPU 型号/数量、训练时长、超参数表未在正文中明确给出，给完全复现带来挑战。
8. **场景覆盖偏差**：以仿真基准为主，未在真实机器人平台上做迁移验证，Sim-to-Real 鲁棒性未知。
