## 摘要
视觉-语言-动作（VLA）模型通常通过自回归文本坐标或不透明的动作令牌来暴露空间定位能力，这使得多模态推理与机器人执行之间形成了脆弱的接口。我们提出了 Pointing-VLA，一个基于 Embodied-R1 构建的类型化隐状态空间读出机制。几何专属的预测头可直接输出归一化点、对象功能定位（OFG）热力图以及视觉轨迹，而无需将几何信息序列化为文本形式。在所评估的 Bridge/WidowX 仿真及物理抓取-放置部署场景中，显式的执行契约将 PICK 动作分配给源条件化的 OFG，将 PLACE 动作分配给 Pointing，从而提供与阶段对齐的直接空间目标。Pointing-VLA 在 Bridge/WidowX 上取得了当前最优的性能，在所评估的四项任务集上平均达到 72.9%，且未进行 Bridge 专属微调，并在启用碰撞检测的 CuRobo 执行器下完成测试。Pointing 与 OFG 在原生及跨数据集评估中展现出互补的优势。OFG/接触读出机制可迁移至 NORA-1.5，在保持或提升成功率的同时，将记录的控制器时间缩短超过 20 倍；在同一外部测试套件上，类型化头的运行速度较 Embodied-R1 的文本解码快 6.68 至 6.90 倍。当作为空间引导集成至 π_{0.5} 动作策略中时，Pointing-VLA 将自主真实机器人在三种视觉场景下的成功率从 52.7% 提升至 80.7%。这些结果确立了类型化空间读出机制作为一种高效且可检视的接口，在具身推理与机器人执行之间所发挥的关键作用。

## Abstract
Vision-language-action (VLA) models often expose spatial grounding through autoregressive text coordinates or opaque action tokens, creating brittle interfaces between multimodal reasoning and robot execution. We present Pointing-VLA, a typed hidden-state spatial readout built on Embodied-R1. Geometry-specific heads predict normalized points, object-functional grounding (OFG) heatmaps, and visual trajectories without serializing geometry as text. For the evaluated Bridge/WidowX and physical pick-place deployments, an explicit execution contract assigns PICK to source-conditioned OFG and PLACE to Pointing, providing direct stage-aligned spatial targets. Pointing-VLA achieves SOTA performance on Bridge/WidowX, averaging 72.9\% across the evaluated four-task set without Bridge-specific finetuning under collision-enabled CuRobo execution. Pointing and OFG show complementary strengths across native and cross-dataset evaluations. The OFG/contact readout transfers to NORA-1.5, preserving or improving success while reducing recorded controller time by more than 20$\times$; typed heads are also 6.68--6.90$\times$ faster than Embodied-R1 text decoding on a shared external suite. When integrated as spatial guidance for a $π_{0.5}$ action policy, Pointing-VLA raises autonomous real-robot success from 52.7\% to 80.7\% across three visual contexts. These results establish typed spatial readouts as an efficient, inspectable interface between embodied reasoning and robot execution.

# Pointing-VLA 论文总结

## 一、核心问题与研究动机

- **VLA 模型的接口瓶颈**：现有视觉-语言-动作（VLA）模型在将空间定位信息暴露给机器人执行端时，主要采用两种方式：
  - **自回归文本坐标**：模型需要逐 token 生成数字字符串，执行器还需逆向解析回像素坐标；密集的部件级证据在序列化过程中被丢弃。
  - **不透明的动作令牌**：虽避免了文本解析问题，但隐藏了机器人栈或人类审计员需要的空间推理依据。
- **两类接口失败模式**（见图 1）：
  - 文本生成在产出有效几何坐标前就已失败（如格式错误、循环生成）。
  - 语法上可解析的坐标可能在语义上空间错误。
- **核心论点**：具身定位应被视为**类型化接口预测**而非文本坐标生成。三类空间目标（指称点、功能区域、视觉轨迹）虽共享视觉-语言骨干，但几何本质不同——点稀疏、可供性常为部件级密集区域、轨迹具时序结构——强行折叠到单一输出分布会产生负向干扰。
- **理论依据**：借鉴神经科学的"行动视觉通路"理论（Goodale & Milner, 1992；Cisek, 2007），下游读出头直接从分布式内部活动解码空间变量，而非通过序列化系统。

## 二、方法论

### 2.1 整体架构

- **骨干网络**：基于 Embodied-R1（具身多模态视觉-语言模型），冻结基础权重。
- **三个几何专属读出头**（分别解码不同空间目标）：
  - **Pointing 头**：输出归一化坐标 $(\hat{x}, \hat{y}) \in [0,1]^2$。
  - **OFG 头**：输出 2D 接触热力图，保留功能接触的空间范围。
  - **VTG 头**：输出 $T=8$ 个归一化图像空间航点，描述视觉轨迹而非低层动作。

### 2.2 关键技术细节

- **隐状态空间读出（Hidden-State Spatial Readout）**：
  - 通过共享的 Grounding Adapter（1024-D 投影）和任务条件化的学习查询，将多模态隐状态映射到定位空间。
  - Pointing 与 OFG 专家使用 8 个定位查询；VTG 专家使用时序查询直接关注多模态序列以避免固定 token 瓶颈。
  - 每个专家保留各自的 LoRA、学习查询与解码器。

- **Pointing 头计算流程**：
  - 学习指针查询 $q_{pt}$ 通过 cross-attention 选择用于图像定位的证据。
  - 最终坐标 $(\hat{x}, \hat{y}) = \sigma(W_p \cdot \text{LN}(z_{pt}) + b_p)$，直接发出，无需文本解析。
  - 像素坐标通过 $(\hat{u}, \hat{v}) = ((W-1)\hat{x}, (H-1)\hat{y})$ 映射到原图。

- **OFG 头计算流程**：
  - 利用 FiLM 条件化调制视觉塔的 2D 特征图：$F'_{ofg} = \gamma(g_{ofg}) \odot F_{vis} + \beta(g_{ofg})$。
  - 通过卷积热力图解码器得 $\hat{H}_{ofg}$，取峰值为功能接触位置。

- **VTG 头**：$z_{\tau t} = \text{Attn}(q_{\tau t}, H^{mm}_{vtg})$，$\hat{\tau}_t = \sigma(W_\tau z_{\tau t} + b_\tau)$。

### 2.3 执行契约（Execution Contracts）

- **固定 PICK/PLACE 契约**：
  - PICK：由源条件化的 OFG 头提供（处理源实例消歧与功能接触）。
  - PLACE：由 Pointing 头提供（紧凑的目标点）。
  - 查询按指令 $\ell$、源描述 $c_{src}$、目标描述 $c_{goal}$ 构建。
- **外部包装层**：通过相机内参 $K$、深度 $D$ 和相机-机器人变换 $T_{r \leftarrow c}$ 将图像空间输出转换为机器人坐标系目标。

### 2.4 训练目标

- **损失函数**：$L = \lambda_{pt} L_{pt} + \lambda_{box} L_{box} + \lambda_{ofg} L_{ofg} + \lambda_{vtg} L_{vtg} + \lambda_{aux} L_{aux}$
  - 点与轨迹使用 SmoothL1。
  - OFG 对高斯关键点用 MSE，对密集可供性掩膜用类别平衡 BCE。
- **GRPO 风格精炼**：应用于 Pointing 头，引入组归一化优势与 SFT + KL 正则化，进一步提升精度（61.3% → 64.3%）。
- **分阶段训练**（图 3）：
  1. 几何预热：训练 Adapter、查询、几何头。
  2. LoRA 专精：仅更新低秩骨干参数。
  3. 任务继续：仅更新任务所需子集。
- **源条件化 OFG 适应**：冻结 Embodied-R1 基础、Pointing/VTG 模块与执行器，联合更新 OFG LoRA、共享 Adapter、OFG 查询与热力图解码器；采用密集源掩膜重建 + 源-干扰物排序 + 干扰物抑制。

## 七、主要结论与发现

- **原生空间头**：Pointing 在 VABench-P 上达 64.3%，OFG 将 Part-Affordance-2K 准确率从 40.9%（Embodied-R1）提升至 57.3%（+16.4 个百分点）。
- **VTG**：在 300 个 VABench-V 示例上达 0.1042 RMSE、0.1368 ADE、0.1493 FDE。
- **固定契约验证**：OFG-PICK/Pointing-PLACE 配置在 Bridge/WidowX 上达 72.9% 平均成功率，超过次优配置 14.6 个百分点；Stack 任务 100% 完成，Eggplant 任务 22/24。
- **跨数据集互补性**：Pointing 在 RefCOCO（PIB 56.1%）与 RoboAff 上最强；OFG 在 AGD20K（PIM 64.4%）与 Part-Affordance-2K（57.3%）上最强。
- **运行时效率**：类型化头比 Embodied-R1 文本解码快 6.68–6.90 倍。
- **跨骨干迁移**：NORA-1.5 + OFG 头在水平姿态上保持 100% 成功率，竖放姿态从 89.0% 升至 95.0%，控制器时间缩短 20.5×–22.1×。
- **真实机器人**：$\pi_{0.5}$ + Pointing-VLA 将成功率从 52.7% 提升至 80.7%（Δ=+28.0 pp），三场景均一致提升；抓取前失败从 47 降至 16，托盘到达失败从 13 降至 4。
- **失败阶段分析**：改善集中于抓取前与放置到达阶段；抓取后转移仍是主要瓶颈。

## 八、优点

- **核心理念创新**：明确将具身定位抽象为"类型化接口预测"，从系统层面解决了文本坐标序列化带来的效率与稳定性损失。
- **架构解耦**：三类空间目标分别由专属头解码，避免负向干扰，并允许各头独立优化。
- **执行契约显式化**：固定的 OFG-PICK/Pointing-PLACE 契约将每个执行阶段与其所需几何对齐，无需推理时选择器。
- **跨骨干可迁移**：OFG 头可直接迁移至 NORA-1.5，无需重新训练骨干，且保持或提升性能。
- **运行时优势显著**：消除文本解码与解析，推理速度提升近一个数量级。
- **空间引导即插即用**：作为空间先验插入现有 $\pi_{0.5}$ 策略，无需替换动作生成器即获得大幅提升。
- **失败诊断精细**：按抓取前/抓取后/托盘到达阶段分桶报告，使改进归因清晰。

## 九、不足与局限

- **任务多样性受限**：Bridge/WidowX 四任务均为 pick-place 类结构化场景，未覆盖更广泛的具身操控任务（如折叠、装配、长时序任务等）。
- **闭环几何感知执行缺失**：作者承认任务相关变化在 spoon-on-towel 等任务上仍可见，明确指出闭环几何感知执行是未来工作方向。
- **抓取后转移瓶颈**：真实机器人实验中，post-grasp transfer 失败未得到改善，说明空间引导仅在 PICK/PLACE 几何边界起作用，缺乏运动期间的反馈修正。
- **算力与训练透明度不足**：未披露具体训练时长、参数总量、数据规模等关键复现信息，仅列出 GPU 型号。
- **统计置信度有限**：多数结果为单次报告值，未给出多次独立运行的均值/置信区间；VTG 仅基于 300 个样本。
- **跨数据集实验细节部分在补充材料**：主文未完整呈现样本构造与分割细节，影响结果可重复性评估。
- **对干扰物鲁棒性评估有限**：真实机器人仅引入圆柱形干扰物，未涵盖更多类别的视觉干扰或场景变化。
- **依赖外部包装层**：图像空间到机器人帧的转换仍需传统几何标定（深度、内参、外参），若标定误差较大将影响执行精度。
- **仅与少量最新方法对比**：Bridge/WidowX 部分基线（如 MemoryVLA、SoFar）未在统一执行器下复现，可能影响公平性判断。
