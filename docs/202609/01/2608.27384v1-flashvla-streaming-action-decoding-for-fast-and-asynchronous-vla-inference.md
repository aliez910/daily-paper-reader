## 摘要
视觉-语言-动作（VLA）模型在机器人操作领域展现出日益广阔的应用前景，但其实际部署仍受推理延迟高和异步执行不稳定所限制。这一挑战在基于流匹配的VLA模型中尤为突出，因为动作解码需要以VLM上下文为条件进行多次迭代步骤。高效推理方法能够提高控制频率，异步方法则可减少执行空闲时间，但现有方法往往无法同时实现低延迟推理以及准确、时间一致的异步执行。我们提出了FlashVLA，这是一种以统一方式应对这两项挑战的流式动作解码框架。FlashVLA维护一个包含多个处于不同噪声水平的动作块的流式动作缓冲区，并利用分块因果注意力对其进行解码。该设计使FlashVLA能够在每个推理步骤中生成一个可执行动作块。此外，其分块自回归建模方式能够隐式保持动作连续性，无需额外的未来状态条件输入，即可实现平滑的异步执行。在大量仿真和真实世界实验中，FlashVLA显著提升了推理速度，同时保持了卓越的任务性能。在真实世界部署中，该方法可在单块GPU上实现不低于30 Hz的控制频率，并提供流畅的异步推理。

## Abstract
Vision-Language-Action (VLA) models are increasingly promising for robotic manipulation, yet their real-world deployment remains bottlenecked by high inference latency and unstable asynchronous execution. This challenge is particularly pronounced in flow-matching-based VLA models, where action decoding requires multiple iterative steps conditioned on the VLM context. While efficient inference methods improve control frequency and asynchronous methods reduce execution idle time, existing approaches often fail to jointly achieve low-latency inference and accurate, temporally consistent asynchronous execution. We introduce \textbf{FlashVLA}, a streaming action decoding framework that addresses both challenges in a unified formulation. FlashVLA maintains a streaming action buffer with multiple chunks at different noise levels and decodes them using chunk-wise causal attention. This design allows FlashVLA to produce one executable action chunk per inference step. Moreover, its chunk-wise autoregressive formulation implicitly preserves action continuity, enabling smooth asynchronous execution without extra future-state conditioning. Across extensive simulated and real-world experiments, FlashVLA substantially improves inference speed while maintaining strong task performance. It can achieve $\geq$30\,Hz control frequency on a single GPU with smooth asynchronous inference in real-world deployment.

# FlashVLA 论文总结

## 1. 核心问题与研究动机

- **研究背景**：视觉-语言-动作（VLA）模型（如 π0.5）已成为机器人端到端操控的主流范式，但其在真实机器人上的实时部署面临两大瓶颈：
  - **高推理延迟**：以 π0.5 为例，动作解码消耗约 75% 的单步推理时间，主要来自流匹配（flow-matching）所需的约 10 次顺序去噪步骤。
  - **异步执行不稳定**：同步推理在每个 chunk 边界会让机器人停顿；异步推理虽可重叠预测与执行，但因基于"陈旧观测"预测下一个 chunk，预测状态与机器人实际到达状态之间的不匹配会随前瞻（lookahead）增大而加剧。
- **现有方法的局限**：
  - 高效推理方法（轻量化骨干、压缩、token 剪枝、动作头加速）只降低每次前向开销，不改变迭代解码循环结构；
  - 异步方法（未来状态条件、动作流匹配等）在解码后"打补丁"，需要额外监督或架构改动，且补丁成本随前瞻增长。
- **核心观察**：两种失败模式有共同根源——动作 chunk 以**隔离**方式解码（从纯噪声、仅依赖当前观测、互不关联）。将解码改为**联合**进行，可同时解决延迟与不匹配问题。

## 2. 方法论

### 2.1 核心思想
提出 **FlashVLA**：受长视频生成中的 streaming chunk-wise diffusion 启发，将动作 chunk 的解码从"独立去噪"改为"流式联合去噪"——维护一个含 N 个处于**阶梯式噪声水平**的 chunk 缓冲，在 chunk-wise 因果注意力下联合推进。

### 2.2 关键技术细节
- **流式动作缓冲**：缓冲 Bₜ = [x_{τ₁}^{(1)}, x_{τ₂}^{(2)}, …, x_{τₙ}^{(N)}]，噪声水平取自 Beta 分布并按阶梯排列 τ₁ < τ₂ < … < τ。最前端的 chunk 接近干净、即将执行；最后端的 chunk 是纯噪声、将在若干步后执行。
- **Chunk-wise 因果注意力掩码**：噪声更大的未来 chunk 可关注噪声更小的近执行 chunk，但反向不行。这让"为未来状态解码的 chunk"隐式获得"当前正在执行轨迹"的调节，无需额外的未来状态预测器。
- **三大量化效益**：
  - **摊销去噪**：每步前向同时推进缓冲中所有 chunk，单 chunk 跨 N 步完成去噪，单步动作解码延迟下降最多达 20×（GPU 工作量约 9.3×，wall-clock 约 19.9×）。
  - **隐式异步条件**：未来 chunk 自然以正在执行的轨迹为条件。
  - **Chunk 级记忆**：高噪声 chunk 关注缓冲中所有更早 chunk，提供短而结构化的历史，对长时任务尤其有益。
- **架构改动**：仅需对动作专家做轻量修改，使用 **FiLM** 增强多层级时间步条件；SmolVLA 等无原生 FiLM 的模型额外引入 time-MLP 与 FiLM 层。
- **训练方式**：从预训练 VLA 微调，提出**多缓冲联合微调（Multi-Buffer Joint Fine-tuning）**——将同一观测对应的 N 种缓冲配置打包为单个训练样本（共享观测编码，仅动作部分变化），损失为标准 flow-matching loss 在所有 buffer 配置上的求和。

### 2.3 流式推理算法（Algorithm 1）
- **冷启动阶段**：以 N-1 个 padding chunk 加 1 个高斯噪声初始化缓冲，运行 N-1 次推理填充，期间执行"安全默认动作"（如初始状态/归零动作），使机械臂保持静止。
- **稳态流式阶段**：循环执行 —— ① 推进所有 chunk 去噪一步；② 弹出最干净 chunk 执行；③ 其余 chunk 前移；④ 尾部追加新的纯噪声 chunk。每步推理产出一个可执行 chunk。
- **系统级优化**：将每阶段编译为 CUDA Graph，打包线性层减少 kernel 启动开销，配合 PyTorch max-autotune，消除剩余 kernel 气泡。

### 3.3 基线对比

- **执行时长**：执行 horizon 在 LIBERO=5，RoboTwin 2.0=16，真实任务=16（异步延迟 d=2）。

## 5. 实验数量与充分性

- **数据集维度**：3 类（LIBERO 4 子集 + RoboTwin 2.0 50 任务 + 真实 3 任务）。
- **异步延迟扫描**：d=1、2、3、4 在 LIBERO 与 RoboTwin 2.0 上分别评估成功率与时步时间。
- **横向对比维度**：同步 vs 异步；不同 chunk 大小（C∈{10,15,20}，N=5 固定）；不同缓冲长度（N∈{4,5,6}，C=10 固定）；跨架构（SmolVLA、LingBot-VLA）。
- **消融实验**：
  - **因果掩码消融**（最关键）：保留缓冲但移除 chunk-wise 因果注意力，异步成功率平均下降约 10 个百分点。
  - **chunk 大小消融**：C=10 为最佳甜区，过大反而成功率下降。
  - **缓冲长度消融**：N∈{4,5,6} 下结果稳定。
- **对照公平性**：
  - 各方法使用相同的 CUDA Graph 与 kernel fusion 系统优化；
  - 训练预算与执行 horizon 在对比方法间匹配；
  - LIBERO 结果取 5 次运行平均；
  - 报告了 95 百分位/平均值与多视角（2/3 views）下的延迟测量。
- **总体评价**：实验较为充分，覆盖了同步/异步、延迟/反应速度、不同 horizon、不同架构与多种消融；但 RoboTwin 2.0 的 speedup 较小（仅 1.08–1.10×），文中也明确指出这是由于该基准**模拟器主导**（渲染与通信占比高，policy 推理仅占约 17%）。

## 6. 主要结论与发现

- **延迟下降**：相对 π0.5，FlashVLA 单步动作解码延迟最多下降 20×；LIBERO 端到端每动作加速 2.43×，RTX 5090 三视图下达到约 50 Hz 策略更新率。
- **异步连续性恢复**：在 d=1 异步延迟下，FlashVLA 在 LIBERO 上将 π0.5 平均成功率从 96.9% 提升至 97.8%，同时将时步从 53.8 ms 降至 22.1 ms。
- **鲁棒性**：在 d=1–4 范围内，LIBERO 成功率维持在 97.5–98.3%（始终高于 96.9% 的同步基线），RoboTwin 2.0 异步下仍高于同步 π0.5 与 VLASH。
- **长时任务的显著增益**：RoboTwin 2.0 50 任务按 horizon 分组时，FlashVLA 在长时任务上比 π0.5 提升 **36.6 个百分点**（54.2% → 90.8%），中时任务提升 4.3 个百分点；LIBERO-Long 提升 3.8 个百分点。这被解释为 chunk 级记忆的实证表现。
- **反应速度**：TTFA 从 π0.5 的 80.0 ms / FASTER 的 62.1 ms 降至 37.1 ms；TTR 从 130.0/112.1 ms 降至 70.4 ms（1.7×/1.6× 改善）。
- **跨架构泛化**：SmolVLA 推理延迟 19.7→10.1 ms（1.95×），同步成功率保持 80.1%；LingBot-VLA 延迟 70.6→25.1 ms（2.81×），成功率提升 3.4–4.1 个百分点。
- **真实部署**：30 Hz 控制频率下，跨任务平均得分由 π0.5 同步的 80.0%（RTC 同为 80.0%，naive async 为 75.6%）提升至 84.4%，完成时间平均加速 1.3×。
- **因果掩码是关键**：移除 chunk-wise 因果注意力而仅保留缓冲，异步成功率下降约 10 点，证明因果掩码是 FlashVLA 异步收益的真正"活性成分"。

## 7. 优点

- **统一框架解决两个问题**：将推理延迟与异步不匹配归因于"chunk 隔离解码"，通过一次结构性修改同时解决，理论动机清晰。
- **跨架构即插即用**：仅对动作专家做轻量改动（FiLM、时间步条件），可在 π0.5、SmolVLA、LingBot-VLA 上复用。
- **仿真与真实一致性强**：从仿真结果到 7-DoF Franka 真实部署均验证了 30 Hz 可行性与长时任务增益。
- **消融设计有针对性**：因果掩码消融直接论证设计核心，chunk/缓冲长度扫描给出可操作的设计准则（如总缓冲跨距 ≈ 预训练 chunk 长度）。
- **系统级优化披露充分**：明确指出 CUDA Graph、kernel fusion、max-autotune 等工程手段与算法贡献是**正交**的，避免高估算法本身的加速。
- **对长时任务的强解释力**：chunk 级记忆假说与 horizon 分组实验相互印证。
- **训练效率优化**：多缓冲打包共享观测编码，避免将数据集放大 N 倍。

## 8. 不足与局限

- **未从零预训练**：FlashVLA 仅在下游微调阶段引入因果式流式解码，仍继承预训练模型的"独立 chunk"训练目标，理论上从零按该范式训练可获进一步增益（论文已声明为未来工作）。
- **冷启动开销**：每个 episode 需 N-1 次 warm-up 推理，多秒级 roll-out 上可摊销，但**在极短任务上较为明显**；冷启动期间需执行"安全默认动作"以保持机械臂静止。
- **预训练动作专家的数值不稳定**：在 RoboTwin 2.0 50 任务多任务训练中需重置动作专家的归一化层并从头训练，说明该改动对部分骨干稳定性有影响。
- **RoboTwin 2.0 端到端加速有限**：因模拟器主导（policy 推理仅占基线时步约 17%），Time/Step 仅提升 1.08–1.10×，与 inference latency 的显著下降不完全对应。
- **真实实验样本量较小**：每任务 15 次试验，覆盖 3 个任务；任务种类有限（水果抓放、白板擦除、桌面清理），尚未覆盖更复杂接触、富干扰或人机交互场景。
- **对照公平性的细节差异**：VLASH 在 d=1 下速度提升较小（1.15×）但成功率提升（+0.3），StreamingVLA 速度提升 1.70× 但成功率下降（-2.0），作者选择综合指标对比但读者难以直接复现各基线的全部工程细节。
- **依赖额外系统优化**：要兑现全部 latency 收益需配合 CUDA Graph 等系统级手段，对部署环境提出更高要求。
- **代码与可复现性**：文末仅给出 GitHub 链接（https://github.com/z-lab/flashvla.git），目前尚未确认公开仓库与权重是否已完整发布。
